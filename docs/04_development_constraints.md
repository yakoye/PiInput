# 开发约束

## 1. 功能约束

- 不开发 AI 改写、AI 联想或大模型功能；
- 不开发语音输入；
- 不加入广告、资讯和无关入口；
- 基础输入功能不得依赖账号和网络；
- 双拼架构不能绑定小鹤，小鹤只是第一优先方案；
- 标点和符号系统进入 Windows 首版范围；
- 同步后开发，但数据模型前置预留。

## 2. 架构约束

- 核心使用 C++20；
- 核心不得包含 Windows、Android 或 Apple 平台头文件；
- 跨模块和跨语言接口不得暴露 STL ABI；
- 对外最终提供 C ABI；
- Windows TSF DLL 必须保持薄；
- 网络和同步不能链接进 TSF DLL；
- 静态大词库不得在按键时解析文本；
- SCEL 只能作为导入格式，不能作为运行时格式。

## 3. 性能约束

按键处理线程禁止：

- 网络 I/O；
- 磁盘数据库查询；
- 同步磁盘写入；
- 运行时解压词库；
- 运行时解析 SCEL/JSON/YAML；
- 等待其他进程的无超时 IPC；
- 大范围锁；
- 未受控日志输出。

所有热路径功能都必须有基准测试。

## 4. 候选稳定约束

- 输入未变化时候选顺序不得变化；
- 异步结果不能替换当前快照；
- 选词不能只传候选下标；
- 每次候选更新必须增加 generation；
- 词库热更新只能影响后续 generation；
- 任何候选跳变问题都属于阻断发布的问题。

## 5. 数据约束

- 不记录用户完整按键流；
- 不默认保存完整输入历史；
- 用户学习数据必须可查看、导出、删除和关闭；
- 密码框、支付、隐私模式等敏感场景不得学习；
- 同步必须可完全关闭；
- 剪贴板同步默认只处理文本；
- 服务器不得获得明文同步内容；
- 删除操作必须通过 tombstone 或变更日志同步，避免跨设备复活。

## 6. 词库约束

- 词库数量不能作为准确率替代品；
- 通用高频词优先级不能被专业冷门词随意覆盖；
- 每个词库有独立来源、版本、类别和权重；
- 导入第三方词库时需要去重、质量检查和权重上限；
- 公开发布不得随意打包没有明确再分发授权的完整第三方词库；
- 用户自行导入和本地转换与公开重新分发分开处理。

## 7. 开发流程约束

参考用户提供的 Superpowers Skills：

1. 先明确需求和设计；
2. 设计写入文档；
3. 任务拆分到可验证的小步骤；
4. 核心解析、排序、状态机和 bug 修复优先采用测试驱动；
5. 调试先找根因，不用延时和重复重试掩盖；
6. 声称完成前必须运行完整验证；
7. 每版发布前逐项检查需求，不以“测试通过”代替需求检查；
8. 每个发布包必须自包含，能够在新会话继续。

## 8. 代码质量约束

- 开启高等级编译警告；
- 警告不得长期积压；
- 解析外部文件必须进行边界检查；
- 错误信息包含上下文或文件偏移；
- 不允许未定义行为；
- 核心模块使用 RAII；
- 所有资源有明确生命周期；
- 公共接口有文档；
- 复杂算法必须有解释和测试；
- 格式版本必须显式记录；
- 数据升级必须保持向后兼容或提供迁移工具。

## 9. 发布约束

每版必须包含：

- 带版本号的压缩包；
- 源代码；
- Markdown 文档；
- 版本说明；
- 带下一目标版本号的开发计划；
- 构建命令；
- 测试结果；
- 可执行文件；若当前阶段无法提供，必须明确原因和用户本机构建方式；
- 准确的 Git 提交命令，不能使用模糊的 `update`。

## Windows SDK 宏约束

- 包含 `windows.h` 前必须定义 `NOMINMAX` 和 `WIN32_LEAN_AND_MEAN`；
- 标准库 `std::min` / `std::max` 不得被 Windows 宏污染；
- 对外部头文件无法保证宏环境时，可使用 `(std::min)(...)` 和 `(std::max)(...)`；
- 发现 MSVC 错误时必须先检查预处理宏和平台头文件污染，不得仅为通过编译替换算法逻辑。

## 构建流水线约束

- 配置、编译、测试、安装任一步返回非零，脚本必须立即终止；
- 测试通过不等于所有可执行目标都已编译成功；
- 安装前清理旧输出，防止陈旧二进制被误认为当前版本产物；
- 发布脚本必须验证所有预期 EXE、DLL 或安装包真实存在；
- `.cmd` 包装脚本必须向调用者传递 PowerShell 的退出码。

## TSF COM 和链接约束

- `ITfInputProcessorProfileMgr` 必须通过 `CLSID_TF_InputProcessorProfiles` 对象查询获得；
- 不得使用不存在的 `CLSID_TF_InputProcessorProfileMgr`；
- TSF COM 接口通过 `msctf.h` 声明和 `Msctf.dll` 运行时提供，项目不得凭名称猜测并链接 `msctf.lib`；
- 标准 TSF GUID 由 Windows SDK/`uuid.lib` 提供；
- 新增 Windows 链接依赖前必须在真实 Windows SDK 中确认库文件存在；
- Windows 首次编译反馈必须转化为自动回归检查。
