# Superpowers Skills 开发流程参考

用户提供了 `superpowers-skills(4).zip` 作为开发方法参考。本项目吸收其原则，但根据 C++、Visual Studio、CMake 和 Windows TSF 环境调整工具名称。

## 采用的主要流程

### 需求与设计

- 实现前先理解目标、边界和成功标准；
- 对有多种实现路径的功能给出方案和权衡；
- 设计决策写入 Markdown，而不是只留在聊天中；
- 大功能拆成独立阶段，避免一次性开发所有平台。

### 编写计划

- 任务拆到可验证的小步骤；
- 每一步写明文件、接口、测试和完成条件；
- 下一版本计划文件名必须带目标版本号；
- 计划区分“必须做、可选、以后做”。

### 测试驱动

优先用于：

- 外部文件解析；
- 拼音切分；
- 双拼映射；
- 候选排序；
- 状态机；
- 候选快照；
- 同步冲突；
- bug 修复。

### 系统化调试

- 先稳定复现；
- 收集边界、状态和日志；
- 沿数据流追踪根因；
- 不用睡眠、重复重试和扩大超时掩盖竞态；
- 修复根因后增加回归测试；
- 必要时做防御性校验，但不能用校验代替根因修复。

### 完成前验证

- 构建成功不能替代测试；
- 单元测试通过不能替代需求清单；
- 测试结果必须是本次修改后的新结果；
- 发布前运行完整构建、测试和样本验证；
- 未实际验证的内容必须明确标注。

### 分支和代码审查

推荐：

- 独立功能分支或 Git Worktree；
- 实现后做规范检查；
- 再做代码质量审查；
- 核心接口变化需要更新文档；
- 合并前重新运行测试；
- 不自动丢弃用户已有修改。

## 本项目的具体落地

```text
需求讨论
  ↓
设计文档
  ↓
版本化实施计划
  ↓
测试/基准先行
  ↓
最小实现
  ↓
系统化调试
  ↓
代码与需求双审查
  ↓
完整验证
  ↓
版本化压缩包和 Git 命令
```

这些 Skills 是流程参考，不作为 LiteIME 安装包运行依赖，也不复制到最终用户程序目录。
