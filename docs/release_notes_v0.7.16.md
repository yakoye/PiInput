# PiInput v0.7.16 版本说明

v0.7.16 修复了一个会让输入法在重启后彻底失效的安装缺陷，补上了 Windows 搜索里看不到候选的问题，并给安装和升级流程做了一次实打实的返工。

## 重启后输入法失效（重要）

- 修复升级后重启，输入法注册项全在、程序文件却全部消失的问题。

  升级流程是「先卸载再安装同一批路径」。卸载时 `PiInputTSF.dll` 正被每个运行中的程序映射、`PiInputHost.exe` 正在跑，删不掉，卸载器就把整棵安装树的路径登记进 `PendingFileRenameOperations`。安装器随即把新文件写回**同样的路径**，装完当场可用；下一次重启时，Windows 忠实执行那份待删清单，把刚装好的文件全删了。注册表因为是立即写入、不进队列，所以完好无损 —— 于是留下「输入法还在列表里、能切换，但一个字也打不出来」这种极具迷惑性的半死状态。

  现在删不掉的文件一律先改名到本次卸载独有的一次性路径，再登记那个路径，稳定路径永远不进待删队列。一次性名字取自 `FILETIME` 而不是 `GetTickCount64` —— 后者在重启后从零重新计数，跨重启会撞名。

- 如果你的安装已经处于这个状态：注册表还在，只是文件没了，重新安装即可恢复，用户词库、设置和学习记录都不受影响。

## Windows 搜索里的候选

- 修复在任务栏搜索框输入时看不到候选框的问题。拼音照常上屏、空格照常提交，唯独候选看不见。

  原因不是候选窗没画出来，而是**画出来了但被盖住**：Windows 11 的搜索面板绘制在一个普通窗口无法逾越的层级带上，候选窗即便带 `WS_EX_TOPMOST` 也压不过它。候选窗现在会避开搜索面板整体摆放，位置随面板实时变化。

  这个避让严格只对 `SearchHost.exe` 生效，其余所有程序的候选窗位置逐像素不变。

- 宿主声明由自己绘制候选却始终不绘制时，输入法会恢复显示自己的候选窗，不再出现两边都不画、用户什么都看不到的情况。

## 安装与升级

- 安装器有界面了。此前双击之后不显示任何窗口，40 MB 词库复制期间毫无反馈，UAC 也不解释自己为何出现。

  现在分三步：动手前先确认，说明装到哪两个位置、本次是全新安装还是覆盖升级、为什么需要一次管理员权限；安装过程走进度条并显示当前步骤；完成页把「打开设置程序和配置目录」改成可勾选项，不再强行弹出两个窗口。

  `--silent` 依然完全静默，行为与旧版逐字节一致。

- 一键更新改为原地覆盖升级，不再先卸载。UAC 提示从两次减少到最多一次；Shim 字节没有变化的升级一次都不需要。需要彻底重装时使用 `-CleanReinstall`。

  这同时消除了「卸载器删掉机器级 Shim、安装器再装回同一路径」这一步 —— 那正是上面那个重启丢文件缺陷的成因。

- 一键更新的 CMD 入口改用 UTF-8，中文提示不再乱码，并可透传参数。

## 诊断

- 新增候选界面协议的可选诊断日志，在临时目录放置 `piinput-candidate-trace.on` 后启用，记录到 `piinput-candidate.log`。它记录宿主是否真的取走了候选列表，用于判断「看不到候选」究竟是没画还是被遮挡。与既有的语言栏、光标、按键诊断同一机制，默认关闭。
