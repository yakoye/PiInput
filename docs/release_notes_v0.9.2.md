# PiInput v0.9.2 版本说明

一个真缺陷，一个新功能。

## 飞书这类程序里，句号规则失效

**症状**：在飞书（以及其他一些程序）里，字母或数字后面按句号得到的仍然是 `。`，不是 `.`。换句话说 `geek.` 根本打不出来，只能切到英文模式。

**成因**：两键规则要看光标前面是什么字符才能成立。这个信息靠 TSF 向程序索取，而飞书这类程序的 `RequestEditSession` 读不出周边文本——于是「光标左边」永远是空的，规则永远不命中，每一个句号都走中文形式。

**修法**：文档不肯说的时候，用「输入法自己刚上屏了什么」顶上——那是唯一能确定的事。

兜底的寿命刻意很短：只活到下一个**非标点**按键。字母会开新的合成串、方向键会移动光标，过了那个点就不能再断定光标还跟在那段文本后面。而「按两次得到中文形式」自然成立，不需要额外状态：第一次按完之后，记住的尾字符变成了 ASCII 句点，它不是字母数字，规则自己就不再命中。

读得到周边文本时仍以文档为准，这一支只在真的读不到时启用。

**冒号补了测试**。此前冒号只有「时间」「比例」这些专用规则有用例，两键规则本身一条都没有——而那才是日常最常撞到的一条。现在与句号完全对称地钉住，连同「左侧为空」那条边界，免得以后有人在引擎里加一条「默认 ASCII」的捷径。

## 暗色主题与跟随系统

候选窗新增三挡配色：**跟随系统**（默认）、浅色、暗色。

设置里在「候选窗 → 配色」，也可以打 `zt`、`zhuti` 或 `vuti`，候选框第 2 到 4 位直接切换——三种拼法都认：全拼、简拼，以及小鹤双拼下「主题」的打法。换了方案的人够不着的入口等于不存在。

跟随系统读的是 Windows 的 `AppsUseLightTheme`，并在每个合成边界重新解析，所以改了系统设置之后下一次打字就跟上。不用 `GetSysColor`：经典系统颜色从来没跟着个性化设置走过，暗色模式下它依旧返回浅色。

**暗色不是把浅色取反。** 候选窗是浮在别人窗口上的一条小面板，纯黑会在深色应用上糊成一片、在浅色应用上又过于刺眼，所以底色取深灰并保留一圈更亮的描边，让它在两种背景上都有边界。

实现上把散在绘制代码里的十三个颜色收成了一张调色板，并加了门禁：绘制函数里再出现 RGB 字面量就构建失败——那种缺陷只在暗色下看得见，最容易漏过去。菜单也不再用系统画刷，它此前会在深色面板上糊出一块白。

## 顺带修掉的两个问题

**三挡配色的顺序是反的。** 按位置插入原先是从后往前走的，为的是让「两条都要第 2 位」时保持表里的先后；但行比配置的位置短时会把顺序弄反——三条分别要 2、3、4 位时，浅色和暗色对调了。三条同时出现是第一次撞到这个形态。改成从前往后插并记住上一条落在哪，两种情形同时成立。

**词库给不出候选时的占位候选会把标签打进文档。** 它用的是快捷项的名字，于是打 `zt` 时候选 1 是「配色：跟随系统」这串纯文本——选中它就打进文档了，而且和候选 2 的动作项几乎分不出来。现在占位用的是用户打的那几个字母。
