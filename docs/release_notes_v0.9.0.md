# PiInput v0.9.0 版本说明

两件新东西：常用语，和一个会把话说清楚的安装器。

## 常用语

把常用的长文本存起来，打几个字母就能从候选框取出来。设置里新开了一页「常用语」。

| 内容 | 触发码 | 怎么用 |
| --- | --- | --- |
| 北京市海淀区xx街道xx小区 | `dzjl` | 打 `dzjl`，候选框第 2 位 |
| 622322199005012219 | `sfz` | 打 `sfz` 取用 |
| 15801616544 | 留空 | 打前 3 位 `158`，按 `Tab` 补齐 |

**触发码可以不填。** 留空时按内容的第一个字符推导：中文用首字拼音声母（`北京市海淀区…` 认 `bj`、`bjs`、`bjsh`），拉丁字母用它自己的前几个字母（`github.com/…` 认 `gi`、`git`、`gith`），数字走下面那条单独的路。

**和快捷调用是两张表，不是一张。** 快捷调用启动程序，常用语上屏文本。共用一个字段的代价是：存进去的地址会被当成路径去启动，而一条命令行会被原样打进文档——两种错都不便宜，分开存就谁也变不成谁。

**不进学习记录。** `dzjl → 北京市海淀区…` 不是一条「拼音—词」事实，学进去会污染反查，下次打 `dzjl` 还会多出一个来源不明的重复候选。

### 数字那条路：不吃第一个数字

按字面做需要从第一个数字起就接管按键，把数字做成合成串。代价是两条硬性要求同时破掉——「输入数字 `123` 不得丢失首个数字」，以及「远程桌面地址框等数字输入框直接透传」。为一个便利功能去动所有人的数字输入，不划算。

实际做法是：**数字照常落下，只补齐没打完的部分。**

打 `158` 之后候选框给出建议，按 `Tab` 插入 `01616544`。不删除已上屏的数字，也不重写周边文本——所以在 TSF 支持差的终端里一样成立，最坏情况只是建议不出现，而不是把文档改坏。数字键本身一个字节都没改，没存数字常用语的用户行为与上一版逐字节相同。

用 `Tab` 而不是空格或回车：数字打到一半时，空格和回车的意思是「这个数字输完了」，拿它们去接受建议，会让只想打 `158` 的人得到整个号码。

门槛定在 3 位，1 位或 2 位会频繁误弹——日期、价格、编号里到处是短数字。

## 安装器

三个系统对话框换成了五页向导：欢迎、安全提示、安装位置、进度、完成。

换掉它们不是为了好看，是因为那三个对话框说不完必须说的话。装完之后用户不知道怎么用——`Win+Space` 切换、`Shift` 切中英、候选数字选词、`fh`/`bq`/`sz` 这些入口，全写在随包的 markdown 里，而没有人会去读它。

**没有签名这件事现在讲在动手之前。** SmartScreen 怎么放行、智能应用控制为什么没有放行入口且关闭不可逆、Defender 有时会把引擎进程当木马隔离导致「图标还在但一个字打不出来」——这些都写在第二页，而不是等用户撞上再去搜。

**操作指引做成了随包 HTML**（`piinput-guide.html`），完成页和托盘的「帮助与反馈」都能打开。此前那个入口打开的是一份 markdown，而 markdown 在 Windows 上通常没有默认程序，点开要么弹「用什么打开」要么是记事本里一堆井号。

**完成页的三个勾选项都不强加**：打开设置、查看操作指引、立即激活输入法。最后一项值得默认勾上——profile 刚注册完有时并不在前台生效，而用户看到的只是任务栏里找不到输入法。

**没有引入 NSIS 或 Inno Setup。** 它们会多带一个未签名的可执行壳，而这正是现在最怕的东西：Defender 已经会隔离引擎进程，智能应用控制强制模式下安装器本来就进不去，再套一层第三方 stub 只会让启发式判定更难过。

`--silent` 的行为一个字节都没改。脚本、一键更新和提权子步骤全都依赖它完全没有窗口。

## 协议 v7

数字常用语需要把「刚打出的那串数字」从 Shim 交给 Host，为此加了 v7 和一个文本字段。

**默认版本仍然是 v5。** Shim 不做版本协商，它发什么版本就是什么版本；升级之后旧 Host 可能还在跑，而它的白名单里没有 v7，收到会整包丢弃、连回复都没有——那就是那个应用彻底打不出字，正是 v6 那次的故障形态。所以 v7 只用在 `digit_run` 这一种报文上：它是纯增量的提示，Shim 不等它的回复，旧 Host 拒收的后果仅仅是「数字建议不出现」。

同样的理由，v6 和 v7 都永久留在接受白名单里。**发布过的版本号不可撤回。**
