# PiInput v0.6.0-dev 验证记录

## 本版阻断问题

用户实录视频显示，连续输入期间存在多次 5～6 秒无界面更新，随后积压文字成批出现。

逐帧测量结果：

- 0.0～5.2 秒：停顿约 5.2 秒；
- 5.4～10.5 秒：停顿约 5.1 秒；
- 12.9～18.0 秒：停顿约 5.1 秒；
- 20.9～26.9 秒：停顿约 6.0 秒。

## 根因

稳定 TSF 入口通过单线程 FIFO 向常驻 Host 发送请求。Host 不可用时，队首请求会等待固定 5000 毫秒；后续按键虽然已经被 TSF 接收，却全部排在该请求后面，形成周期性的五秒冻结和批量补字。

## 修复

- 删除每个请求都可触发的 5000 毫秒等待；
- 首次连接失败只允许一次 750 毫秒冷启动窗口；
- 当前机器真实 Host 完全停止后冷启动到健康响应实测约 357 毫秒；
- 一个启动窗口失败后进入 1750 毫秒熔断冷却；
- 冷却期间每个请求仍会立即探测现有管道，但不会重复启动并等待；
- Host 恢复成功后自动重置熔断状态。

## 自动门禁

- 首次断线只允许一次 750 毫秒启动预算；
- 同一故障窗口内后续按键必须零等待失败；
- 冷却结束允许一次新的有界重连；
- 连接成功后必须能处理下一次独立故障；
- TSF 传输源码禁止重新出现 `5000ULL` 固定等待。

## 最终验证结果

- Windows x64 Release 全目标编译：通过；
- 完整 CTest：57/57 通过，0 失败；
- Host 进程启动、重启交接、管道通信与断线策略：通过；
- 真实外部词库增量性能、长全拼性能、SCEL 和 3500/7000 汉字覆盖：通过；
- 发布元数据与 488 个源码文件 SHA-256 校验：通过；
- 发布包：`PiInput-v0.6.0-dev-windows-x64.zip`。

## 用户验证重点

在 Notepad++ 中连续输入：

```text
我，他们。我们明天，去哪里？明天、后天！
```

观察中文、逗号、句号、问号和顿号前后是否连续响应，不应再出现约五秒停顿后批量补字。
