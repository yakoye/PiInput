## 无法靠改代码解决的

### 代码签名

无可信 Authenticode 签名与 RFC 3161 时间戳。开启智能应用控制强制模式的机器会在内核代码完整性层直接拒绝安装器，且不提供绕过入口。

微软的 Artifact Signing 服务排除中国大陆，只能走传统 CA。发布脚本里的签名开关已经备好。

签名必须用 **RSA**——Smart App Control 目前不支持 ECC 证书。

## 待查证的怀疑

### explorer.exe 的 GDI 泄漏是不是我们的

2026-08-28 观察到 explorer 的 GDI 对象数达到 9845（上限 10000），触发基于堆栈的缓冲区溢出对话框。

现有证据都指向**不是** PiInput：泄漏方向与使用量相反（PiInput 用得最多的 MobaXterm 422、notepad++ 318，几乎不用的 explorer 9845）；shim 里没有随按键增长的 GDI 创建路径；泄漏的是 GDI 对象而图标属于 USER 对象（explorer 的 USER 仅 1685）。

但**证否本身做不到**。要彻底排除，需要在 explorer 重启后挂探针记录它的 GDI 增长曲线，看它在完全不使用 PiInput 时涨不涨。

## 已知但不打算修的

### MobaXterm 里候选框不跟随光标

原理上做不到。该程序不维护系统光标，`GetTextExt` 与 `GetScreenExt` 都返回固定的退化矩形（实测 53 次不变），没有任何接口能问出插入点在第几行第几列——那个信息只存在于它自己的绘图代码里。

已评估并否决的方案：

- **屏幕捕获找闪烁光标**：时序对不上（闪烁周期 500ms–1s，而候选框必须在第一个字母按下时就位）；打字时画面本来就在变，合成串的变化特征与光标几乎相同；隐私代价不成立——把 SSH 会话的屏幕内容读进输入法进程，与输入法应有的可信度冲突。
- **键盘位置推算**：我们只看得见自己吃掉的键，看不见 shell 命令、Tab 补全、方向键和远端输出，位置会自信地漂移且无法自知。它还依赖 cell 尺寸和 viewport 原点，而那两个量本身要靠视觉方案提供。
- **DLL 注入 / hook 绘图函数**：为候选框位置付出的代价远超收益。

当前做法是稳定、不乱跳、落在输入区附近，并已写入随包文档，避免试用者误认为是缺陷。
