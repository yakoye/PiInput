# PiInput v0.9.3 版本说明

**修 v0.9.2 的一个发布缺陷。如果你装了 v0.9.2，请装这一版。**

## v0.9.2 的配色开关对老用户是无效的

v0.9.2 新增了 `zt` / `zhuti` / `vuti` 切换配色。它在全新环境里工作正常，**在任何打开过设置窗口的机器上却是零候选**——也就是几乎所有老用户。

成因：那三挡当时是作为默认「快捷调用」行发布的。而 `[shortcuts]` 段一旦被保存过就带着 `count=`，解析时会把这张表严格截成那个长度。老用户的文件里写着 `count=6`，于是 v0.9.2 新增的第 7、8、9 行被整个丢掉。

本机实测复现：装上 v0.9.2 之后打 `zt`，候选数为 0。

**修法是把配色改成引擎内置项**，与日期时间那组（`riqi` / `shijian`）一样不经用户可编辑的表——那一组从一开始就建在引擎里，正是因为它们不该受用户表长度的摆布。现在用一个 `count=6` 的真实旧配置验证过：`zt` 给出三挡，原有的 `fh` / `bq` / `sz` / `msp` 一个都没动。

## 这暴露的问题比这个功能大

「保存过的 `count=` 会截断内置表」意味着**此后任何新增的内置快捷行都到不了老用户手上**。这一版只是绕开了它（把配色挪出那张表），没有根治。

根治需要能区分「从没见过这一行」和「用户自己删掉了这一行」，否则补回默认行会把用户的删除撤销掉。方向是在 `[shortcuts]` 段记录它写入时对应的内置集合版本，只补该版本之后新增的行。已记入 `docs/待办事项.md`，没有半做。

## v0.9.2 的其余内容原样保留

- 飞书这类读不出周边文本的程序里，字母数字后的句号终于能得到 ASCII 形式
- 候选窗的暗色与跟随系统两挡配色
- 冒号的两键规则测试
- 三挡配色的排列顺序、占位候选不再把动作名打进文档

细节见 `docs/release_notes_v0.9.2.md`。
