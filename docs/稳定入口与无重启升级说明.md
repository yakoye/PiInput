# PiInput 稳定入口与无重启升级说明

适用版本：PiInput `v0.4.2-dev` 及以后。

## 目标

旧开发版把完整输入引擎、词库和候选窗口都装进 `PiInputTSF.dll`。Windows 会把这个 DLL 加载到记事本、浏览器、ChatGPT、VS Code 等每个正在使用输入法的程序中；只要任一程序没有退出，旧 DLL 就无法覆盖，而且不同程序可能长期停留在不同版本。

`v0.4.0-dev` 将运行时拆为两部分：

```text
应用程序
  └─ PiInputTSF.dll（永久稳定入口，只负责 TSF/组合文本/IPC）
       └─ 本地命名管道 PIINPUT_IPC_V1
            └─ PiInputHost.exe（词库、解码、排序、设置、候选窗口）
```

稳定入口使用固定身份：

```text
CLSID   {13EB305F-2DA3-4CF7-8C45-16B016B801B5}
Profile {4ED27B7C-678E-4240-827A-24DA597F8D4B}
协议     PIINPUT_IPC_V1
```

## 安装目录

```text
%LOCALAPPDATA%\PiInput
├─ Runtime
│  ├─ Shim
│  │  └─ PiInputTSF.dll             永久固定入口
│  ├─ versions
│  │  └─ <版本-构建号>
│  │     ├─ bin\PiInputHost.exe     可重启的输入引擎
│  │     └─ data\...                词库、符号和英文资源
│  └─ current.json                  原子发布的当前版本标记
├─ UserData                         用户设置、词库和学习数据
└─ Uninstall\PiInput-Uninstall.exe
```

注册表只保存当前 Host 的完整路径；稳定入口在断线后按该路径启动当前 Host。

## 升级行为

- 第一次从旧架构迁移到 `v0.4.0-dev` 时，安装器注册一次永久入口和永久 Profile，并清除旧开发身份。
- 安装器启动一个当前用户级常驻 Host；词库只加载一次，所有应用通过同一管道复用。
- 以后普通升级不修改入口 DLL，只安装新的版本化 Host 和数据。
- 若入口自身必须修正且旧 DLL 正被程序占用，安装器优先把已加载文件改名留存，再把新版放回同一个永久路径。旧程序继续使用内存中的旧入口，新打开程序加载固定路径的新入口；COM 注册路径永远不进入版本目录。
- 若 Windows 明确禁止安全改名，安装器必须失败并提示关闭占用程序或重启，不能在旧字节仍生效时报告升级成功。
- 安装器先让旧 Host 排空请求，再切换当前 Host 路径并启动、健康检查新版 Host。
- 稳定入口在每个按键请求中携带已经确认的组合串、光标和中英文状态；Host 重启后会重新计算候选并继续输入。
- 已打开的 ChatGPT、Chrome、VS Code 等程序不需要退出，也不会继续加载不同版本的完整引擎。
- 若新版 Host 启动或健康检查失败，安装器恢复原 Host 路径并重新启动旧 Host，不发布损坏版本。

## 如何确认实际运行版本

运行解压包或安装版本中的：

```text
bin\piinput-diagnostics.exe --status --json
```

重点字段：

- `profile_registered/profile_enabled/profile_active`：Windows Profile 状态；
- `shim_path/shim_sha256`：唯一永久入口 DLL；
- `host_path`：当前版本化 Host；
- `host_connected/host_health`：实时 Host 管道与 build ID；
- `protocol_version`：当前 IPC 主版本。

诊断工具不会把“某进程曾映射过旧 DLL”误报为当前激活版本。

## 边界

只有稳定入口自身发生安全修复或 TSF 接口变更时，才需要更新 `PiInputTSF.dll`。词库、排序、全拼、小鹤、英文候选、符号、设置和候选界面的普通升级全部位于 Host，不要求关闭使用中的应用。已经加载旧入口的长期运行程序不会被强制终止；它们退出后再次打开时自然加载固定路径的新字节。
