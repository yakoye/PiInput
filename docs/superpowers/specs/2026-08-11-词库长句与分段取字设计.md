# PiInput 词库长句与分段取字设计

日期：2026-08-11  
状态：用户已确认  
范围：全拼、小鹤双拼、候选策略、词库构建与词库诊断

## 1. 目标

PiInput 必须同时正确处理两类长输入：

1. 词库中已有的长词、成语、古诗词和固定句，完整拼音命中时直接作为高优先级候选；
2. 词库中没有、语义不确定或仅能逐字覆盖的长输入，通过分段取字完成，不再把大量低可信单字路径伪装成完整句子。

代表性验收用例：

```text
小鹤：hlheruhdlq       → huang'he'ru'hai'liu → 黄河入海流（首选）
全拼：huangheruhailiu → huang'he'ru'hai'liu → 黄河入海流（首选）

无完整词库命中：
正常候选仅保留少量可解释结果；按 = 后进入分段取字，逐段暂存，最后统一上屏。
```

## 2. 已确认的事实

- `黄河入海流` 位于本地 `THUOCL_poem.txt`，但当前词库构建脚本只下载 THUOCL，没有合并它。
- 当前生成的 `piinput-combined.tsv` 不含 `黄河入海流`。
- 当前解码器会把每个音节的单字候选做笛卡尔式 Beam 组合，所以产生“黄河如还刘”等形式上覆盖全部拼音、语言上不可信的结果。
- `hlheruhdlq` 的小鹤解析本身正确，问题位于词库构建和候选分层，不是小鹤键位映射。

## 3. 产品原则

- 离线、轻量、快速、稳定、可解释。
- 不增加 AI、云联想或网络热路径。
- 相同输入、相同词库和相同用户数据必须得到稳定顺序。
- 不能用“是否由单字组成”推断文本是否有意义；古诗和自然句也可能需要多段组合。
- 候选可信度由可验证的来源和路径结构决定，不根据文字内容做主观判断。
- 默认候选窗保持一行；只有用户按 `=` 或下方向键才展开/进入分段选择。

## 4. 候选证据模型

为每个中文候选保留明确类型和路径证据：

```cpp
enum class CandidateKind : std::uint8_t {
    exact_lexicon,          // 一个词库词条完整覆盖全部输入
    decoded_sentence,       // 多个词库边组成并完整覆盖输入
    prefix_lexicon,         // 只覆盖当前未决输入的前缀
    single_character,       // 当前音节的单字候选
    incomplete_completion, // 未完成音节的合法补全
};

struct CandidateEvidence {
    CandidateKind kind{};
    std::size_t consumed_syllables{};
    std::size_t word_count{};
    std::size_t single_character_tokens{};
    bool covers_all_input{};
};
```

候选窗口不再根据候选文字或最终分数猜测其性质。

## 5. 正常候选策略

正常模式的排序分层如下：

1. 用户固定或用户学习的完整精确词条；
2. 完整输入的精确词库词条；
3. 可靠的多词解码路径；
4. 当前输入前缀的词语候选；
5. 单音节输入时的单字候选；
6. 未完成音节补全。

精确完整词条必须先于由多条边拼出的同音结果。`黄河入海流` 一旦进入词库，就不能再被“黄河如还刘”压过。

多音节输入的全单字组合最多保留一行作为即时猜测，不允许占满后续多行。按 `=` 请求更多候选时，如果下一行只剩这类结果，改为进入分段取字。

## 6. 分段取字状态机

候选视图有两种模式：

```cpp
enum class CandidateViewMode : std::uint8_t {
    normal,
    segment_selection,
};
```

### 6.1 进入条件

- 正常模式按 `=` 或下方向键时仍有可靠候选行：移动到下一行；
- 下一行只包含低可信全单字组合，或不存在更多正常候选：进入 `segment_selection`；
- 初始候选为空但输入可解析出合法音节：按 `=` 直接进入 `segment_selection`。

### 6.2 分段候选

以第一个未解决音节为起点，依次生成：

1. 能覆盖更多音节的精确词库词语；
2. 当前完整音节的常用单字；
3. 当前未完成音节的合法补全候选。

分段模式不返回自动补齐整个剩余输入的伪句子。

### 6.3 暂存与统一上屏

选择一个分段候选后：

- 将候选文字加入 `staged_text`；
- 记录该候选消耗的标准拼音音节数；
- 保留原始输入和已选择段历史；
- 从下一个未解决音节重新生成分段候选；
- 不向应用上屏。

当剩余音节全部解决或用户按空格确认时，才把 `staged_text + remaining_best_text` 一次性写入应用。

### 6.4 按键

```text
=           下一行；正常候选耗尽后进入分段取字
-           上一行；分段模式首行继续向上则返回正常候选
1～9        选择当前行候选；分段模式中只暂存
Backspace   分段模式优先撤销最近一次暂存选择
Esc         先退出分段模式；再次按下才取消整个组合
Space       确认当前最佳剩余路径并统一上屏
左右/Home/End 保持组合区光标语义，不造成候选快照跳变
```

## 7. 词库构建策略

### 7.1 THUOCL 分类导入

THUOCL 不再“全部排除”或“全部无差别混入”。按分类导入并使用独立基础权重：

- `THUOCL_poem.txt`：古诗词和固定句；
- `THUOCL_chengyu.txt`：成语；
- 其他领域文件保持可配置，默认低于通用基础词库。

THUOCL 的 DF 只用于同来源内部排序，先做对数归一化，不能直接与 Rime 权重或 SCEL 权重相加。

### 7.2 拼音解析

THUOCL 只有词和 DF，没有拼音。构建器按两级解析：

1. 优先使用 `phrase-pinyin-data` 中完全相同词条的读音；
2. 没有整词读音时，使用基础汉字读音逐字生成一个低置信读音；多音字无法唯一确定的条目写入构建报告，不静默生成大量组合。

生成报告必须分别统计：精确短语读音、逐字推导读音、无法解析条目。

### 7.3 权重

```text
用户固定/用户学习 > 通用基础词库 > 精确完整的诗句/成语匹配
                    > 普通领域词 > 单字兜底
```

“精确完整匹配奖励”只在输入拼音完整等于词条拼音时生效，避免低频长词在普通句子局部匹配中污染首选。

## 8. 词库查询功能

扩展 `piinput-cli`，提供两个只读诊断入口：

```text
piinput-cli --lexicon <file> --lookup-word 黄河入海流
piinput-cli --lexicon <file> --lookup-pinyin "huang'he'ru'hai'liu" --top 20
```

输出至少包括：

```text
word
pinyin
weight
exact=yes/no
```

`--lookup-word` 使用词条反向索引，不允许每次查询扫描完整词库。TSV 和 `.lex` 必须得到一致结果。

开发目录增加可双击入口 `query-dictionary.cmd`，交互式询问汉字词语或标准拼音，默认查询当前安装的 `%LOCALAPPDATA%\PiInput\UserData\lexicons\piinput-imported.lex`。

## 9. 测试要求

### 9.1 精确长词

```text
hlheruhdlq / huangheruhailiu → 黄河入海流，首选
quzicelt / quzicelue          → 取字策略，首选或第一页
```

### 9.2 分段取字

- 无精确长词时按 `=` 进入分段模式；
- 选词或单字后只更新组合区，不调用应用提交；
- 连续选择多段后统一上屏；
- Backspace 逐段撤销；
- `-` 能返回正常候选；
- 旧 generation 的候选 ID 不能选择；
- 分段候选不包含自动拼接的完整伪句子。

### 9.3 词库构建与查询

- THUOCL poem fixture 能生成 `黄河入海流\thuang'he'ru'hai'liu`；
- DF 归一化稳定且无整数溢出；
- 无法解析的多音条目进入报告；
- `--lookup-word` 与 `--lookup-pinyin` 在 TSV、`.lex` 上一致；
- 487,000 级词库查询保持索引查找，不退化为逐条扫描。

### 9.4 性能与稳定性

- 普通输入热查询 P95 ≤ 2 ms，P99 ≤ 5 ms；
- 进入分段模式不得重新加载词库；
- 选择一段后只解码未解决后缀；
- 相同候选快照在输入不变时顺序不变。

## 10. 明确不做

- 不使用 AI 判断句子是否“有意义”；
- 不访问云端候选服务；
- 不实现新的输入方案；
- 不把所有 THUOCL 分类设置为相同高权重；
- 不用手工向基础 TSV 只补一个“黄河入海流”来掩盖构建缺陷；
- 不在本阶段修改同步、语音、手写或其他功能。
