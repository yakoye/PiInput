# PiInput 多应用输入可靠性设计

## 背景与根因

v0.4.5 的核心与 Host 自动测试通过，但真实 Windows 应用仍暴露四类缺口：

1. 候选列被固定限制为 180 像素，并使用 `DT_END_ELLIPSIS`；同时一次 Composition 锁死宽度，长句候选因此全部显示为“我…”。
2. 常驻 Host 实际健康且已加载词库；新窗口延迟发生在 TSF Context、同步编辑与 Host 会话握手之间，不是词库重新加载。
3. 一个进程中的多个标签页共用单一 `CompositionMirror` 和 session id，旧标签页的组合串可能被 Resume 到新标签页。
4. Shift 只在 `OnKeyUp` 提供非空 Context 时切换；部分应用的 KeyUp Context 为空，造成只切换一次或完全不切换。
5. 中文标点策略主动把 `-`、`=`、`+` 变成全角字符，且无法识别数字后的列表点。

## 选定方案

保持“稳定 TSF 入口 DLL + 常驻 Host”的模块化结构，不把 50 万词词库重新塞回每个应用进程。修复入口状态边界、编辑回退和候选布局。

未采用的方案：

- 只增大候选列宽：六个长句仍会超出屏幕，不能解决全部省略。
- 把完整引擎移回 TSF DLL：会重新引入多版本 DLL 占用、每应用加载大词库和升级困难。

## Context 与首次输入

- 每个 `ITfContext` 获得独立 Host session id 与 `CompositionMirror` 状态；同一进程切换标签页时不携带旧 raw/caret。
- KeyDown 收到的 Context 与当前绑定不同时，先建立新会话，再发送当前按键；旧 sequence/session 的回复一律拒绝。
- 同步 `RequestEditSession` 暂时不可用时，更新操作也允许有界异步完成；异步成功后再发送 caret，失败则恢复 mirror，不吞按键。
- 常驻 Host、词库与一字母预热缓存继续全局复用；不得在新 Context 中重新读取词库。

## Shift 与混合输入

- 单独按下再释放 Shift 必须切换中文/英文；作为组合键使用时不得切换。
- `OnKeyUp` 的 Context 为空时使用 `ITfThreadMgr::GetFocus` / `GetTop` 取得当前 Context。
- 模式切换是入口本地确定状态，再同步给 Host；Host 暂时不可达时也不能让本地模式卡在错误状态。
- 验收句：`1.今天很不错。记住这个book_list——Bringup?` 能通过两次 Shift 完整输入。

## 标点策略

- 中文模式保留 `，。？！；：“”‘’、【】《》……——`。
- `+ - = _ / \\ | < >` 等程序员高频运算符保持 ASCII；特别保证连续 `++`、`--`、`==` 不全角化。
- 数字后紧接 `.` 时输出 ASCII 点，支持 `1.`；普通中文文字后的 `.` 仍输出 `。`。
- 英文模式全部输出 ASCII 标点。

## 候选布局

- 普通短词继续按设置每行 6 个（单字配置仍可为 9 个）。
- 第一行包含长句时，按文本长度自适应降为 2 列或 1 列；数字键、左右键和 `=` 的索引必须与实际列数一致。
- 候选窗口左上角在一个 Composition 内保持固定；宽度只允许向右单调增长，不因每个按键左右跳动。
- 单个不超过 32 个汉字的候选必须完整显示；超长段落才允许在屏幕工作区边界处省略。

## 测试与发布门槛

- 自动测试覆盖：长候选列数、完整显示宽度、Context 切换清空、旧回复失效、首次异步 update、Shift 空 Context 回退、两次 Shift 往返、混合标点句。
- Host 进程测试继续验证冷启动、首客户端、第二客户端和 50 万词词库性能。
- 手工兼容矩阵至少包括 Notepad4、Notepad++、文件资源管理器重命名框、Chrome 普通文本框；记录首键候选、Space、Shift、焦点切换和标点结果。
- 本轮只生成安装包，不自动覆盖用户当前安装，不推送仓库。
