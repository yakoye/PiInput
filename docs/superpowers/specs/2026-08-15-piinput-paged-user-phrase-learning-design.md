# PiInput 候选分页、用户造词与丝滑输入设计

## 1. 目标

本设计只解决以下相互关联的输入体验问题：

1. `=` 和 `-` 成为稳定、可预期的候选翻行键；
2. 用户通过词组或单字分段组成的新词，在成功上屏一次后成为本地用户词；
3. 用户词下一次输入时至少进入第一行，但一次学习不强制成为首选；
4. 用户第二、第三次选择后逐步前移，不再等待五次才体现学习；
5. 静态词库缺少整词时，合法单字必须能够组成完整文字并统一上屏；
6. 删除候选后，该候选消失，后续候选向左补位；
7. 所有学习、查询、分页和保存都不能给按键热路径带来可感知卡顿；
8. 实现必须通用，不允许通过向生产词库手工添加测试词完成验收。

本轮不处理边界覆盖、SCEL 新格式兼容、AI、云联想、拆字扩展、新符号功能或其他输入方案。

## 2. 已确认的现状与根因

### 2.1 “丝滑”缺失的实际原因

当前 `dist/windows-x64/data/piinput-base.lex` 包含 101,470 条词条。实际查询结果为：

- `lookup-word 丝滑` 无结果；
- `lookup-pinyin si'hua` 无整词结果；
- 小鹤输入 `sihx` 能正确解析为 `si'hua`；
- 引擎只能从现有单字临时组合出“死话、死花、四话、丝话”等结果。

外部 `dicts` 目录中的 11 个 SCEL 目前只有“电子词汇大全”和“计算机词汇大全”成功导入。“网络流行新词”等词库因非标准头、未知拼音表引用或词条结构异常被跳过。无法证明“丝滑”存在于这些未导入文件，但可以确认它没有进入最终二进制词库。

因此，“丝滑”问题同时暴露了两个独立事实：静态词库存在覆盖缺口；当前用户模型不能把新组合变成候选。本设计修复后者，SCEL 兼容另行设计。

### 2.2 `=` 当前不是纯翻行

`HostSession::apply(expand_next_row)` 当前会先在可信候选范围内移动候选行；到达可信范围末尾后，它会自动进入 `CandidateViewMode::segment_selection`，寻找第一个消费一个音节的候选，并把选择位置移动到该候选的真实索引。结果是：

- 同一个按键有“移动行”和“切换内部模式”两种用户可见效果；
- 进入新行后不一定选中第一个候选；
- 数字键选择目标可能与用户对当前行的判断不一致；
- 词语候选和单字兜底之间出现突变。

### 2.3 用户模型不能生成新候选

当前 `UserModel` 保存规范拼音、文字、次数、最近使用、固定和屏蔽状态，但 `Engine` 只把它作为 `IncrementalDecoder::UserScore`。候选必须先由静态词库或解码器生成，用户分数才有机会作用。

因此，静态词库中不存在的组合即使被记录，也不会在下一次查询时主动出现。根本修复是让用户模型同时成为一个候选来源，而不只是加分器。

### 2.4 “选择五次才明显变化”的原因

现有分数为：

```text
选择次数 × 50000 + 最近使用加分
```

不同来源的基础权重不在同一尺度上，固定的线性加分无法保证一次或两次选择能跨过原有排序差距。新设计不再依赖单一大分值，而使用明确学习等级和第一行保留规则。

## 3. 采用的总体方案

采用“只读静态词库 + 内存用户词库叠加层 + 用户排序学习”的结构：

```text
静态基础词库（只读）
        │
        ├── 完整词、真实短词、单字
        │
本地用户词库（可变、按规范拼音索引）
        │
        ├── 用户组成的新词
        ├── 用户选择次数
        ├── 最近使用
        ├── 固定首位
        └── 删除/屏蔽
        │
统一候选合并与稳定排序
        │
CandidateGrid 翻行与数字键选择
```

不采用“每次学习后重编译大词库”，因为它会把磁盘写入和词库构建引入输入热路径。不采用“继续堆静态词库作为唯一修复”，因为任何静态词库都无法覆盖用户姓名、新产品、地方称呼和个人新词。

## 4. 候选来源与稳定混排

候选来源按以下层级参与合并：

1. 用户明确固定首位；
2. 与完整规范拼音精确匹配的本地用户词；
3. 静态词库完整匹配和高质量整句；
4. 能消费输入前缀的真实短词；
5. 传统句子解码结果；
6. 合法单字兜底；
7. 动态拼接兜底。

上述层级不是“上一层全部耗尽后才出现下一层”。第一行必须稳定混排，让用户既能直接选择完整词，也能立即选择可消费前缀的真实短词。动态拼接只补空位，不能用大量无意义长句压住真实词条。

候选的稳定比较键依次为：

```text
固定状态
→ 学习等级
→ 用户选择次数（受上限约束）
→ 最近使用等级
→ 候选证据类型
→ 基础词频
→ 消费音节数
→ 词数
→ 稳定词条 ID / 文字 / 拼音
```

相同输入、相同设置、相同用户模型和相同 generation 必须得到完全相同的候选顺序。

## 5. 第一行用户词保留规则

一次成功选择或分段组成的新词必须在下一次相同规范拼音查询时进入第一行，但不强制第一个。

实现使用“第一行保留”而不是无限放大的分数：

1. 固定首位独占第一个位置；
2. 普通用户学习词最多占用第一行的两个保留位置；
3. 第一行其余位置继续由高质量静态候选和真实短词填充；
4. 用户学习词超过保留位置时，按学习等级、次数、最近使用和稳定 ID 选择进入第一行的词；
5. `items_per_row` 为 5～9 时，保留位置仍不超过两个，避免学习词挤走全部基础候选；
6. 用户词不够时，不保留空位，由其他候选自然补齐。

这条规则使一次学习立即可见，同时防止一次误选直接长期霸占首位。

## 6. 学习等级

### 6.1 等级 0：未学习

完全按静态词频、候选证据和解码质量排序。

### 6.2 等级 1：成功选择或组成 1 次

- 保证进入第一行；
- 不保证成为第一个；
- 可以排在一个或多个高质量基础候选之后；
- 同一 generation 不立即重排，下一次输入才使用新学习结果。

### 6.3 等级 2：成功选择 2 次

- 继续向第一行前部移动；
- 通常进入前三；
- 仍低于固定首位。

### 6.4 等级 3：成功选择 3 次及以上

- 具备竞争首选资格；
- 三次以后次数增长使用递减增益，不再线性无限增加；
- 选择次数设置饱和上限，避免整数溢出和永久霸榜。

### 6.5 固定首位

用户通过候选右键菜单执行“固定首位”后，该拼音下该词无条件成为第一个。取消固定只清除固定状态，保留学习次数和用户词身份。

## 7. 新词学习条件

只有满足全部条件才创建或更新用户词：

1. 当前为中文输入模式；
2. 最终文字至少包含两个汉字；
3. 输入已经解析为完整合法音节序列；
4. 所有音节都被用户选择的词段或单字消费；
5. 用户明确通过空格、数字键或候选点击完成选择；
6. 最终 TSF 提交实际成功；
7. 不是 Esc 取消；
8. 不是 Enter 上屏原始字母；
9. 不包含未完成尾部拼音；
10. 不把用户未明确选择的动态假句自动当成用户造词；
11. 用户学习设置处于启用状态。

全拼、小鹤双拼和以后其他拼音方案都先转换为同一规范拼音，因此：

```text
sihx  → si'hua
sihua → si'hua
```

两种输入入口共享同一用户词。

## 8. 分段组成与统一上屏

静态词库不存在整词时，分段选择过程如下：

1. 引擎解析完整规范拼音；
2. 查询从当前未解决位置开始的真实词条；
3. 按“消费音节更多的真实词 → 更短真实词 → 当前音节单字”排序；
4. 用户选择一个候选后，只消费它覆盖的音节；
5. 已选文字保留在组合区；
6. 剩余规范拼音继续生成候选；
7. Backspace 可以撤销最后一个已选段；
8. 所有音节解决后，最终文字只提交一次；
9. TSF 成功提交后记录完整规范拼音与完整文字；
10. 下次相同规范拼音查询时，完整用户词进入第一行。

生产代码不包含任何具体新词。自动测试可以使用“丝滑”“邓振铎”“叶鹏玉”等夹具证明通用行为，但这些词不得加入 `data/base_lexicon.tsv`、发布 `.lex` 或生产常量。

## 9. `=`、`-` 和方向键

### 9.1 `=` / 下方向键

二者都表示“下一候选行”：

1. 保持输入内容和候选顺序不变；
2. 活动行加一；
3. 新行活动列强制为 0；
4. 新行第一个候选高亮；
5. 数字 `1` 选择该行第一个候选；
6. 候选窗口从一行逐步扩展到 `visible_rows`；
7. 超过可见行数时滚动候选窗口；
8. 到最后一行后停止，不循环；
9. 组合状态下最后一行继续按 `=` 时吞掉按键，不上屏等号；
10. 同一候选集合内部翻行只移动视图，不重新运行解码和排序。

### 9.2 `-` / 上方向键

二者都表示“上一候选行”：

1. 活动行减一；
2. 新行活动列强制为 0；
3. 到第一行停止，不循环；
4. 组合状态下第一行继续按 `-` 时吞掉按键，不上屏减号；
5. 从分段候选第一页向上时，恢复正常候选最后一行并选中第一个。

### 9.3 左右方向键

只在当前行移动，不自动跨行。到行首或行尾时停止。

### 9.4 新 generation

输入字母、Backspace、Delete、中间编辑、选择词段或切换输入方案都会创建新 generation，并重置为第一行第一个。单纯翻行不会创建新的候选顺序，只更新候选视图状态。

## 10. 正常候选与分段兜底的分页衔接

用户只看到连续候选页，不需要理解内部模式：

1. 先浏览正常候选行；
2. 正常候选行耗尽后继续按 `=`，进入当前未解决位置的分段候选第一页；
3. 分段页第一个候选获得高亮；
4. 分段候选先列真实多音节词，再列真实短词，最后列单字；
5. 分段页按 `-` 可以返回正常候选最后一行；
6. 正常候选耗尽后，Host 使用当前 Session 已有的规范拼音和未解决位置生成一次分段候选快照；不得重新加载词库，也不得改变已经展示过的正常候选顺序；
7. 进入或退出分段页时，候选 ID 和 generation 必须更新，旧候选不能提交；返回正常页时恢复先前缓存的正常候选快照；
8. 分段页内部继续按 `=` 只向后翻行，不再次切换其他模式，也不重新生成候选。

## 11. 用户模型数据结构

将当前扁平 `pinyin + '\n' + word` 键改为按规范拼音索引的嵌套结构：

```cpp
struct UserEntry {
    std::uint32_t selection_count{};
    std::uint64_t last_used{};
    bool pinned{};
    bool suppressed{};
    bool user_created{};
};

std::unordered_map<
    std::string,
    std::unordered_map<std::string, UserEntry>
> entries_by_pinyin;
```

必须提供：

```cpp
record_selection(pinyin, word)
record_composed_phrase(pinyin, word)
query_exact(pinyin)
pin(pinyin, word)
unpin(pinyin, word)
suppress(pinyin, word)
remove_learning(pinyin, word)
```

`query_exact` 只返回指定规范拼音下的用户词，复杂度为 O(1 + k)，其中 k 为该拼音下的用户词数量，不能扫描全部用户数据。

## 12. 持久化与旧数据兼容

用户模型 TSV 新增可选第 7 列：

```text
pinyin	word	count	last_used	pinned	suppressed	user_created
```

兼容规则：

- 旧 4～6 列记录继续加载；
- 缺失 `user_created` 时默认为 `false`；
- 损坏行隔离报告，不得清空其他有效记录；
- 保存使用唯一临时文件、完整写入、Flush 和原子替换；
- 保存失败时保留旧文件；
- 屏蔽记录即使 `count == 0` 也必须持久化。

## 13. 删除与候选左移

“删除该词”的用户可见语义是：该拼音下该候选立即消失，后续候选向左补位。

处理规则：

1. 用户创建词：清除学习数据并保留屏蔽 tombstone，防止同词从其他来源重新出现；
2. 基础词库词：不修改只读词库，只写本地屏蔽记录；
3. 删除只影响完全相同的规范拼音和文字，不影响其他读音；
4. 删除后生成新候选 generation；
5. 当前页重新填满，后续候选左移；
6. 高亮优先保持在原屏幕位置；若越界则落到新列表最后一个有效候选；
7. 旧候选 ID 立即失效；
8. 取消固定与删除是两个动作，取消固定不会删除候选。

## 14. 性能与多窗口一致性

学习热路径只能修改内存并设置 dirty 标志，不得：

- 重编译静态词库；
- 重新加载静态词库；
- 同步写完整用户模型；
- 扫描全部用户词；
- 等待其他应用或 DLL；
- 阻塞 TSF 按键线程。

稳定 Host 进程持有唯一用户模型。任意应用成功学习后，其他应用的新 generation 立即可见；已经显示的旧 generation 不允许后台跳变。

用户模型在最后一次修改后 1～2 秒由 Host 后台批量保存，并在 Host 正常退出或升级前强制刷新。保存使用原子替换。

性能目标：

```text
用户词精确查询 P95 ≤ 0.2 ms（10,000 条用户词）
完整核心候选查询 P95 ≤ 2 ms
候选翻行 P95 ≤ 0.1 ms
内存学习更新 P95 ≤ 0.2 ms
按键热路径磁盘写入次数 = 0
```

## 15. 自动化测试要求

### 15.1 CandidateGrid

- `=`/下键进入下一行并把列重置为 0；
- `-`/上键进入上一行并把列重置为 0；
- 5～9 个每行候选全部覆盖；
- 不完整最后一行、空候选、单候选和最大数量安全；
- 第一行和最后一行不循环；
- 数字键只选择当前活动行；
- 输入变化后回到第一行第一个；
- 翻行不改变候选顺序。

### 15.2 用户词候选来源

测试夹具静态词库只放单字或词段，不放完整目标词：

- 第一次查询不存在完整词；
- 分段完成后创建用户词；
- 第二次查询完整词进入第一行；
- 全拼和小鹤共享规范拼音；
- 关闭学习时不创建；
- 重启加载后仍存在；
- 测试词只存在于临时夹具，不进入生产词库。

### 15.3 学习等级

- 一次选择进入第一行但不强制第一；
- 两次选择比一次靠前；
- 三次选择具备首选竞争资格；
- 三次以后递减增长；
- 固定首位始终第一；
- 取消固定恢复学习排序；
- 次数饱和不溢出；
- 同分结果稳定。

### 15.4 分段选择

- 多字词缺失时单字兜底可达；
- 选择一个词段只消费对应音节；
- 已选文字保留，剩余拼音继续查询；
- Backspace 撤销最后一段；
- 完成后统一一次上屏；
- TSF 失败不记录用户词；
- 旧 candidate ID 不能提交；
- 正常候选与分段候选可通过 `=`/`-` 双向衔接。

### 15.5 删除和屏蔽

- 删除用户词后候选消失并左移；
- 删除基础词后通过 tombstone 持久屏蔽；
- 其他读音不受影响；
- 删除末尾候选不越界；
- 重启后屏蔽仍有效；
- 取消固定不删除词。

### 15.6 持久化与并发

- 旧 4～6 列和新 7 列格式兼容；
- 损坏行不破坏有效数据；
- 保存失败保留旧文件；
- 无残留临时文件；
- 多窗口共享内存学习结果；
- 两次相邻保存不丢更新；
- 热路径不执行磁盘写入。

### 15.7 性能

使用至少 100,000 条静态词和 10,000 条用户词验证上述 P95 门槛，并单独验证第一次查询、热查询、翻行、学习和后台保存。

## 16. 手工验收

1. 在 Notepad++ 逐字组成一个静态词库不存在的新词，第二次输入时第一行出现；
2. 在 Notepad++ 学习后切换 Chrome、Word 或 Codex，同一新词立即可见；
3. 连续按 `=`，每次进入下一行并选中第一个；
4. 按 `-` 返回上一行并选中第一个；
5. 删除用户词后当前行左移补位，重新输入仍不出现；
6. 一次、两次、三次选择呈现逐步前移；
7. 固定首位后无条件第一，取消固定后词仍存在；
8. 候选未变化时窗口不跳动；
9. 记录首次输入和切换应用后的候选延迟，不能出现秒级停顿。

## 17. 明确不做

- 不向生产基础词库手工添加测试词；
- 不根据单篇测试文本增加专用规则；
- 不在学习时重建静态词库；
- 不在按键热路径同步写磁盘；
- 不把所有学习词强制排到第一；

## 18. 完成定义

只有同时满足以下条件才算完成：

1. 所有新增行为都有先失败后通过的自动测试；
2. 没有在生产词库或生产常量中加入测试目标词；
3. Release 全目标构建通过；
4. 全量 CTest 通过；
5. 真实发布词库性能门禁通过；
6. Windows Host/TSF 定向测试通过；
7. 用户模型旧格式迁移测试通过；
8. 安装包和便携测试包均携带更新后的文档；
9. 在至少 Notepad++、Notepad4 和 PiInput-Test 中完成手工验收；
10. 形成安装、使用、删除误学词和用户造词说明。
