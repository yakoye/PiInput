# PiInput 真实应用全量验收设计

日期：2026-08-13  
适用版本：v0.4.6-dev 及后续版本

## 1. 目标

建立一套长期复用、结果可追溯的 Windows 输入法验收体系。它必须把“核心自动测试通过”和“真实软件中可以正常输入”分开记录，不能再用单元测试代替真实应用兼容性结论。

本规范验证以下产品底线：

- 新打开软件后首键立即进入组合，不能等待数秒；
- 候选靠近文本插入点，只有应用不提供文本光标坐标时才退回鼠标附近；
- 候选清晰、单行稳定，输入内容不变时不得跳动、闪烁或反复缩放；
- `Space`、数字键、方向键、`-`、`=`、`Enter`、`Esc` 行为一致；
- 单独按 `Shift` 可可靠切换中文和英文，作为组合键时不得误切换；
- 全拼、小鹤双拼、长句、分段取字、中英混排、标点、英文补全、符号中心和帮助入口按设计工作；
- 切换窗口、标签页和输入框时，不继承其他输入框的组合状态，不丢首键；
- 安装、升级和卸载不要求结束全部应用；稳定入口和 Host 版本必须可诊断。

## 2. 测试分层与发布门槛

### 2.1 自动阻断测试

每个开发包发布前必须全部通过：

1. Release 全目标构建；
2. 完整 CTest，失败数必须为 0；
3. 407 个标准全拼音节；
4. 406 个用户确认的小鹤合法码；
5. 3500/7000 汉字覆盖；
6. 786 条结构化语料及扩展段落语料；
7. Host 冷启动、热连接、重启交接和 IPC；
8. 候选布局、稳定锚点、分页、方向键和分段取字；
9. Shift、中英混排和 ASCII/中文标点；
10. 安装器、卸载器、迁移、发布清单及 SHA-256。

### 2.2 真实应用发布必测

以下四类应用每次发布必须测试，任一关键用例失败则真实应用验收不通过：

| 编号 | 应用 | 主要输入面 |
|---|---|---|
| APP-01 | Notepad4 | 普通编辑区、新窗口、重新聚焦 |
| APP-02 | Notepad++ | 两个标签页、同进程多编辑区 |
| APP-03 | 文件资源管理器 | 新建文件或重命名编辑框 |
| APP-04 | Chrome | 普通网页文本框、多标签页 |

### 2.3 扩展兼容测试

环境中存在且可安全控制时全部测试；缺少软件、登录状态或自动化能力时记录 `BLOCKED`，不得写成通过：

- Windows 记事本；
- VS Code；
- Visual Studio；
- Edge；
- Word、Excel、PowerPoint；
- Windows Terminal；
- 微信；
- Claude；
- Codex/ChatGPT。

Codex/ChatGPT 桌面应用不通过自动化控制自身。该项只能由用户人工输入或由独立测试进程验证，并在报告中注明证据来源。

## 3. 统一结果状态

每条用例只能使用下列状态：

- `PASS`：观察结果完全符合标准；
- `FAIL`：能够复现且不符合标准；
- `BLOCKED`：受 UAC、登录、软件缺失、安全限制或第三方状态阻塞；
- `NOT RUN`：尚未执行；
- `N/A`：应用不具备该能力，且用例明确允许不适用。

不得用“看起来正常”“应该通过”代替状态。

## 4. 测试环境记录

每次报告开头记录：

- Windows 版本、缩放比例、显示器数量；
- PiInput 发布包版本和 ZIP SHA-256；
- `%LOCALAPPDATA%\PiInput\Runtime\current.json` 的 Host 版本；
- 稳定 Shim DLL 路径和 SHA-256；
- `PiInputHost.exe` 进程 ID、启动时间和实际路径；
- 输入方案、候选设置、英文候选和 `u/v` 兼容配置；
- 基础词库文件大小、词条数和自定义 SCEL 数量；
- 被测应用名称、版本、进程位数和 DPI。

如果安装版本、Host 版本和发布包不一致，立即停止功能结论，只记录为环境失败。

## 5. 计时方法

### 5.1 首次输入延迟

每个应用完全退出后重新打开，聚焦空文本框，输入第一个合法编码。分别记录：

- `T_key`：发出首键时刻；
- `T_comp`：组合文本首次可见时刻；
- `T_candidate`：候选窗首次可见时刻；
- `T_commit`：按 Space 后文字完成上屏时刻。

计算：

- 首键到组合：`T_comp - T_key`；
- 首键到候选：`T_candidate - T_key`；
- Space 到上屏：`T_commit - T_space`。

同一应用执行 5 次冷场景和 20 次热场景。报告 P50、P95、最大值，不只写平均值。

验收目标：

- 热场景首键到候选 P95 不超过 50 ms；
- 新应用首个客户端 P95 不超过 200 ms；
- Space 到上屏 P95 不超过 50 ms；
- 任何一次不得出现 1 秒以上无反馈。

测量工具自身精度不足时，报告观测上限和视频帧率，不伪造毫秒精度。

### 5.2 候选位置与稳定性

截图必须同时包含文本插入点和候选窗。记录：

- 候选窗左上角到 caret 底部的横向、纵向距离；
- 是否遮挡正在输入的组合文本；
- 输入同一组合期间左上角是否改变；
- 候选文本变长时是否出现省略号、裁切或模糊；
- 100%、125%、150%、200% 缩放下的清晰度。

应用提供 caret 坐标时，候选窗不得跟随鼠标；应用不提供时才允许使用鼠标附近回退。

## 6. 通用真实场景用例

以下用例在每个必测应用中执行。

### RW-001 首键冷启动

1. 完全退出被测应用；
2. 重新打开并立即聚焦编辑区；
3. 小鹤输入 `wo`，全拼输入 `wo`；
4. 观察组合和“我”候选；
5. Space 上屏。

通过标准：首键不丢失、无数秒空白、候选首项合理、Space 上屏一次且仅一次。

### RW-002 新窗口与连续切换

1. 在应用 A 输入一半 `woxm`，不确认；
2. 切到应用 B，输入 `gjjt`；
3. 切回应用 A，继续输入；
4. 重复 A/B 切换 20 次。

通过标准：两个输入框状态隔离；新窗口首键立即可用；候选只属于当前焦点；无旧回复覆盖新候选。

### RW-003 标签页隔离

在 Notepad++ 和 Chrome 各建立两个标签页，分别输入不同未完成编码并往返切换。

通过标准：标签页之间不串音；候选不留在非活动页；返回后状态符合该输入框自身状态。

### RW-004 Space、Enter、Esc

1. 输入 `gjjt`，Space 选择“感觉”；
2. 输入 `codex`，Enter 提交原始字母；
3. 输入 `woxmzd`，Esc 取消。

通过标准：Space 不被宿主吞掉；Enter 不触发错误候选；Esc 同时清理组合和候选窗。

### RW-005 候选导航

1. 输入具有多行候选的编码；
2. 用 `=`、`-`、上下左右键移动；
3. 用数字键选择当前活动行；
4. 抵达可靠整词末尾后继续按 `=`。

通过标准：默认一行；按 `=` 才展开或下移；整词耗尽后进入真实单字/分段取字，不展示无意义假句子；已选片段保留在组合区，最终统一上屏。

### RW-006 候选稳定性

逐字输入 `fwihkk`、`woxmzd`、`wojtdddd`，每键间隔 500 ms，不确认。

通过标准：每次新按键允许更新内容；输入未变化时候选窗不得重绘跳动；外框左上角稳定；长候选完整显示，不出现“我…”式裁切。

### RW-007 Shift 中英切换

1. 中文状态输入“今天”；
2. 单独按 Shift，输入 `book_list`；
3. 单独按 Shift，输入中文；
4. 用 Shift 作为大写或标点修饰键。

通过标准：单独 Shift 每次只切换一次；修饰键不切换；切换后首键不丢；英文和中文候选模式符合配置。

### RW-008 中英标点混排

输入：

```text
1.今天很不错。记住这个book_list——Bringup? ++ -- == 1.9
```

通过标准：`1.`、`1.9`、`++`、`--`、`==` 保持 ASCII；中文句号和破折号符合中文模式；英文问号符合英文状态。

### RW-009 全拼与小鹤基础

全拼和小鹤分别验证：

- `wo` → 我；
- `gjjt` → 感觉；
- `xmzd` → 现在；
- `vsgo` → 中国；
- `yuwh` 与 `yvwh` → 欲望；
- `xnhe`、`xnheul` 至少能够提供真实单字分段候选；
- `mkt` → 明天；
- `rug` → 如果、入股等真实候选；
- `hlheruhdlq` → 黄河入海流。

### RW-010 长句与段落

全拼和小鹤分别输入并验证候选、分段、修改和最终上屏：

```text
床前明月光，安得广厦千万间，大庇天下寒士俱欢颜！风雨不动安如山。呜呼！何时眼前突兀见此屋啊，高堂明镜悲白发，朝如青丝暮成雪。人生得意须尽欢，莫使金樽空对月，甘肃省民勤县大坝镇王谋村一社
```

同时使用用户提供的照护提醒、旅游政策、沟通语气、新闻、水母、手段与目的、笨狼故事和北京暴雨段落。

通过标准：候选顺序稳定；整句词库命中优先；无法整句命中时只对未解决位置提供真实词条；中途修正不丢已选片段；最终只上屏一次。

### RW-011 专业语料

输入固件、寄存器、配置空间、链路状态机、事务层、AER、IOMMU、ATS、PASID、SR-IOV、输入法候选排序和用户词频语料。

通过标准：启用相应专业词库后，专业词进入第一页；关闭专业词库后不得污染普通首选。

### RW-012 英文候选

在英文候选关闭和开启两种配置下测试：

- `r` → `r`、`right`、`really`；
- `re` → `re`、`really`、`remember`；
- `rev` → `rev`、`review`、`reverse`；
- `reve` → `reve`、`revile`、`reverse`；
- `b` → `b`、`but`、`because`；
- `bo` → `bo`、`both`；
- `boo` → `boo`、`book`、`boom`；
- `book` → `book`、`books`、`booked`。

再输入用户提供的 Market Talks 英文段落。

通过标准：关闭时完全直通；开启时首字母即有多个离线候选；用户词优先于内置词；方向、Space、Enter、Esc 和 caret 编辑正常。

### RW-013 符号、帮助与 Markdown

测试：

- 中文和英文标点全集；
- 符号中心触发序列；
- 帮助入口；
- 原有 `;sheshidu` 兼容；
- 单个反引号和三个反引号作为 Markdown 正常上屏；
- ``f 约定入口只在明确规则下触发，不破坏普通反引号。

符号中心每个内置符号至少执行一次检索和上屏，结果与 `data/symbols.tsv` 一致。

### RW-014 拆字模式

只有功能已实现时执行，否则状态为 `N/A`：

- 心丿 → 必；
- 王白石 → 碧；
- 木木木 → 森；
- 车又又又又 → 辍；
- 龍龍龍 → 龘；
- 大走之 → 达；
- 单人雨而 → 儒。

通过标准：拆分序列可编辑、可取消、可翻页；候选只来自可解释的部件匹配；不会污染普通拼音模式。

### RW-015 安装、升级和卸载

1. 记录当前 Shim、Host 和版本目录；
2. 保持普通应用打开，安装同入口的新 Host；
3. 验证新会话使用新 Host；
4. 运行卸载器并保留用户数据；
5. 重新安装并检查设置、学习和词库；
6. 再执行删除用户数据的显式卸载测试。

通过标准：不覆盖被占用 DLL；不要求结束所有应用；稳定入口版本一致；失败时保持旧版本可用；卸载器无缺失运行库；保留/删除用户数据严格服从选择。

## 7. 应用特有用例

### 7.1 文件资源管理器

- 文件重命名、文件夹重命名、新建文件夹名称；
- 取消重命名后候选立即消失；
- 文件名中的英文、下划线、连字符和句点保持 ASCII。

### 7.2 Chrome/Edge

- 普通文本框、contenteditable、地址栏；
- 地址栏和 URL/邮箱输入不应错误启动中文长组合；
- 两个标签页与两个窗口之间状态隔离；
- 网页缩放 80%、100%、125% 时候选仍靠近 caret。

### 7.3 Office

- Word 正文、批注；
- Excel 单元格内编辑和公式栏；
- PowerPoint 文本框；
- 组合期间撤销、换页和切换单元格不残留候选。

### 7.4 终端和代码编辑器

- Windows Terminal、VS Code、Visual Studio 中的 ASCII 标点；
- 代码标识符 `book_list`、`PCIe`、`SR-IOV`；
- `++`、`--`、`==`、反引号和 Markdown 代码围栏；
- 密码框或安全输入框不学习、不显示候选。

## 8. 报告格式

每次报告保存为：

```text
artifacts/test-reports/YYYYMMDD-HHMMSS-real-app-acceptance.md
```

每个应用使用同一表格：

| 用例 | 状态 | 冷启动 P50/P95/Max | 热输入 P50/P95/Max | 实际结果 | 截图/日志 |
|---|---|---:|---:|---|---|
| RW-001 | PASS/FAIL/BLOCKED |  |  |  |  |

报告结尾必须汇总：

- 自动测试通过数/总数；
- 必测应用 PASS/FAIL/BLOCKED 数；
- 扩展应用 PASS/FAIL/BLOCKED/NOT RUN 数；
- 所有失败的最短复现步骤；
- 安装版本、实际 Host 版本和发布包 SHA-256；
- 是否满足“可交给用户测试”的结论。

## 9. 安全和真实性约束

- UAC、安全桌面、登录和权限确认不得绕过或代替用户操作；
- 不为了测试强制结束用户正在工作的应用；
- 不自动控制 Codex/ChatGPT 自身；
- 不把自动发送文字当作真实 TSF 按键测试，必须区分文字注入和逐键输入；
- 截图、日志和计时必须来自本次运行；
- 未运行或被阻塞的项目必须明确标注，禁止推断为通过。
