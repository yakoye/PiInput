# PiInput 稳定 TSF 入口与独立 Host 架构设计

日期：2026-08-11  
状态：待用户书面复核  
适用范围：Windows 开发版升级链路、TSF 接入、候选界面、输入核心进程隔离

## 1. 背景与问题定义

当前 PiInput 将完整输入法实现编译进 `PiInputTSF.dll`。Windows 会把该 DLL 分别加载进 ChatGPT、Chrome、VS Code、Notepad4 等每个使用文本服务的进程。安装器即使把 COM 注册切换到新的版本目录，已经运行的进程仍会继续执行旧 DLL，直到进程退出。

这导致同一时刻出现以下不可接受状态：

- 磁盘和安装标记已经是新版本；
- 不同应用仍分别运行多个旧版本；
- 新旧候选布局、词库和按键行为同时存在；
- 开发测试必须逐个退出应用，甚至可能误判修复是否生效；
- DLL 内的崩溃、递归或堆栈溢出会直接拖死宿主应用。

这不是安装脚本能够彻底解决的问题，而是进程内 TSF 架构的固有限制。正常升级必须不再替换各应用正在执行的业务代码。

## 2. 设计目标

### 2.1 必须达到

1. 日常升级拼音、词库、排序、候选 UI、英文补全或配置逻辑时，不要求关闭 Chrome、ChatGPT、VS Code 等应用，也不要求重启电脑。
2. TSF 入口 DLL 长期稳定、体积小、职责少，不加载词库，不运行解码器，不绘制候选窗，不写用户数据库。
3. 全部可频繁变更的输入逻辑在独立 `PiInputHost.exe` 中运行；Host 可在升级时安全重启，所有应用自动重连。
4. Host 崩溃、超时或升级断开时，不得拖死宿主应用，不得造成递归、堆栈溢出或静默丢字。
5. 候选结果使用不可变快照和严格代次号；旧结果不能覆盖新输入。
6. 默认候选始终只显示一行；只有实际收到 `=` 或向下箭头的正式按键事件后才展开。TSF 探测事件不得改变状态。
7. 完成一次新的稳定 Profile 迁移后，Windows 菜单中只保留一个 PiInput 项，旧 Profile 自动停用并移除。
8. 保持核心跨平台：全拼、小鹤双拼、词库、排序和用户学习仍位于平台无关 C++ 核心中。
9. 保持纯离线、无 AI、无语音、无广告、无输入内容上传。

### 2.2 明确边界

- Windows 无法把已经映射到进程内的旧 DLL 原地替换。迁移到新 Profile 后，旧 DLL 可能暂时仍留在进程地址空间，但必须已经失活，不能继续接收按键。
- 普通 Host、词库、配置和候选 UI 升级不需要重启应用。
- 极少发生的稳定入口 DLL 协议破坏性升级，必须创建新的协议/Profile 世代，或提示一次注销系统；不得伪装成无重启热更新。
- 本阶段不建立第三方二进制插件市场。扩展通过稳定接口和数据格式实现，避免任意 DLL 进入输入热路径。

## 3. 方案比较与结论

### 方案 A：继续注册版本化完整 TSF DLL

优点是改动小。缺点是所有运行中应用永久持有旧代码，当前问题必然重复出现，因此否决。

### 方案 B：稳定入口 DLL，在进程内动态加载版本化引擎 DLL

它能减少注册变化，但版本化引擎仍进入应用进程。引擎卸载需要证明没有线程、窗口、COM 对象或回调仍在使用，升级和崩溃隔离都不可靠，因此否决。

### 方案 C：稳定 TSF 入口 DLL + 独立 Host 进程

入口仅完成 TSF/COM 必需操作，Host 拥有所有可变逻辑。升级时切换版本目录、平滑重启 Host、客户端重连。它是唯一同时解决版本一致性、升级占用和宿主崩溃隔离的方案，因此采用。

## 4. 总体架构

```text
Windows 应用进程
┌────────────────────────────────────┐
│ PiInputTSF.dll（稳定入口 / Shim）   │
│ - TSF COM 接口与 EditSession        │
│ - 最小按键消费策略                  │
│ - 本地组合串镜像                    │
│ - IPC 客户端与断线保护              │
│ - 不加载词库、不排序、不绘制候选窗  │
└─────────────────┬──────────────────┘
                  │ 每用户会话 IPC
                  ▼
┌────────────────────────────────────┐
│ PiInputHost.exe                    │
│ - SessionManager                   │
│ - 全拼 / 小鹤双拼 / 分段取字        │
│ - 词库、排序、用户学习              │
│ - 中文与英文候选                    │
│ - Candidate UI                     │
│ - 设置热加载                        │
│ - 升级排空与重启协议                │
└─────────────────┬──────────────────┘
                  │
                  ▼
┌────────────────────────────────────┐
│ piinput_core（跨平台 C++）          │
│ 解析、解码、词库、排名、测试接口    │
└────────────────────────────────────┘
```

### 4.1 稳定身份

新的稳定入口使用一次性永久身份，实施后不得随普通版本改变：

- TSF COM CLSID：`{13EB305F-2DA3-4CF7-8C45-16B016B801B5}`
- TSF Profile GUID：`{4ED27B7C-678E-4240-827A-24DA597F8D4B}`
- IPC 协议首版：`PIINPUT_IPC_V1`

当前 v0.3.x 的旧 CLSID/Profile 仅作为迁移源，不再作为后续版本入口。

## 5. 模块边界

### 5.1 `PiInputTSF.dll`

入口 DLL 只允许包含：

- COM 类工厂、TSF 激活和停用；
- `ITfKeyEventSink`、Composition、EditSession 和插入点位置获取；
- 一个无阻塞的本地按键状态机；
- 当前 Composition 原始串、光标和最后一个已确认候选快照的镜像；
- IPC 连接、协议协商、超时和重连；
- 将 Host 返回的编辑动作应用到 TSF Context。

明确禁止：

- 读取 `.lex`、SCEL、英文 TSV 或配置全集；
- 运行句子解码、候选排序和用户学习；
- 创建候选窗口；
- 网络访问；
- 同步磁盘写入；
- 在 `OnTestKeyDown` / `OnTestKeyUp` 中修改任何输入状态。

`OnTestKeyDown` 只能回答是否可能消费按键。只有正式 `OnKeyDown` 事件可以生成输入序列号和改变状态，以杜绝探测事件造成候选误展开。

### 5.2 `PiInputHost.exe`

Host 按当前 Windows 用户和登录 Session 各运行一个实例，内部继续模块化：

- `HostLifecycle`：单实例、启动、优雅排空、升级退出、崩溃恢复；
- `IpcServer`：认证、协议协商、消息收发、背压；
- `SessionManager`：为每个 TSF Context 保存独立输入会话；
- `ChineseEngine`：全拼、小鹤、增量音节、长句、分段取字；
- `EnglishEngine`：离线前缀补全和学习；
- `DictionaryManager`：基础、下载、SCEL、用户词库和原子重载；
- `RankingService`：稳定且可解释的排序；
- `CandidateController`：一行/展开状态、选择和分页；
- `CandidateWindow`：唯一候选 UI，不抢焦点；
- `SettingsManager`：配置校验、热加载和版本化快照；
- `UserDataWriter`：内存更新、批量原子落盘。

### 5.3 `piinput_core`

跨平台核心不依赖 Win32、COM、窗口或命名管道。Host 通过清晰接口使用它；CLI、测试程序和未来 macOS/Android/iOS 前端复用同一核心。

### 5.4 扩展边界

后续扩展通过下列稳定边界完成：

- 输入方案：标准拼音音节接口和数据化双拼映射；
- 词库：版本化 `.lex` 和统一导入中间格式；
- 排序：确定性的特征输入和稳定输出 ID；
- 候选 UI：Host 内部 ViewModel，不进入核心；
- IPC：按消息版本添加可选字段，旧客户端忽略未知字段。

## 6. IPC 和会话模型

### 6.1 传输与访问控制

- 使用本地 Named Pipe，不开放 TCP 端口；
- Pipe 名包含 Windows Session ID 和协议主版本；
- ACL 只允许当前用户和 LocalSystem；
- 首次握手校验用户 SID、协议版本、Host 构建 ID 和随机连接 nonce；
- 不传输到网络，不记录完整输入正文到普通日志。

### 6.2 消息关键字段

每条消息至少包含：

```text
protocol_version
client_instance_id
session_id
sequence
generation
message_type
payload
```

- `sequence` 对单个连接严格递增，用于检测重复和丢失；
- `generation` 对 Composition 每次内容改变递增；
- Host 返回的候选和动作必须携带对应 generation；
- Shim 丢弃小于当前 generation 的所有响应；
- 候选选择提交候选唯一 ID，而不是“第几个”。

### 6.3 非阻塞策略

TSF 回调不得无限等待 Host：

- 未开始 Composition 且 Host 不可用时，字母直接交给应用，保证键盘可用；
- 已开始 Composition 时，Shim 保留原始串和光标，不清空用户输入；
- 候选计算异步完成，通过 Shim 的消息窗口触发异步 EditSession；
- Commit/Cancel 必须等待可控的短事务结果并检查 `RequestEditSession` 与 `session_result`；失败则保留镜像状态并允许重试；
- 不在 TSF 回调中启动递归消息循环。

## 7. 候选窗口与按键状态

### 7.1 默认一行规则

`CandidateController` 使用明确状态：

```text
Collapsed -> Expanded -> Collapsed
```

- 新输入、插入、删除、切换会话、收到新 generation：重置为 `Collapsed`；
- `Collapsed` 永远只显示设置的 `items_per_row` 个候选；
- 只有正式 `OnKeyDown` 产生的 `=` 或 Down 动作可以进入 `Expanded`；
- `-` 或 Up 在展开状态逐行向上；到首行后保持边界，不生成假候选；
- 数字键按当前活动行选择；候选 ID 与 generation 必须同时匹配；
- `OnTestKeyDown`、焦点切换、候选刷新、设置热加载都不得展开。

### 7.2 v0.3.9 问题的诊断门禁

开发版提供只在本地开启的结构化按键追踪，记录事件类型、虚拟键、sequence、generation 和候选视图状态，不记录已上屏正文。测试必须证明输入 `drlojuzi` 的每个字母后都保持一行；只有追加一个正式 `=` KeyDown 才显示多行。

## 8. 安装与无重启升级

### 8.1 目录布局

```text
%LOCALAPPDATA%\PiInput\Runtime
├── Shim
│   └── PiInputTSF.dll          # 稳定入口，普通升级不替换
├── versions
│   └── <version-build-id>
│       ├── PiInputHost.exe
│       ├── bin
│       └── data
├── current.json                # 原子指向当前 Host 版本
└── rollback.json               # 最近一次已验证版本

%LOCALAPPDATA%\PiInput\UserData # 与程序版本分离
```

### 8.2 首次迁移

1. 将稳定 Shim 和新版本 Host 安装到临时目录并校验哈希；
2. 启动新 Host，完成自检、词库打开和 IPC 握手测试；
3. 注册新的永久 CLSID/Profile，将其加入当前用户键盘列表；
4. 在测试 Context 中验证激活、Composition、候选和 Commit；
5. 原子写入 `current.json`；
6. 停用并移除旧 Profile；
7. 保留仍被进程映射的旧文件，待解锁后清理或安排重启后删除；
8. 任一步失败则恢复旧 Profile 和旧 current 标记，不留下两个可用菜单项。

迁移后，旧 DLL 即使仍显示在某进程模块列表中，也只是未卸载的失活模块。诊断工具必须分别显示“已加载”和“当前活动 Profile”，不能再把加载旧模块直接等同于正在使用旧输入法。

### 8.3 日常升级

1. 安装完整新版本目录；
2. 启动新 Host 并完成健康检查；
3. 通知旧 Host 进入 drain，只处理已经接收的事务；
4. 原子切换 `current.json`；
5. 新 Host 接管固定 Pipe；
6. Shim 自动重连并重新同步每个活动 Session 的镜像状态；
7. 旧 Host 无会话后退出；
8. 安装器报告客户端重连数量、Host 构建 ID 和健康状态。

升级不关闭用户应用，也不覆盖正在执行的业务 DLL。

## 9. 崩溃、超时与回滚

- Shim 中所有 IPC 入口必须有深度为一的重入保护；重入时立即返回安全结果，禁止递归调用 Host；
- Host 使用顶层异常边界，单个会话异常只销毁该 session，不终止其他应用会话；
- 连续握手或健康检查失败时，启动器自动回退 `rollback.json`；
- 候选 UI 崩溃不得影响 Composition；可继续编辑并用 Enter 上屏原始串；
- 词库重载采用“构建新快照 -> 完整校验 -> 原子交换”，失败继续使用旧快照；
- 用户学习批量写入，失败保留内存队列并限量重试；
- 所有超时、HRESULT 和协议错误写入有界本地诊断日志，不写完整输入内容。

## 10. 测试与验收

### 10.1 单元和协议测试

- IPC 编解码、未知字段、截断消息、错误长度和协议协商；
- sequence/generation 去重和乱序响应丢弃；
- CandidateController 默认一行、显式展开、重置和边界；
- `OnTestKeyDown` 纯函数/无状态变化；
- Composition 镜像、光标、提交失败回滚；
- Host 断线、重连和会话恢复；
- 词库与设置快照原子切换。

### 10.2 Windows 集成测试

- 两个独立测试进程同时连接 Host；升级 Host 后两个进程不退出且都报告新 build ID；
- 保持 ChatGPT/Chrome/VS Code 运行完成升级，新输入会话使用同一 Host 版本；
- 人为终止 Host，Shim 不崩溃、不栈溢出，Host 重启后恢复候选；
- 输入 `drlojuzi` 只显示一行，按 `=` 后才展开；
- `drlojuzi` 首选“段落句子”，候选不因异步响应跳变；
- 全拼、小鹤双拼、分段取字、英文候选、标点和 Shift 状态机全部通过现有回归语料；
- Notepad4、Notepad、Chrome、VS Code、ChatGPT、Office 至少完成 Composition、选词、取消和切换测试。

### 10.3 发布门禁

- Release 全目标构建成功；
- 全量 CTest 通过；
- 安装器升级夹具证明不终止客户端进程；
- Host 重启压力测试至少 100 次，无输入丢失、死锁或句柄持续增长；
- 候选查询与 IPC 合计热路径 P95 不高于 10 ms，P99 不高于 20 ms；
- 安装包清单、SHA-256、许可证和安装使用文档同步更新；
- 在用户机器上安装前先提供包和验证记录，由用户决定是否运行安装器。

## 11. 实施顺序

1. 先为 v0.3.9 候选误展开建立可重复的按键序列测试并修复当前状态机；
2. 定义并测试 IPC V1 和进程无关 Session 模型；
3. 把跨平台引擎、词库、排序和设置迁入 Host；
4. 把候选窗口迁入 Host；
5. 将当前 TSF 实现收缩为稳定 Shim；
6. 完成 Host 崩溃恢复、重连和升级排空；
7. 实现新 CLSID/Profile 的事务式迁移安装；
8. 运行多进程无重启升级验收；
9. 更新安装、使用、卸载、故障排查和扩展开发文档；
10. 只生成本地安装包，不推送远程仓库，直到用户确认安装成功。

## 12. 完成定义

只有同时满足以下条件才可以宣称问题彻底解决：

- 系统中活动的 PiInput Profile 永久指向稳定 Shim；
- 所有新旧应用会话都连接同一个当前 Host build ID；
- 普通升级期间应用进程不退出且输入会话可恢复；
- 旧 DLL 仅可能作为失活映射存在，不再处理按键；
- v0.3.9 的候选三行误展开测试已复现并通过修复；
- Host 崩溃和升级不会拖死宿主应用；
- 用户最终只需运行一个安装器，并可从系统“已安装的应用”正常卸载。
