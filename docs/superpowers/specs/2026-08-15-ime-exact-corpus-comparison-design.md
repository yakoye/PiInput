# 输入法三组文本逐字准确对照测试设计

## 目标

使用搜狗小鹤双拼与 PiInput 小鹤双拼，把三组真实文本完整输入到 Windows 编辑器。最终输出必须逐字、逐数字、逐标点一致，并记录完成正确文本所需的真实操作成本。

## 核心原则

1. 候选探查窗口与正式正文窗口隔离。
2. 正式正文设置不可回退的确认边界；任何删除、撤销和 Escape 都不得影响边界之前的文字。
3. 按自然词语、动词短语、固定搭配断开输入，不按固定字数机械切分。
4. 先查看当前可见候选行；找不到目标才按 `=` 或向下键逐行查找。
5. 当前拼音找不到目标词语时，缩短为较小词组；最后才退到单字。
6. 只保留经过逐段校验的文字。整个文本完成后再次与目标文本进行精确比较。

## 输入流程

候选探查窗口负责确定每个自然片段的实际候选路径：输入码、候选行、数字键、是否需要缩短片段。探查窗口允许取消当前组合，但不保存为最终结果。

正式正文窗口只执行已经确认的路径。每个片段完成后记录确认边界；若实际输出不符，停止测试并返回探查窗口重新确定路径，不在正式正文中盲目删除。

### 逐键视觉观察门禁

真实用户每按一个字母都会观察候选框，因此测试必须保存同样的决策过程：

1. 每输入一个字母后刷新并观察当前候选框。
2. 候选框尚未稳定或目标未出现时，只能继续输入字母，不能提前按空格。
3. 按空格、数字键、`=`、上下方向键之前，必须基于最新候选框作出决定。
4. 只有可见候选与目标文字完全一致时才允许提交。
5. 例如 `vivs` 显示 `1.职中 2.之中` 时，必须选择 `2`，不得先按空格再删除“职中”。
6. 视觉观察不计入物理按键数，但记录候选何时出现、首选何时变化以及最终选择依据。

正式正文测试不允许“先上屏再校验”。校验发生在确认键之前；上屏后的文本应当已经正确。

## 动态分段策略

分段不是预先固定的机械切词，而是模拟用户看到候选后的即时决定：

1. 先尝试当前剩余内容能够自然输入的最长短句。
2. 首选正确就用空格确认整段。
3. 当前行存在正确候选就用数字键选择。
4. 当前行找不到时先翻下一行；仍找不到，才从前面拆出一个高把握词。
5. 高把握词确认后，把剩余内容重新作为一个较长短句匹配，而不是继续机械拆成单字。

代表性路径：

- 原文：`我一直沉浸在飞鸟集的翻译打磨之中`
- 实际操作：`我␠ / 一直␠ / 沉浸␠ / 在→2 / 飞鸟集的翻译打磨␠ / 之中␠`

其他示例：

- `听到␠ / 有人␠ / 嫌弃饭菜不好`，若长段不正确再拆 `嫌弃 / 饭菜 / 不好`。
- `让我的思绪走近你`，若整段不正确则拆 `让 / 我的思绪 / 走近你`。
- `萤火煽秋夜`，先在整段候选中选择 `萤火`，再对剩余部分选择 `煽 / 秋夜`。

优先利用输入法的“已选前缀保留在组合区、剩余拼音继续选词”能力；只有输入法不支持该路径时，才分别提交多个词。

## 记录指标

- 字母按键数；
- 空格确认数；
- 数字选词数；
- 候选翻行数；
- 缩短重输数；
- 当前组合取消数；
- 标点和数字按键数；
- 总耗时；
- 逐键候选观察次数；
- 目标候选首次出现时的输入长度；
- 最终精确匹配结果。

候选观察本身不计为按键；探查窗口中的试验按键单独记录，不混入最终正文所需按键。

## 成功标准

1. 搜狗输出与目标文本完全一致。
2. PiInput 输出与目标文本完全一致。
3. 两款输入法均有逐片段候选路径和操作计数。
4. 报告明确区分首选准确率、修正成本和最终可完成性。
5. 不修改 PiInput 生产代码，不改变词库和用户学习数据。

## 学习效果与未见文本

原三组文本分别连续完成三遍准确输入。第 1、2、3 遍独立记录候选排名、数字选词、翻行、缩短重输、总按键和耗时，用于观察输入法的用户学习效果。现有输入法已经带有用户历史，因此第 1 遍称为“当前用户状态下首次完整测试”，不称为全新安装冷启动。

原文本三遍完成后，才允许首次输入 `tests/data/unseen_generalization_corpus_2026-08-15.txt`。未见语料分为：

1. 日常生活自然中文；
2. 文言文；
3. 包含 PCIe、LTSSM、文件名、版本号和英文短语的中英文混排。

未见语料只测试一遍，用来区分“记住已输入内容”与“对新内容的泛化能力”。在首次测试前不得把这些句子加入基础词库、用户词库或排序测试数据。
