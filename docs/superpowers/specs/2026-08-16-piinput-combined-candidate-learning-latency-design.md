# PiInput 组合候选、一次学习与输入延迟修复设计

## 目标

本轮只解决四项稳定性问题：

1. `=` 展开后保留已有整词候选，并在其后继续排列整词、最后才排列分段/单字候选。
2. 用户通过分段选字完成一个新词后，成功上屏一次即记住；下一次同码进入第一行。
3. 将“开悟”和“丝滑”纳入随程序发布的基础词库。
4. 消除 Codex 等应用连续输入时的可感知停顿，并用逐键性能门禁防止回归。

## 候选行规则

- 折叠状态只显示第 1 行。
- 第一次按 `=` 后显示 `[candidates].visible_rows` 行，默认 3 行，设置允许 2 至 6 行。
- 选中位置移动到第 2 行第 1 项；以后每按一次 `=` 向下移动一行，`-` 向上移动一行。
- 候选顺序固定为：
  1. 当前拼音对应的可信整词候选；
  2. 当前未解决拼音对应的真实分段词候选；
  3. 当前未解决音节的单字候选。
- 从整词浏览进入分段选择时，不得替换或删除已经显示的整词候选。
- 连续按 `=` 时采用普通滚动队列：活动行越过可见区域后，最早的行自然滚出视线，不固定首行。
- 数字序号只显示在当前活动行，非活动行只显示候选文字。
- 相同输入 generation 内候选内容和顺序保持不变；只改变高亮行不得重新查询词库。
- 展开高度由 `visible_rows` 控制，不写死为两行或三行。

## 选择与学习

- 选择整词候选时沿用普通选词学习。
- 分段选择过程中，已选文字留在组合区，剩余拼音继续提供候选，最后只上屏一次。
- 只有 TSF 确认最终上屏成功后才记录学习；失败、取消或过期 generation 不学习。
- 两个及以上汉字组成的新词第一次成功上屏即建立用户词条，下一次同拼音进入第一行，但不强制成为首选。
- 第二次、第三次选择继续提高顺序；固定首位仍是独立显式操作。
- 删除误学词只删除该用户学习状态，基础候选自然左移。

## 基础词库

- `开悟\tkai'wu` 与 `丝滑\tsi'hua` 写入基础 TSV，并进入发布包实际加载的二进制词库。
- 这两条是用户明确要求的基础词补充；通用的新词学习能力必须由算法完成，禁止用逐词硬编码替代。

## 性能

- Host 进程继续唯一加载真实大词库，各应用的 TSF Shim 不重复加载词库。
- 同一输入 generation 的候选快照只构造一次；窗口移动高亮不得触发 Engine 查询。
- 增加真实连续输入逐键基准，记录 P50/P95/P99 和最大值。
- Release 门禁目标：热查询 P95 不高于 5 ms，单个逐键查询最大值不高于 20 ms；若真实 Windows UI 仍有停顿，继续分离 Host 查询、管道往返、TSF 编辑和绘制耗时。

## 验收

- `mingtian`/`mktm`：折叠首选“明天”；按 `=` 后保留第 1 行，展开到配置行数，先遍历词语，之后才出现单字。
- 用单字分段组成一个词，成功一次后新会话同码可在第一行看到该词。
- `kaiwu`/`kdwu` 可得到“开悟”；`sihua`/`sihx` 可得到“丝滑”。
- `visible_rows=3/4/5/6` 时展开行数和选择移动均正确。
- 连续输入现实长串时无候选乱跳，性能门禁通过。
