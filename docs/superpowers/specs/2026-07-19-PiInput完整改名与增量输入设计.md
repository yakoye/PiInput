# PiInput 完整改名、增量输入与配置系统设计

## 1. 目标

本阶段一次性完成以下工作：

1. 产品、源码、程序、Windows 输入法、运行目录、本地仓库和 GitHub 仓库统一改名为 `PiInput`；
2. 将当前用户词库、设置和学习数据迁移到新目录，验证成功后清理旧运行环境；
3. 把增量候选从“整词前缀查询”升级为支持任意长短输入的增量句子解码；
4. 在全拼中支持可配置的 `u/v/ü/u:` 输入习惯兼容；
5. 建立可热加载的配置文件；
6. 增加默认关闭的离线英文候选；
7. 候选窗口支持每行 5～9 项、1～5 行，以及按行滚动；
8. 扩展自动测试，并整理当前项目与运行目录。

不增加 AI、云联想、语音、广告或联网输入。按键热路径仍不得访问网络或同步读写磁盘。

## 3. 一次性迁移与清理

### 3.1 迁移顺序

```text
确认旧用户数据和已注册 DLL
→ 建立只读备份清单与哈希
→ 构建 PiInput
→ 安装新的 TSF 服务和 Profile
→ 复制词库、设置、用户学习和自定义数据
→ 验证新数据可读、候选可查询、Profile 可用
→ 注销旧 TSF 服务
→ 删除旧运行目录
→ 重命名本地项目和 GitHub 仓库
→ 清理旧源码副本与归档
```

### 3.2 数据冲突规则

- 新目录不存在：完整复制旧数据；
- 新目录已存在且目标文件相同：保留一个；
- 新目录存在不同文件：把旧文件临时保存为带时间戳的迁移副本，完成合并验证后再清理；
- 设置字段使用新配置模型迁移，未知旧字段写入迁移日志但不阻断；
- 用户词频按 `pinyin + word` 合并，选择次数取较大值，避免重复放大；
- 删除旧目录前必须重新读取新词库并通过关键候选测试。

### 3.3 锁定文件

旧 DLL 仍被应用加载时：

- 不终止应用；
- 先注销并切换到 PiInput；
- 将旧文件登记为 Windows 下次启动时删除；
- 当前迁移报告明确显示“等待重启清理”；
- 重启后验证旧运行目录不存在。

### 3.4 回滚

在新 Profile、词库和配置全部验证前，不删除旧用户数据。任何验证失败都停止清理，保留备份清单和错误日志。GitHub 仓库改名放在本地构建、安装和数据迁移验证之后。

## 4. 配置系统

### 4.1 文件位置与格式

```text
%LOCALAPPDATA%\PiInput\UserData\settings.ini
```

INI 使用 UTF-8，无 BOM。键名使用小写蛇形命名；布尔值仅接受 `true/false`；整数必须经过范围校验。未知节和未知字段保留但忽略，方便向前兼容。

默认配置：

```ini
[general]
schema=flypy
hot_reload=true

[pinyin]
uv_compatibility=true
accept_u_colon=true
incomplete_candidates=true
prefix_beam_width=32
prefix_scan_limit=4096

[candidates]
items_per_row=6
visible_rows=3
max_items=90
horizontal=true
equal_key=next_row
minus_key=previous_row
down_key=next_row
up_key=previous_row

[english]
enabled=false
builtin_dictionary=true
user_dictionary=true
user_learning=true
items_per_row=6

[punctuation]
mode=chinese
```

### 4.2 数据结构

```cpp
struct PinyinSettings {
    bool uv_compatibility;
    bool accept_u_colon;
    bool incomplete_candidates;
    std::size_t prefix_beam_width;
    std::size_t prefix_scan_limit;
};

struct CandidateSettings {
    std::size_t items_per_row;
    std::size_t visible_rows;
    std::size_t max_items;
};

struct EnglishSettings {
    bool enabled;
    bool builtin_dictionary;
    bool user_dictionary;
    bool user_learning;
    std::size_t items_per_row;
};

struct SettingsSnapshot {
    std::uint64_t generation;
    PinyinSettings pinyin;
    CandidateSettings candidates;
    EnglishSettings english;
    PunctuationMode punctuation;
};
```

候选会话持有不可变 `SettingsSnapshot`。配置更新只创建新快照，不修改正在显示的候选。

### 4.3 校验规则

| 字段 | 范围或枚举 | 非法值处理 |
|---|---|---|
| `schema` | `full`、`flypy` 及现有内置方案 | 使用上一有效值 |
| `prefix_beam_width` | 8～128 | 使用上一有效值 |
| `prefix_scan_limit` | 128～16384 | 使用上一有效值 |
| `items_per_row` | 5～9 | 使用上一有效值 |
| `visible_rows` | 1～5 | 使用上一有效值 |
| `max_items` | 9～180，且不少于一屏 | 使用上一有效值 |
| `punctuation.mode` | `chinese/english/programmer` | 使用上一有效值 |

配置文件保存后检测修改时间。解析在非按键热路径完成；当前 Composition 结束后原子切换到新快照。语法错误写入 `%LOCALAPPDATA%\PiInput\UserData\logs\settings.log`，继续使用上一份有效配置。

## 5. 任意长度增量句子解码

### 5.1 当前问题

整串词库前缀查询只能处理词库中存在的完整长词。输入由多个词组成或句尾音节尚未完成时，整串可能无匹配，候选为空。

### 5.2 新模型

输入解析生成：

```cpp
struct IncrementalParse {
    std::vector<std::string> complete_syllables;
    std::string trailing_prefix;
    std::string canonical_prefix;
    int parse_score;
};
```

解码过程：

1. 全拼或小鹤解析出多个 `IncrementalParse`；
2. 对完整音节建立普通词图边；
3. 对最后未完成音节建立前缀边；
4. 词图 Beam 保留固定宽度的最佳路径；
5. 尾部前缀候选与前面路径拼接；
6. 使用基础词频、用户学习、词数惩罚、完整匹配奖励和补全长度惩罚统一排序；
7. 使用稳定词条 ID 处理同分，保证重复查询顺序一致。

完整输入继续优先于补全输入。前缀路径只补全最后一个未完成音节，不在中间任意插入字符，不承担拼写纠错。

### 5.3 性能边界

- `prefix_beam_width` 控制每个音节位置的路径数；
- `prefix_scan_limit` 控制尾部前缀最多扫描词条数；
- 单次引擎返回不超过 `max_items`；
- 词库使用有序拼音索引和 `lower_bound`，禁止全库扫描；
- 所有查询只读内存中的词库与设置快照。

## 6. 全拼 `u/v/ü/u:` 兼容

### 6.1 配置开关

`uv_compatibility=true` 时支持：

```text
ju / jv
qu / qv
xu / xv
yu / yv
lü / lv / lu:
nü / nv / nu:
lüe / lve / lu:e
nüe / nve / nu:e
```

这些输入规范化到词库内部标准拼音。`jugelizi` 和 `jvgelizi` 必须得到相同的“举个例子”候选。

`uv_compatibility=false` 时仅接受标准键盘约定；`accept_u_colon` 单独控制 `u:`。小鹤双拼中的 `v` 是方案键位，不应用全拼替换规则。

### 6.2 规范化接口

```cpp
std::vector<std::string> normalize_full_pinyin_variants(
    std::string_view input,
    const PinyinSettings& settings,
    std::size_t variant_limit);
```

变体数量必须有上限，同一规范拼音去重，并按标准写法、常见写法、兼容写法的固定顺序排序。

## 7. 英文候选

### 7.1 行为

默认 `english.enabled=false`。开启后，英文模式输入字母会显示离线候选；关闭时保持当前直接输入英文行为。

候选来源：

1. 用户固定和自定义词；
2. 用户已选择英文词的本地计数；
3. 内置分级英文基础词库。

基础词库使用具有明确再分发许可证的分级英文词表，并在 `THIRD_PARTY_LICENSES.md` 记录来源、版本、许可证和生成方式。候选功能断网完整可用。

### 7.2 数据结构

```cpp
struct EnglishEntry {
    std::string word;
    std::uint32_t base_weight;
    std::uint32_t flags;
};
```

运行时按小写前缀查询，同时保留候选原始大小写。排序顺序为用户固定、用户学习、基础词频、补全长度、稳定词条 ID。

只记录被用户选择的英文词和次数，不记录完整按键历史。用户可编辑 `%LOCALAPPDATA%\PiInput\UserData\english_user.tsv`。

## 8. 候选窗口与按行滚动

候选按二维网格布局：

```text
每行：5～9 项
可见：1～5 行
默认：每行 6 项、显示 3 行
```

操作：

- `=` 和下箭头：当前行向下移动一行；
- `-` 和上箭头：当前行向上移动一行；
- 到边界时保持不动，不循环；
- 数字键选择当前高亮行中对应编号；
- 鼠标点击可选择任意可见候选；
- Esc 关闭候选或取消 Composition；
- 输入改变后回到第一行；
- 当前输入未改变时，只移动视窗，不重新排序候选。

候选快照继续保存最多 `max_items` 个稳定结果。滚动只修改 `first_visible_row` 和 `active_row`。

## 9. 测试设计

### 9.1 自动前缀矩阵

对全拼和小鹤词句生成从第一个按键到完整编码的所有前缀。覆盖：

- 单字、双字词、长词和多词句子；
- 奇数和偶数长度小鹤编码；
- 长句最后一个音节只输入一个键或部分字母；
- Backspace 后回退到上一前缀；
- 相同输入重复查询的候选顺序稳定；
- 非法前缀不崩溃、不扫描全库。

测试断言分层：完整输入要求目标候选命中；未完成输入要求候选非空且与已输入拼音兼容，不强制每个前缀都把最终整句排第一。

### 9.2 兼容输入矩阵

为 `u/v/ü/u:` 等价组生成全拼解析、候选、删除回退和配置开关测试。小鹤测试确认全拼兼容开关不会改变双拼键位。

### 9.3 设置测试

- 默认值；
- 所有字段上下界；
- 未知字段；
- 损坏 INI；
- 热加载不改变当前候选快照；
- 下一次 Composition 使用新设置；
- 错误日志不包含输入内容。

### 9.4 英文候选测试

- 默认关闭；
- 开启后的前缀命中；
- 用户自定义词和用户选择提升；
- 大小写；
- 数字与标点结束英文 Composition；
- 不保存未选择的英文输入。

### 9.5 候选网格测试

- 每行 5～9 项；
- 1～5 行；
- `=`/下箭头和 `-`/上箭头行为一致；
- 边界不越界；
- 数字键只选择当前高亮行；
- 横向尺寸、高 DPI 和候选定位回归。

### 9.6 改名与迁移门禁

- 当前源码、文件名、目标名、文档和运行目录中旧品牌文本匹配数为 0；
- Git 历史排除在检查范围外；
- 新 TSF GUID 与旧 GUID 不同；
- 新安装、旧数据迁移、冲突、回滚和等待重启删除均有测试；
- GitHub 远程地址、本地目录和安装目录均为 PiInput；
- 用户数据迁移前后关键文件哈希或语义内容一致。
