# PiInput v0.8.3 版本说明

本版修的都是「某个窗口里打不出中文」，三个成因互不相同，只有把每一个都测到才分得开。

## Chrome 的标签重命名和书签编辑

打字母出来的是拉丁文，语言指示器还显示「中」，按 Shift 也不切换。

这几个框被 PiInput 判成了**密码输入域**，于是所有按键原样放行。判据里有六项，五项是密码和 PIN，第六项是 `IS_PRIVATE` —— 而它的意思是「**这段文本不要被记住**」，不是「这个框不接受输入」。Chrome 会给普通文本框打这个标记，我们理解错了。

现在拆成两个独立的问题：哪些输入域该拒绝转换（密码和 PIN），哪些只是不该被记忆（`IS_PRIVATE`）。

追踪里加了每次拒绝的**理由**。此前五条拒绝路径在记录里长得一模一样，都只是「按键到了、没有派发」，分不出是哪条；现在各有各的名字，其中三条是粘性的——一旦触发就不会自愈，正对应「进了那个框就再也打不出中文」。

## yesymbol 里完全打不出中文

不是某个框的问题，是**整个程序**里都不行 —— 因为 PiInput 根本没被加载进那个进程。

它的 UI 线程是多线程套间（MTA）。在 MTA 线程上用 COM 创建 `Apartment` 模型的对象，会把它构造到另一个线程上，对一个必须跑在窗口所在线程的输入法毫无用处。**所以 TSF 会跳过任何没有声明「可以不经 COM 加载」的输入法，而且是静默跳过**：激活调用照样返回成功，DLL 就是不出现。

这个分类此前是**有意不注册**的，理由写着「PiInput 没有实现那些激活契约」。对安全桌面那一项成立，对这一项不成立：不经 COM 的加载走的就是 `DllGetClassObject`，那本来就是这个 DLL 的入口，而且只构造一个类工厂。输入路径上没有任何 COM 对象创建。

专门写了个 MTA 进程逐个激活各家配置来定位，每次只激活一个以排除顺序因素：搜狗、微信输入法、小狼毫全部加载，只有 PiInput 不加载，而那三家都声明了这个分类。注册之后同一个探针里 PiInput 也加载了。

安全桌面那一项仍然不注册，并把理由写进了门禁——注册它会让 PiInput 出现在 UAC 提示框和锁屏上。

## Shift+Insert 会切换中英文

终端里用 Shift+Insert 粘贴，一按就切模式。**Shift+Delete 剪切、Shift+方向键选中文本、Shift+Home/End 也一样** —— 凡是「输入法不接管的键」配 Shift 都会误触。

切换状态机靠按键回调得知「Shift 是当修饰键用的」，而那个回调**只对被接管的键触发**。Insert 不接管，状态机就不知道 Shift 按着时还按了别的键，松手时当成单击。

两个按键回调谁都看不全：MobaXterm 每个键都先问、只交出接管的；Chrome 完全相反，一次都不问、直接交出全部。所以观测点补在了「询问」那个回调里，用一个只记录、无返回值的方法——从类型上就不可能触发切换，重复调用与调用一次等效。

## 不在本版修复范围内的

**YeImageViewer 里打不出中文，是那个程序自己禁用了输入法**（`ImmDisableIME`）。实测在调用它之后，搜狗、微信输入法、小狼毫、PiInput、甚至语音输入全部无法加载。这不是输入法能绕开的，修复要在那个程序里做。
