## 已确认的行为

- **数字键没有被改动。** 没有合成串时 `should_eat_key` 对数字仍返回 false，数字直接透传。建议是叠在上面的一层：它只在数字已经落进文档之后出现，且只插入后缀。没录入数字常用语的用户，行为与 v0.8.6 逐字节相同。
- **协议新增被收窄到一种报文。** v7 只随 `digit_run` 发出，普通按键继续走 v5。这一条是「数字建议不可能拖垮打字」的全部理由：升级后旧 Host 仍在运行时，它拒收的只有建议，不是按键。
- **安装器向导前三页已实机走通**：欢迎、安全提示、安装位置三页逐页截图核对，文案完整未被裁切，路径分行正确，按钮状态正确。进度页与完成页在本机安装时验证。

## 沿用自前版的已知问题

- `IS_PRIVATE` 字段能输入但仍会被学习。正确做法需要协议新增字段，已记入待办，未半做。
- MobaXterm 里候选框不跟随光标，原理上做不到。
- 有些程序调用 `ImmDisableIME` 主动禁用输入法（如 YeImageViewer），那之后任何输入法都无法加载。

## 本版引入的已知限制

- **中文常用语的自动触发码依赖词库反查。** 生僻字查不到读音时推导会在那个字处停下；推不出两个字母时该行需要手工填触发码，设置界面在触发码列直接显示会用什么触发，不会让用户猜。
- **数字建议只对没填触发码的那些行生效。** 这既是默认行为也是开关：留空就按前几位触发，填了触发码就只认触发码。否则存了证件号之后，在任何地方打出它开头那几位都会把号码弹到屏幕上，而用户没有关掉它的办法。
