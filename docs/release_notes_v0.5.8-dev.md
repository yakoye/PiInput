# PiInput v0.5.8-dev 版本说明

本版不增加新功能，专门修复连续输入时周期性卡顿的重大问题。

## 根因

拼音核心和真实二进制词库查询本身并不慢：小鹤查询通常是几十微秒，全拼长词查询低于 1 毫秒。卡顿发生在 Windows 输入链路：Host 每处理完一个按键连接以后，才创建下一条命名管道。快速输入时，下一按键会在入口尚未建立的短暂窗口内轮询等待，周期性产生约 15～20 毫秒停顿；一串按键和候选定位请求排队后，就会表现为明显的“一卡一卡”。

## 修复

- Host 在处理当前请求时，提前建立一个等待下一请求的管道实例；
- 下一按键可以立即连接，不再等待上一连接完全清理后重新创建入口；
- 当前响应仍在断开前确认已经被客户端读取，避免快速连续请求偶发丢包；
- 不修改词库内容、候选排序、用户学习和输入热路径数据结构。

## 新增性能门禁

- 80 次连续 Host 请求：P95 必须小于 5 ms；
- 真实词库逐键输入：P95 必须小于 10 ms，单次最大值小于 20 ms；
- 覆盖小鹤输入 `womfmktm`（我们明天）、`qunali`（去哪里）、`vegeui`（这个是）、`nijtde`（你觉得）、`zfyh`（怎样）；
- 同一门禁连续执行五轮，防止偶然通过；
- 同时覆盖 32 位 Windows 测试启动器和 64 位正常运行路径。

## 保持不变

- 词库继续由常驻 `PiInputHost.exe` 统一加载，各应用不重复加载大词库；
- 默认小鹤双拼，可在设置中切换全拼；
- `Space` 上屏、`=`/`-` 分行浏览、单独 `Shift` 切换中英文；
- 纯离线、无 AI、无语音、无广告、无输入内容上传。
