# 三个长文本打字测试（v0.8.2）

v0.8.2 继续执行三组真实文本逐键回放、段落输入、结构化语料和逐键延迟门禁，结果与 v0.8.1 一致，无回归。

本版没有触碰解码、词库或候选排序，改的全是按键投递与候选框定位，因此长文本结果预期不变。执行仍是必需的：本版在按键路径上新增了三个追踪点，需要确认追踪关闭时它们没有渗入延迟。

## 本版必须复验的项

- **`piinput-keystroke-latency` 与 `piinput-typing-latency` 未因新增追踪点退化。** `key_offered` 在每次 `OnTestKeyDown` 都会跑一次 `snprintf`，`key_down` 与 `key_up` 各一次，即使追踪关闭也如此（与既有的 `key_dispatch` 同一形态）。这是本版唯一进入按键热路径的改动。
- **补做机制在正常应用中不得触发。** `key_down_recovered` 在行为正常的程序里应恒为 0。长文本回放全程跑完后，追踪里出现任何一次补做都说明状态机判断有误。
- **候选框顶部那一行默认开启，不影响上屏内容。** 该行只是绘制，不参与提交；长文本回放的输出应与 v0.8.1 逐字节一致。

## 真实应用手工测试

必须使用验证记录中的同一 build ID，不能沿用 v0.8.1 的进程或安装结果。**每个受测程序都要重启**——Shim 是 DLL，不重启就还是旧版本。

1. **终端退格**：MobaXterm 中文模式打 `hdui`，连按 Backspace，应逐个删除且无延迟感。
2. **正常应用退格**：Notepad++ 或记事本做同样操作，行为应与 v0.8.1 完全一致。
3. **候选框不跟鼠标**：MobaXterm 中打出候选后移动鼠标到屏幕另一处（含另一个显示器），候选框不应跟着走。
4. **候选框落点**：MobaXterm 中候选框应稳定出现在终端输入区附近，不在屏幕角落，且每个词的位置一致。
5. **合成串开关**：设置 → 候选窗 → 取消「候选框顶部显示正在打的字母」，候选框应回到单行；重新勾选恢复两行。
6. **升级不中断已开程序**：装上本版后，**不重启**任何已打开的程序，在其中任选一个继续打字，应正常工作。这是协议兼容性的实机检验。
