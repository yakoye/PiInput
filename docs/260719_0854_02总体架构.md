# 总体架构

## 分层结构

```text
┌────────────────────────────────────────────┐
│ 平台接入层                                  │
│ Windows TSF / macOS / Android / iOS        │
└─────────────────────┬──────────────────────┘
                      │ C ABI
┌─────────────────────▼──────────────────────┐
│ C++20 输入法核心 ime_core                  │
│                                            │
│ 输入方案  拼音切分  词图  句子解码          │
│ 候选排序  用户学习  标点  符号搜索           │
└─────────────────────┬──────────────────────┘
                      │
┌─────────────────────▼──────────────────────┐
│ 数据层                                      │
│ base.lex / domain.lex / symbols.lex        │
│ user.db / change-log / settings            │
└────────────────────────────────────────────┘
```

## 核心模块

### Input Schema

将按键编码转换成标准拼音：

```text
全拼输入 ─┐
小鹤双拼 ─┤
微软双拼 ─┤→ 标准拼音音节序列
自然码   ─┤
自定义   ─┘
```

方案接口需要支持：

- 完整解析；
- 前缀合法性；
- 不完整输入；
- 零声母规则；
- 输入光标映射；
- 方案切换；
- 配置冲突检查。

### Pinyin Segmenter

处理全拼无分隔字符串的多种切分，例如：

```text
xian → xi'an / xian
```

输出音节图而不是过早只保留一种切分。

### Lexicon

- 静态词库只读；
- 使用内存映射；
- 按标准拼音索引；
- 字符串池去重；
- 通用词库与专业词库独立权重；
- 用户词库单独维护。

### Decoder

根据音节图和词库构建词图，并使用动态规划或受限 Beam Search 输出前若干条路径。

第一阶段评分来源：

- 基础词频；
- 词库层级；
- 词长奖励；
- 完整匹配奖励；
- 用户频率；
- 最近使用衰减；
- 本地二元搭配；
- 专业冷门词惩罚；
- 模糊匹配惩罚。

### Candidate Snapshot

候选列表一旦显示，生成不可变快照：

```text
session_id
generation
composition_revision
candidate_id
candidate_text
candidate_score
```

用户选词时传递 `generation + candidate_id`。后台数据变化只影响下一次按键后的新 generation。

### User Learning

用户学习不能阻塞按键：

```text
选词事件 → 内存增量 → 异步批量提交 → 持久化
```

需要支持：

- 置顶；
- 屏蔽；
- 删除误学；
- 最近使用；
- 频率衰减；
- 应用级轻量权重；
- 同步变更日志。

## Windows 进程结构

正式版本建议：

```text
PiInputTSF.dll
  ├─ TSF/COM 接入
  ├─ 组合文本
  ├─ 按键过滤
  └─ 与引擎 IPC

PiInputEngine.exe
  ├─ 核心引擎
  ├─ 词库内存映射
  ├─ 解码和排序
  └─ 用户数据缓存

PiInputConfig.exe
  ├─ 输入方案
  ├─ 词库导入
  ├─ 标点与符号
  └─ 用户数据管理

PiInputSync.exe（后期可选）
  ├─ 配对
  ├─ 加密同步
  └─ 剪贴板
```

TSF DLL 必须尽量薄，不能在每个宿主应用进程中加载完整词库、SQLite 或网络组件。
