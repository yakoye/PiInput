## 本版修的是一个发布缺陷

v0.9.2 的配色开关在任何打开过设置窗口的机器上都是零候选。成因与修法见 `docs/release_notes_v0.9.3.md`。

**这个缺陷是怎么被发现的，值得记下来**：它不是测试发现的，是本机安装之后顺手用夹具打了一次 `zt`，看到 `candidates=0`。单元测试当时全绿——因为它们用的是 `default_settings()`，那里没有被保存过的 `count=`。**全新环境下的测试看不见只在升级路径上出现的缺陷。**

## 自动验证

- 干净 Release 构建，全量 CTest 通过（69 项，0 失败）。
- 构建标识形如 `0.9.3+<发布提交短哈希>`，工作树干净。精确值与包 SHA-256 记在候选目录的 `BUILD-ID.txt` 与 GitHub Release 正文里。

### 本版新增的测试

- `piinput-host-session-tests`：**把 `custom_shortcuts` 清空**之后打 `zt`，三挡仍须出现在候选 2–4。清空是对「保存过的 count 截断了表」最直接的模拟。
- `piinput-settings-tests`：默认快捷表里不许出现任何 `theme_` 目标；`is_theme_shortcut` 覆盖 `zt`/`zhut`/`zhuti`/`vut`/`vuti` 五种拼法，且 `zhu`、`z` 这类裸前缀不命中（否则会盖住普通词）；三挡位置严格递增。
- 源码门禁：`default_custom_shortcuts()` 的函数体里不许出现 `theme_`，并在失败信息里写明原因——下一个想把内置项塞进用户表的人会先读到它。

## 实机核对

- **用用户真实的 `settings.ini`（含 `count=6`）起隔离宿主**：`zt` 给出 `zt` / 🌗跟随系统 / ☀浅色 / 🌙暗色，顺序正确；`fh` 仍为 `Ω符号`，原有工具未受影响。
- 暗色与浅色渲染、工具与日期入口位置，沿用 v0.9.2 的核对结果（这一版未触及绘制与位置逻辑）。

## 尚未验证（阻止转为正式版）

- Host 8 小时长稳、TSF/App 长稳、P0 真实宿主矩阵未运行。
- 中文模式英文候选未实机使用（默认关闭，本版未触及）。
- **飞书里的句号行为仍未在飞书上实测**（本机未安装）。追踪字段 `smart_context_source=committed_tail` 已备好。
- **无可信 Authenticode 签名与 RFC 3161 时间戳。**

## 本版引入的已知限制

- **配色三挡的位置和图标不可编辑**，因为它们已不在用户表里。这是换来「老用户也能用上」的代价，与日期时间入口的处境相同。
- **「新增内置快捷行到不了老用户」没有根治**，只是让配色绕开了它。下一次真要往用户表加内置行时这个坑还在，已记入 `docs/待办事项.md`。

## 结论

发布缺陷已修，并用真实的旧配置验证过。自动回归完整通过，新增测试与门禁直接针对这个升级路径。

**v0.9.2 不应继续分发**：它的新功能对老用户无效。长稳、宿主矩阵、签名门禁未完成，本版同样只能作为候选版。
