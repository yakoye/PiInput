1. 切换到 PiInput

按 Win + 空格 在已安装的输入法之间轮换，直到任务栏右下角出现 π 标记。

刚装完，已经打开的程序里用不了，这是正常的。 输入法组件是一个 DLL，程序不重启就还是加载着旧版本或者根本没加载。把要用的程序关掉重开一次即可——不需要重启电脑，也不需要重新登录。

怎么确认真的切过去了

任务栏的输入法指示器会显示 中 或 英。看不到指示器时，先确认光标在一个可以输入文字的地方——没有输入焦点时 Windows 不显示它。

Shift 只在单独按下时切换中英文。 Shift+Insert 粘贴、Shift+Delete 剪切、Shift+方向键选择文本，这些组合都不会误触切换。

候选框的位置

候选框跟随光标。终端类程序是例外：MobaXterm 这类程序不向系统报告插入点位置，它维护的不是文本文档而是自己绘制的字符网格，没有任何接口能问出光标在第几行第几列。那里的候选框会稳定地落在输入区附近，但不跟随——这是原理上的限制，不是缺陷。

3. 标点符号

中文标点模式下，紧跟在字母或数字后面的第一个句号是 ASCII 句点，再按一次才是中文句号。冒号同理。

输入得到说明
0.80.8版本号、小数照常
geek 然后句号geek.英文单词后是 ASCII 句点
再按一次句号geek.。第二次才是中文句号
中文后按句号你好。中文行文不受影响，一次就对
apple-bookapple-book横杠在合成串里也能正常输入

要长期使用英文标点，在设置的「标点符号」页把模式改成英文即可。

4. 常用语：地址、证件号、电话

把常用的长文本存起来，打几个字母就能从候选框取出来。在设置 → 常用语里添加。

内容触发码怎么用
北京市海淀区xx街道xx小区dzjl打 dzjl，候选框第 2 位就是它
622322199005012219sfz打 sfz 取用
15801616544留空打前 3 位 158，按 Tab 补齐剩下的

触发码留空会怎样

留空就按内容自动推导，规则取决于内容的第一个字符：

  • 中文开头 → 首字拼音声母。北京市海淀区… 可用 bj、bjs、bjsh 触发。
  • 拉丁字母开头 → 它自己的前几个字母。github.com/… 可用 gi、git、gith 触发。
  • 数字开头 → 打出前 3 位后候选框给出补全，按 Tab 接受。
数字键不会被候选框接管。 数字照常直接输入，建议只是叠在上面的一层提示；按 Tab 才会补齐，按其他任何键都是正常输入。所以存了电话号码，也不影响你手打任何数字。

候选框里显示的是内容本身（过长会截短）。同时存了几条长内容而分不清时，给它们各填一个备注名，候选框就显示备注名。

常用语不会进入学习记录——它不是一条「拼音—词」事实，学进去会污染词库并产生来源不明的重复候选。

6. 装不上 / 打不出字

安装器被 Windows 拦下

PiInput 目前没有代码签名证书，所以在开启了防护的机器上会被拦。这不是程序有问题，是 Windows 无法验证发布者。

  • SmartScreen（弹窗标题「Windows 已保护你的电脑」）：点「更多信息」→「仍要运行」。
  • 智能应用控制（弹窗标题「已阻止可能不安全的应用」）：强制模式下不提供放行入口，只能到「设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 智能应用控制」里关闭。这个操作不可逆，关掉之后除非重装系统无法重新开启，请自行权衡。

弹窗上的「正常」按钮不是放行，它只是关掉弹窗，应用依旧不会运行。改名、换目录、用命令行启动都无效。

图标还在，但一个字也打不出来

这种形态通常是 Defender 把引擎进程当成木马隔离了（常见判定是 Trojan:Win32/Wacatac.C!ml，属于无签名可执行文件的通用误报）。输入法的 shim 是 DLL，不会被查杀，所以语言栏照常显示，但按键送不到引擎。

先跑诊断确认：

%LOCALAPPDATA%\PiInput\bin\piinput-diagnostics.exe

如果 host_exists 是 false 而 shim_exists 是 true，就是这个问题。恢复办法：以管理员身份打开终端，为安装目录加一条排除项，然后重新运行一次安装器。

Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\PiInput\bin"

加排除项意味着 Defender 不再扫描该目录，请确认你了解这个取舍。

某个程序里打不出中文，别的程序正常

  • 先把那个程序完全退出重开——输入法是 DLL，程序不重启就加载不到。
  • 密码框和 PIN 输入框会主动拒绝转换，这是刻意的。
  • 少数程序调用了 ImmDisableIME 主动禁用输入法，那之后 Windows 不会把任何输入法加载进该进程——换哪个输入法都一样，需要那个程序自己改。

还要再深一层

在临时目录（%TEMP%）放一个空文件开启对应日志，排查完请删掉：

放这个文件得到看什么
piinput-key-trace.onpiinput-key-trace-<pid>.csv每个按键的去向：应用交没交出来、有没有送达
