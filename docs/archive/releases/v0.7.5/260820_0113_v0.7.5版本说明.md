# PiInput v0.7.5 版本说明

本版给全拼加超级简拼。双拼不受影响，卸载与安装的改动沿用 v0.7.4。

## 简拼

全拼下每个音节只打声母就能出词，三种写法都支持：

```text
声母简拼      zhly     →  张靓颖
首字母简拼    zly      →  张靓颖
简拼全拼混合  srf      →  输入法
              sruf     →  输入法
              shrfa    →  输入法
              shurf    →  输入法
```

`zh/ch/sh` 自动按首字母归约，所以 `zhly` 和 `zly` 给出完全相同的候选，`zhshjsh` 和 `zsjs` 也一样。这不是模糊音——即使不开模糊音，简拼照样按首字母匹配。

实测：

```text
zsjs     自身建设 在世界上 知识竞赛 指示精神 在设计上 总设计师
zhshjsh  自身建设 在世界上 知识竞赛 指示精神 在设计上 总设计师
srf      输入法 受让方 双人房 杀人犯 首日封 杀人蜂
wlj      为了将 我了解 王老吉 无连接 崴了脚 外连接
```

## 打了几个声母就出几个字的词

简拼只匹配音节数与声母数相同的词。打 `srf` 三个声母，出的是三字词；不会把「输入法软件」「输入法论坛」这些更长的词塞进来——那是在猜用户没打的字。这和未完成音节补全遵循同一条规则。

正因如此，`sruf` 的首选是「输入法」而不是词频高得多的「收入分配」：后者是四个音节，用户只打了三个。

## 不会干扰正常全拼

简拼只在**输入完全无法读作普通拼音**时才启用。

`wang` 是一个合法音节，虽然它也能读成 w+a+n+g 四个声母，但那样会让「王」被一堆四字词埋掉。所以只要输入有完整的拼音读法，简拼就不参与。`zsjs`、`wlj`、`sruf` 这些简拼真正存在的意义所在，本来就没有全拼读法。

回归确认：`wang`→王、`cao`→草、`shuang`→双、`nihao`→你好、`kadun`→卡顿，全部与本版之前一致。

## 开关

```ini
[pinyin]
simplified_pinyin=true
```

默认开启。关掉之后完全回到 v0.7.4 的行为，且不会付出任何代价——简拼索引是第一次用到时才建的，关掉就永远不建。

## 已知的落差

搜狗的简拼首选往往比这里更准，因为它有语言模型。PiInput 是纯离线、无 AI，简拼排序只有词频。

体现在：`zsjs` 的「指示精神」排第 4 而不是第 1，`zly` 的「张靓颖」排第 5。词都在，位置不如搜狗靠前。这是取舍，不是实现技巧能绕开的。

用得多了用户学习会把常用的顶上去。

## 性能

简拼索引在第一次简拼查询时构建，约 300 毫秒，只发生一次。不用简拼的用户完全不付这个成本，词库格式也没有改动——旧词库直接可用，不需要重新编译。

逐键延迟无变化：`key_p95_us` 201、`key_max_us` 272。
