# PiInput v0.7.13 安装、使用与测试

## 安装与版本确认

完整解压发布包，双击根目录的 `PiInput-Install.exe`。升级后重新打开要验证的应用，再用 `Win+Space` 切换到 PiInput。

执行：

```powershell
& "$env:LOCALAPPDATA\PiInput\bin\PiInputHost.exe" --version
& "$env:LOCALAPPDATA\PiInput\bin\PiInputHost.exe" --build-id
```

版本应为 `0.7.13`，构建标识应以 `0.7.13+` 开头。

## 智能标点验收

切到中文状态，在 Notepad++、记事本和浏览器普通文本框分别验证：

| 输入过程 | 预期结果 |
| --- | --- |
| `1` 后按句点 | `1.` |
| 中文状态输入 `v1.0.1.` | `v1.0.1.`，最后一点立即保持 ASCII |
| 中文状态输入 `v1.0.1..` | `v1.0.1.。`，第二点为中文句号 |
| 中文正文中按句点 | `。` |
| `12`、冒号、`23` | `12:23` |
| 中文正文中按冒号 | `：` |
| `2`、斜杠、`3` | `2/3` |
| 中文正文中按反斜杠 | `、` |

数字后的第一下句点立即保持 ASCII `.`，不会因后续输入文字被改写；紧接着第二下句点输出中文 `。`。验收时 `1.文本` 必须保持原样，`1..` 必须得到 `1.。`；出现 `1。文本` 判为失败。

设置页“标点符号”中还提供“中文时使用英文标点”。选中后，输入语言和候选仍为中文，但所有物理标点键都输出 ASCII，且不再进入句号、冒号或逗号的智能临时状态。至少验证 `wo` 仍出现“我”，并依次输入 `.,:;/?[]{}\\|\"'`，确认逐字符原样上屏；选回“中文标点”后恢复上表规则。

## 专业词与大词库验收

运行发布包内的 `PiInput-Test.exe`，并确认本版结构化语料报告中的 313 条用例全部通过、13 个专业词缺口为零。Host 应从映射词库加载，健康信息中的词库加载方式应为内存映射，而不是整文件复制到私有堆。

## 日期与时间快捷输入

全拼方案下输入 `sj`、`shij` 或 `shijian`，候选中应出现“🕗时间”；输入 `riq` 或 `riqi`，候选中应出现“📅日期”。选中入口后展开竖排格式列表，再选择一项即可上屏。时间包含纯时间及多种日期时间格式；日期包含数字、中文和农历格式。

## 安装包闭环

正式发布门禁必须同时满足：

- 压缩包 SHA-256 与同名 sidecar 一致；
- 包内没有源码、构建文件、脚本、PDB 或 source map；
- 所有 EXE/DLL 的 Authenticode 签名有效；
- 静默安装、同版本覆盖安装、卸载，以及最终按需重装全部成功；
- 安装后 Host 的版本与构建标识和发布包一致。
- HKCU 与 64 位 HKLM 的 `InprocServer32` 都指向 `%ProgramFiles%\PiInput\Runtime\Shim\PiInputTSF.dll`，其 SHA-256 与包内 DLL 一致；Windows 搜索等打包系统宿主依赖这个受保护机器入口加载。

## Windows 搜索

安装后重新打开 Windows 搜索，通过 `Win+Space` 选择 PiInput，输入 `zhongwen123`。首个字母后系统集成候选行必须出现，空格应提交“中文”，随后 `123` 完整上屏。验收时记录 SearchHost PID，并确认其加载模块中包含本次安装路径的 `PiInputTSF.dll`；只看到输入法名称、只可提交最终文本、或候选始终不显示，都不算通过。自动回归必须覆盖 `ITfCandidateListUIElementBehavior` 的候选字符串/分页/选择/取消、搜索框 integration style，以及宿主接管时协议 v5 抑制 Host 外部窗；普通桌面程序另行核对 popup 的 `GW_OWNER`。

## 长时间稳定性

8 小时测试期间持续记录 Host 的私有内存、工作集、句柄数、线程数和请求计数。判定以曲线是否在预热后稳定为准；单次起点/终点差值不能替代完整曲线。异常时保留 CSV、Host 日志、构建标识和复现输入序列。
