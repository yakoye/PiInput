# PiInput v0.6.5-dev 版本说明

本版处理四项用户反馈，不改动候选排序权重。

## 一、分段取字选中一个字后停在原地

打 `meilie` 展开进入分段取字，选「每」之后候选回到了整词行（没列/没咧/每列…），必须再翻一次才能选下一个字。

原因是上一版加入「保留已见整词行」之后，暂存一个字仍然执行 `advance_generation(true)` 把网格重置到索引 0，而索引 0 现在是保留的整词，不再是逐字候选。

修复：暂存成功且还有未定音节时，选择位置直接落到追加段的第一个候选，也就是刚空出来的那个音节。进入分段取字和暂存一个字现在走同一段定位逻辑。

## 二、候选框默认五行

`visible_rows` 默认由 3 改为 5，同步更新内置默认设置、原生安装器写入的默认 `settings.ini`、开发安装脚本与页大小脚本。

已有的 `settings.ini` 会覆盖默认值：文件里写着 `visible_rows=3` 的机器需要改成 5 才能看到五行。

## 三、候选编号位固定预留

此前只有活动行按 `1. 2. 3.` 绘制编号，其它行的文字直接从格子左边开始，于是上下两行文字对不齐。

修复：每一列都按编号宽度预留位置，列宽也按含编号的文字测量；编号只在活动行绘制，但所有行的候选文字都从同一横坐标开始。

## 四、标点后再输入的延迟

Host 侧实测：空载往返 P95 199 微秒，中文—标点—中文链路 P95 1281 微秒，普通词逐键 P95 1463 微秒——标点边界在 Host 上并不比普通按键慢，剩余延迟在应用侧的 TSF 路径。

本版去掉其中一处真实浪费：候选窗每次定位都会创建设备上下文并逐项测量文字宽度，而每个按键要定位两次（暂存快照一次、真实光标一次）。窗口几何已锁定且候选内容未变化时，第二次定位只可能得出同一个矩形，现在直接复用，不再测量。默认五行后每次测量最多 30 项，这一项的收益随行数增加。

## 五、提交之后第一个字母的候选栏要等一个来回

这是「打完标点再打字卡顿」的直接原因，问题在我们自己的候选栏逻辑里。

词中间打字时，`CandidatePresenterModel::stage()` 的 `reuse_caret` 为真，Host 收到按键回复就立刻用上一次的光标位置显示候选栏，与应用侧的 TSF 编辑并行，所以感觉不到延迟。

但提交（标点、空格上屏都算）时 `raw` 为空，Host 调 `presenter_->hide()`，它把 `focused_session_` 清零、`caret_available_` 置假。于是下一个字母的 `stage()` 里 `reuse_caret` 为假，`current_caret()` 返回空，**直接返回、不显示候选栏**。候选栏要等到 Shim 走完「新建组合 → 写文字 → `GetTextExt` 问应用要插入点 → 管道发回 Host」才第一次出现，而 `GetTextExt` 打在刚建好的组合上，应用必须现排版。

修复：提交时保留上一次的真实光标作为下一次组合的**临时锚点**，第一个字母立刻显示候选栏；该锚点标记为「非真实光标锁定」，因此第一个真实光标到达时会按既有规则**校正一次**，之后不再跟随每键抖动。

代价是候选栏会先出现在上一个词末尾、真实光标回来后向右挪一次。这与早期版本消除的「从鼠标位置闪现再跳动」不同：同一行内、距离是刚提交那几个字的宽度，且只校正一次。

## 六、提交之后的按键被挡在异步 TSF 编辑后面

用户在 v0.6.4 上录屏复现：打完标点继续输入仍然卡。逐帧比对确认候选栏与组合区文字已经同步（相差 1～2 帧），但「我们，」提交后的第一个字母 `n` 从未单独显示过，`ni` 两个字母在同一帧一起出现；而词中间的 `niv` → `nivi` 是逐帧单独出现的。也就是说，慢的是**组合区文字本身**，不是候选栏。

根因在 `FinalEditKeyQueue::should_queue()`：只要 `final_edit_pending_` 为真就拦下**所有**按键。该标志从提交回复被处理开始，一直保持到那次 TSF 编辑**真正完成**为止。Notepad++（Scintilla）经常拒绝同步编辑会话——这个代码库里整套异步回退正是为它写的——一旦走异步，提交的编辑要等到应用下一轮消息循环才执行，其间打下的每个按键都被排队，然后一个一个放行，每个一次完整往返。

而普通汉字字母根本不需要等：它的回复是 `update`，其 TSF 编辑已经由 `DeferredUpdateQueue` 正确排在待完成的提交之后。

修复：新增 `key_may_begin_final_edit(kind, english_mode)`，只有回复可能再次提交或取消的按键（标点、空格、回车、Esc、数字选字、中英切换、退格、删除，以及英文直输下的字母）才需要等待挂起的提交；普通汉字字母和候选导航立即放行，其引擎工作与应用侧的挂起编辑并行进行。队列非空时仍然全部排队以保持顺序，避免后来的按键插到前面。

## 验证重点

1. 打 `meilie` 按 `=`，选「每」，候选应立即切到 `lie` 的字表；
2. 候选框展开后应为五行；
3. 非活动行的候选文字应与编号行对齐；
4. 连续输入「中文符号中文符号中文」，观察标点后继续输入是否跟手；
5. 「我，」之后打 `ta`、「你好吗？」之后打 `wo`，候选栏应当立刻出现；
6. 打完标点后连续快速输入，第一个字母应当立刻出现，而不是和第二个字母一起蹦出来。
