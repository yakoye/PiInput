# PiInput v0.7.2 版本说明

## 打一串词能拼出整句

整串输入全部解码、但词库里没有任何一条能覆盖它时，现在会把词库里的真实多字词拼接成覆盖全部音节的候选，排在最前面。

小鹤双拼实测：

```text
bwffyshu     →  备份用户    （备份 + 用户）
xpzduuru     →  卸载输入    （卸载 + 输入）
dnyslmffxi   →  调用链分析  （调用链 + 分析）
```

以前这三种输入只能给出覆盖前两个音节的「备份」「卸载」「调用」，用户已经把整串打完了，却要分好几次上屏。

拼接有三条硬约束：

- **只用真实多字词，单字不得作为衔接。** 全是单字的输入不会被拼成句子，这一点和以前一致。
- **最多两条。** 保证真实词条不会被挤出首行。
- **单条真实词库条目排在同样覆盖的拼接候选之前。** `zhonghuarenmin` 首位仍然是词库里的「中华人民」，不是「种花 + 人民」。

同一个首词下比较时，先看最弱的那一环，再看总词频，所以「备份用户」排在「备份拥护」前面。

## 全拼结尾带半个音节不再漏词

全拼下凡是结尾带未完成音节的输入，候选都是错的：

```text
nihaob      修复前：你 尼 泥 逆      修复后：你好 拟好 你 尼
xihuanb     修复前：西湖 洗护 潟湖   修复后：喜欢表 喜欢 西环
woxianzaib  修复前：我系 我洗 我喜   修复后：我现在 我先 我县
zhongguor   修复前：无候选           修复后：中国人 中国日 中国
beijingd    修复前：无候选           修复后：北京的 背景的 北京东
```

根因在前缀展开的排序：`sort_and_limit` 把「完整音节数多」当成更优，压过了分词器自己算出的评分。`woxianzaib` 因此选中 `wo'xi'an'zai`（4 个音节）而不是 `wo'xian'zai`（3 个），后续查词全部走错分支。分词器本身已经「偏好更少更长的音节」并把这个偏好算进了评分，排序现在改为先看未解析字母数（哪个解释了更多用户实际敲的内容），再信分词器的评分。

小鹤双拼不受这个缺陷影响，v0.7.1 的行为逐条复核过，没有回归。

## 安装提示

Shim 会被加载到每个应用进程中。安装完成后必须完全退出并重新打开 Notepad++、浏览器或聊天应用，旧进程不会自动换用新的 DLL。

## 已知边界

- 数字后连续两个点只能得到 `3.。`，得不到 `3..`。第一个点按小数点处理，第二个点回到中文句号，否则数字后面就再也打不出 `。`。
- 组合区显示的是原始字母串，不像搜狗那样按音节插入 `'` 分隔。
