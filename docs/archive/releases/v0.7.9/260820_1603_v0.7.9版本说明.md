# PiInput v0.7.9 版本说明

上一版把「中/英」做成了通知区域图标，位置不对，还多出一个图标。这一版改成和搜狗、微软拼音一样的做法。

## 中/英 和图标现在是一块

它们出现在**任务栏的输入指示器**里，就是微软拼音显示「中 拼」的那个位置：

```text
中  π
```

搜狗、微软拼音、微信输入法都是用 TSF 的语言栏（`ITfLangBarItemButton`）实现的——那些按钮由 Windows 画在输入指示器里，所以看起来是一组。上一版用的 `Shell_NotifyIcon` 是通知区域图标，属于任务栏的另一块地方，两者拼不到一起，结果就是溢出区里两个、任务栏上一个，共三个。

现在通知区域图标已经全部移除，只剩输入指示器里的两个按钮。

「中」和「英」是**文字**，由 Windows 按系统主题绘制：浅色主题黑字，深色主题白字，背景透明，和其他输入法完全一致。这也是不再自己画图标的原因——自己画就得自己处理主题，而且永远差一点。

## 右键菜单

在任意一个按钮上点右键：

```text
中文
小鹤双拼
──────────
符号
设置
──────────
关于 PiInput
帮助与反馈
```

前两项显示当前状态，点击切换。左键单击任意按钮直接切中英。

## 符号直接打开 yesymbol

`yesymbol.exe` 现在**随安装包一起装**，和其他程序放在同一个目录。菜单里点「符号」直接启动它，不需要任何配置。

要用别的路径，在设置窗口「标点符号」页的「托盘符号工具」里填，或者写进 `settings.ini`：

```ini
[general]
symbol_tool=完整路径\yesymbol.exe
```

查找顺序：设置里指定的路径 → 程序目录下的 `yesymbol.exe`。

## 指示器按钮不显示的三个原因（已修）

首个 0.7.9 构建里按钮不显示，三个原因叠在一起，任何一个都足以让按钮被丢掉：

1. **图标资源 ID 写错**：代码用 `1`，实际是 `101`，图标加载失败；
2. **`GetIcon` 在没有图标时返回 `E_FAIL`**：这一步失败，Windows 会丢弃**整个按钮**——所以连只有文字的「中」也一起消失；
3. **`clsidService` 填了 `GUID_NULL`**：Windows 靠它判断按钮属于哪个输入法，填空等于没有归属，指示器不会画。

三处均已修正。这一版还会往 `%TEMP%\piinput-langbar.log` 写几行注册记录（接口是否拿到、按钮是否注册、图标是否加载、Windows 有没有回头查询），文件很小，只在启动和查询时写。

## 验证

完整 CTest 60/60 通过。

设置窗口的回归测试补了一条：运行前先清掉遗留的设置窗口进程。之前它偶发失败，原因是上一次测试留下的窗口还在——第二个实例正确地把那个窗口拉到前台然后退出，看起来却和「窗口打不开」一模一样。
