# PiInput v0.5.5-dev Windows 实机测试记录

测试日期：2026-08-16  
测试系统：Windows 11，简体中文  
安装版本：`0.5.5-20260815-231114-34008`  
测试包：`artifacts/PiInput-v0.5.5-dev-windows-x64.zip`

## 结论

v0.5.5-dev 已安装，TSF Profile 状态为 `registered=yes / enabled=yes / active=yes`。新加载 v0.5.5 DLL 的 Notepad4 和 Word 能完成小鹤双拼、全拼、空格选词、方向键选词、中英文切换、中文标点、符号命令和分段取字等基础流程。

本版仍不满足稳定发布条件，不能宣称“所有软件都可直接使用”。实机测试确认了三个需要先修复的问题：

1. 系统中仍有多个历史版本的 `PiInputTSF.dll` 同时驻留，不同软件实际执行的代码不同；注册表仍指向 v0.5.4，而不是已安装的 v0.5.5。
2. 在设置程序中运行时切换“全拼/小鹤双拼”后，已经打开的 v0.5.5 Word 和 Notepad4 会话会吞掉字母键，不显示组合文本和候选；恢复原方案也不能恢复该会话，重开目标程序后才能恢复。
3. Word 光标靠近窗口底部时，候选框仍向下弹出并被窗口底边裁切，没有自动翻到光标上方。

注册表 `HKCU\\Software\\Classes\\CLSID\\{13EB305F-2DA3-4CF7-8C45-16B016B801B5}\\InprocServer32` 当前仍指向：

```text
C:\Users\color\AppData\Local\PiInput\Runtime\versions\0.5.4-20260815-103202-24164\bin\PiInputTSF.dll
```

这证明当前所谓稳定 Shim 还不是一个真正不变的轻量入口。安装器会尝试替换 `Runtime/Shim/PiInputTSF.dll`；被占用时又退回注册版本目录中的 DLL。已打开的软件继续持有旧 DLL，新软件也可能根据缓存和注册状态加载不同版本。

## 实机通过项

### Notepad4（实际加载 v0.5.5）

- 首次输入 `wo` 能显示“我”，没有观察到 5～10 秒冻结。
- `mktm` 首选“明天”，空格可以上屏。
- `vege / uurufa / hf` 可以依次输入“这个 / 输入法 / 很”。
- `sihx` 的基础第一页未收录“丝滑”；通过分段取字选出“丝 + 滑”后，最终只上屏一次“丝滑”。
- 第一次创建“丝滑”后，再输 `sihx`，“丝滑”进入第一页第 6 位；再次选择后进入第 3 位。
- 用户模型已落盘：`si'hua -> 丝滑`，计数为 2，`user_created=1`。
- `fwihkk` 普通候选优先显示真实词；没有下一页真实词时，第一次 `=` 进入当前未解决位置的分段候选，第二次 `=` 展开多行单字候选。
- `-` 能向上返回，并最终恢复原始 `fwihkk` 候选与首项选中状态。
- `Esc` 能取消组合并删除未上屏字母。
- 全拼模式在重新启动的 Notepad4 中输入 `mingtian`，首选为“明天”。
- 小鹤模式在重新启动的 Notepad4 中输入 `mktm`，首选为“明天”。

### Word（实际加载 v0.5.5）

- `mktm` 首选“明天”，空格上屏。
- `wojtdevegehfhc` 首选“我觉得这个很好”。

- Shift 切到英文后可直接输入 `book_list`，再切回中文。
- 中文、数字和英文混输可以形成：`1．今天很不错记住这个book_list————`。

- 因该进程实际加载 v0.5.4，其候选框偏移和裁切结果不能作为 v0.5.5 验收依据。

## 实机失败项

### 1. 输入方案热更新破坏已有会话

复现步骤：

1. 在已加载 v0.5.5 的 Notepad4、Word 中确认小鹤输入可用。
2. 打开 PiInput 设置，把方案改为“全拼”并应用。
3. 回到原来的 Notepad4、Word，使用物理按键输入 `mingtian`。

实际结果：字母键被吞，没有组合文本、候选或英文直通；Enter 等普通编辑键仍然有效，直接文本写入也有效，因此不是文本框失焦。将设置改回小鹤后，已有会话仍不能恢复。关闭并重开目标程序后，全拼或小鹤又可以正常输入。

期望结果：下一次输入开始时安全重建会话，不能吞键；如果热更新失败，应保留旧方案继续工作，而不是让输入会话失效。

### 2. 多版本 DLL 同时驻留

安装 v0.5.5 后，至少存在 v0.4.6、v0.4.8、v0.4.9、v0.5.4、v0.5.5 五代 DLL。用户无法判断某个软件究竟使用哪套行为，也不能通过一次安装让所有新窗口稳定进入同一个实现。

期望结果：真正固定、版本不变、体积很小的 TSF 入口只负责协议和 IPC；所有词库、排序、候选与设置逻辑位于可独立重启的 Host。入口 DLL 不应每版替换，也不应在共享冲突时重新注册到版本目录。

### 3. 底边候选框未翻转

在 Word 中把插入点移动到窗口底部后输入 `mktm`，候选框继续向下展开，底部被状态栏/窗口边界裁切。

期望结果：优先使用 TSF 文本插入点矩形；下方空间不足时翻到插入点上方，并在当前显示器工作区内完成八向边界约束。

### 4. 基础词库缺少“丝滑”

`sihx` 的第一页没有“丝滑”，需要分段选字。用户学习流程能够建立和提升该词，但基础词库覆盖仍需改善。修复不能靠只补“丝滑”一个固定词，应通过通用词库质量、来源权重和缺词回归集统一解决。

## 未完成的应用测试

- Chrome：当前 Codex 的 Chrome 控制连接不可用，不能按浏览器专用测试要求执行可信的 Chrome 自动化。
- Codex/ChatGPT：自动化工具明确禁止操控当前 Codex/ChatGPT 窗口，需用户手工验证。
- Notepad++ v0.5.5：现有进程加载 v0.5.4，且含用户打开的标签页，本轮没有强制关闭。
- 候选右键“固定首位/删除该词”：候选窗属于独立 `PiInputHost.exe`，当前实机控制接口不能把右键可靠投递给该跨进程瞬态窗口，本轮未给出通过结论。

## 下一版硬性验收门槛

1. 安装后注册表永远指向同一个不可变入口 DLL；升级不能再让新旧程序随机加载不同业务实现。
2. Host 可独立升级、重启和回退，已打开应用不需要全部退出。
3. 全拼和小鹤设置切换后，Notepad4、Notepad++、Word 的当前会话都不能吞键。
4. 候选框通过上、下、左、右及四角共八向边界测试；底边必须向上翻转，多显示器不能跨屏。
5. 新进程首次输入不得出现 5 秒以上等待；热查询与真实按键延迟需由进程内计时记录，不能用截图自动化总耗时冒充产品延迟。
6. `= / - / Space / Enter / Esc / Shift / 上下左右` 在三个编辑器中逐项真实验证。
7. 中英混排、中文标点、`;;f / ``f / ;;h / ;;u`、单反引号和三个反引号分别验证。
8. 只有全部门槛通过，才发布下一版安装包。

## 安装与使用说明

本轮测试时 v0.5.5 已经安装，无需重复安装。若重新安装测试包：

1. 解压 `PiInput-v0.5.5-dev-windows-x64.zip`。
2. 双击 `PiInput-Install.exe`，在 Windows 管理员确认中选择“是”。
3. 通过 `Win + Space` 选择“PiInput 中文输入法（开发版）”。
4. 默认方案已恢复为小鹤双拼；`mktm` 应出现“明天”，空格确认。
5. 当前版本切换全拼/小鹤后必须重开目标程序才能继续输入，这是已确认缺陷，不是正常设计。

在上述三个核心缺陷修复前，不建议把 v0.5.5 发给其他用户。
