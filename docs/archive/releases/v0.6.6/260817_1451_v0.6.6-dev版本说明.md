# PiInput v0.6.6-dev 版本说明

本版只修两个问题，都是用户在真实使用中报告的，不含任何新功能。

## 1. 粘贴的内容不再被删除（数据丢失，最高优先级）

**现象**：在 Claude、Codex 这类空文本框里粘贴一段内容，紧接着打字，粘贴的内容被整段删除。

**根因**：`TextService::OnCompositionTerminated` 在被应用终止组合时，对组合范围无条件执行了清空：

```cpp
(void)terminated_range->SetText(edit_cookie, 0U, L"", 0L);
```

这行是 v0.5.4 加的，本意是「用户点到别处时，不要让编辑器把没上屏的生拼音留成正文」。问题在于它假设那个 `ITfRange` 一定还指向输入法自己写的拼音。基于 contenteditable 的 Web 编辑器在粘贴后会重建整个文档节点并顺带终止组合，这时候这个范围已经映射到用户刚粘贴的文字上了，于是被当成拼音清掉。空文本框最容易触发，因为粘贴之后立刻打字，组合才刚建立。

**修复**：只擦除输入法确实写进去的那段文字。

```cpp
if (range_holds_exactly(terminated_range, edit_cookie,
        utf8_to_wide_local(mirror_.composition_text()))) {
    (void)terminated_range->SetText(edit_cookie, 0U, L"", 0L);
}
```

`range_holds_exactly()` 用 `ITfRange::GetText` 故意多读一个字符，再与 `CompositionMirror` 里已确认的组合文本逐字比较：

- 完全一致 → 清空，保留 v0.5.4 的原有行为；
- 范围更长（多出字符）→ 不动，说明应用已把范围重映射到我们不拥有的内容上；
- 范围更短、内容不同、或读取失败 → 一律不动。

取舍是明确的：极端情况下屏幕上残留一个拼音音节，远好于删掉用户的粘贴内容。

新增 Windows 源码门禁，禁止这行清空重新变回无条件执行。

## 2. 中文输入时可以打出 `-`

**现象**：中文模式下打「in-to」，中间的连字符打不出来。

**根因**：`-`（`VK_OEM_MINUS`）在组合状态下被无条件映射成候选行上翻。已经在第一行、没有行可翻时，Host 返回未处理，这个键就成了死键。

**修复**：`-` 只在真的能翻行时才是翻行键。

- Shim 在 `previous_row` 事件上带出字符 `-`；方向键上不带字符；
- Host 在无行可翻、且不处于分段取字时，把它按普通标点处理：先提交当前候选，再送出 `-`，与 `，` `。` 等标点的既有规则完全一致。

需要说明清楚这个键现在的实际行为：组合区有内容时按 `-`，会**先把当前候选上屏**再输出连字符。要打纯 ASCII 的「in-to」，仍然应该用 Shift 切到英文模式。方向键上的行为没有任何变化。

## 3. 候选框弹出位置

**现象**：候选框第一次弹出的位置和插入光标对不上。在满屏文本的 Notepad++ 里随便点一个位置直接打字，问题最明显。

**根因**：Host 在收到第一个按键的候选快照时就要决定把候选框放在哪，但此时真实光标位置还没回来。v0.6.1 为了不让候选框空等一个往返，加了「继承上一个词的光标位置」的快捷路径：

```cpp
} else if (remembered_session_ == session_id && remembered_caret_.has_text_caret) {
    caret_ = remembered_caret_;   // 上一个词结束的地方
```

同一个会话里点到别处再打字时，这个「上一个词结束的地方」可能在屏幕的完全另一端，候选框就先在那里弹出来，等真实光标回来才跳过去。

**修复**：按用户提的思路——先读光标，再弹候选。

1. **按键前光标探测**。Shim 在一个词的**第一个按键**上，先用 `TF_ES_SYNC | TF_ES_READ` 只读编辑会话读一次当前选区位置，再把按键发给 Host。只读会话比读写会话更容易被同步授予，代价很小，而且只在每个词的首键上做一次。
2. **探测不到就不猜**。读不到位置时明确发送 `has_text_caret = false`，Host 收到后清掉旧锚点，宁可等一个往返也不在错误的位置弹出来。
3. **一个词之内锚点不漂移**。插入点会随每个字母右移，跟着它走会让候选框在词中间横向漂移。现在锚点在组合建立时取一次，直到组合结束才释放，这也是微信和搜狗的做法。

权威锚点仍然来自成功的组合编辑会话（v0.4.2 的既有约束没有放松），探测只负责补上「首键到真实光标回来」之间的空档。源码门禁同步改为**同时**断言这两点：组合会话内的取值必须保留，只读会话只允许用于按键前探测。

新增三条测试：探测到的锚点覆盖上一个词的位置；探测失败时候选框等待而不是乱弹；一个词打到底锚点不动、提交后释放。

## 验证

- 完整 CTest：全部通过；
- 新增 `test_dash_that_cannot_page_becomes_an_ordinary_dash` 与 `test_dash_still_pages_the_candidate_rows_when_a_row_exists`；
- 新增组合终止清空的源码门禁。

## 用户验证重点

1. 在 Claude 或 Codex 的空输入框里粘贴一段文字，**立刻**开始打字，确认粘贴的内容还在；
2. 中文模式下连续输入 `wo`、`-`，确认连字符能输出；
3. 候选超过一行时按 `-`，确认仍然能翻回上一行；
4. 打开一个满屏文本的 Notepad++，**随便点一个位置直接打字**，看第一次弹出的候选框是否就在插入光标下面（这一条最能说明问题）；
5. 继续把这个词打长，确认候选框不会跟着光标横向漂移。
