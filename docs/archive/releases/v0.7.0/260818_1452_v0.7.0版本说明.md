# PiInput v0.7.0 版本说明

## 标点后继续输入不再停顿

真机追踪确认，TSF 编辑、应用消息循环和 Host 计算都没有造成停顿。真正的问题是 Shim 把 `commit_result` 提交回执当成必须收到回复的请求；而 Host 在没有待学习内容时按协议保持静默。成功送达的单向通知因此被误判为断线，并进入 750 毫秒冷启动重试，后续按键只能在同一工作队列中等待。

v0.7.0 会区分“已经成功写入管道但没有回复”和“请求根本没有送达”。`commit_result` 成功送达即完成，不再重试；真实连接失败仍保留原有的 Host 拉起和重连逻辑。

## 数字 0 与其他数字使用相同的小数点规则

此前数字直通状态只识别 `1` 到 `9`，漏掉了 `0`，所以中文模式下 `0.7.0` 的第一个点会错误变成中文句号。v0.7.0 把 `0` 纳入直通数字判断，同时保留原有候选数字键规则。

预期结果：

- `0.7.0` 保持 `0.7.0`；
- `1.2.3` 保持 `1.2.3`；
- `0..` 输出 `0.。`，只有紧跟数字的第一个点按英文小数点处理；
- 普通中文句号仍输出 `。`。

## 安装提示

Shim 会被加载到每个应用进程中。安装完成后必须完全退出并重新打开 Notepad++、浏览器或聊天应用，旧进程不会自动换用新的 DLL。

## 开机不再弹出 Host 黑窗口

旧版把控制台程序 `PiInputHost.exe --serve` 直接写进 Windows 登录启动项，因此每次开机都会出现一个终端窗口。v0.7.0 升级时会删除这个旧启动项。Host 仍会由安装器和 TSF Shim 使用无窗口、分离进程方式在后台启动，不影响输入法使用。
