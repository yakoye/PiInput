# PiInput 词库长句与分段取字实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让词库长句精确命中，同时在无可靠长句时通过按 `=` 进入可撤销的分段取字，并提供索引化词库查询工具。

**Architecture:** 词库构建器新增 THUOCL 词频源和离线拼音解析；解码器为候选附加可验证的路径证据；`ImeSession` 在普通候选与分段取字之间管理不可变快照。Windows TSF 只负责按键映射、组合文本同步和候选窗呈现，不自行推断候选可信度。

**Tech Stack:** C++20、CMake、MSVC、Win32/TSF、PowerShell、CTest

## Global Constraints

- 保持纯离线；按键热路径不得访问网络或读取文本词库。
- 不使用 AI 判断句子是否有意义。
- 默认候选窗只有一行；`=`/下方向键才展开或进入分段取字。
- 分段选出的文字保留在组合区，最后统一上屏。
- 相同输入、词库和用户数据下候选顺序必须稳定。
- 不无差别提高 THUOCL 专业词权重。
- 不推送远端仓库；本阶段只保留本地提交。
- 不覆盖当前工作树中与本计划无关的既有修改。

- [ ] **Step 3: Implement strict THUOCL parsing and two-level pronunciation resolution**

```cpp
enum class DictionarySourceFormat {
    piinput_tsv,
    rime_yaml,
    pinyin_data,
    phrase_pinyin_data,
    thuocl,
};

struct DictionaryTerm {
    std::string word;
    std::uint64_t frequency{};
};

struct DictionaryBuildReport {
    std::size_t exact_phrase_count{};
    std::size_t character_derived_count{};
    std::size_t unresolved_count{};
};
```

Rules:

- reject malformed or zero-frequency rows;
- prefer an exact phrase pronunciation;
- otherwise join one deterministic primary reading per character;
- if any character has no reading, skip the entry and increment `unresolved_count`;
- normalize THUOCL DF with `round(log1p(df) * 1000)` and clamp to `uint32_t`.
