# 全拼超级简拼设计

日期：2026-08-20
状态：已定稿，进入实施

## 目标

全拼下支持简拼输入，覆盖三种写法：

```text
声母简拼      zhly     → 张靓颖
首字母简拼    zly      → 张靓颖
简拼全拼混合  srf / sruf / shrfa → 输入法
```

参考搜狗与 Google 输入法的公开说明。双拼不涉及——双拼本身就是定长简化，再叠一层简拼没有意义。

## 不做什么

- **简拼参与多词拼接**。`zsjs` 已经能匹配上千个词条，再让它参与「实词 + 实词」的拼接，候选空间会失控。PiInput 没有语言模型，排序只有词频，撑不住这个歧义量。第一版只做「简拼匹配词库里的整词」。
- **独立的「z 代表 zh」开关**。搜狗和 Google 都有这个选项，但在本设计里简拼键统一用首字母形式，`zhly` 与 `zly` 归一化后查同一张索引，开关无处可加，也没有行为差异可选。少一个用户需要理解的概念。
- **简拼的独立学习层**。选中后照常走现有的用户学习，不为简拼单独记账。

## 简拼键

每个词条算一个简拼键：取每个音节的首字母，拼接。

```text
zhi'shi'jing'shen  → zsjs
shu'ru'fa          → srf
zhang'liang'ying   → zly
```

`zh/ch/sh` 天然归约成 `z/c/s`，因为只取首字母。用户输入的声母简拼 `zhshjsh` 在查询前做同样的归约得到 `zsjs`，命中同一个键。这就是搜狗文档里「声母首字母简拼的作用和模糊音中的 z、c、s 相同，但属于两回事」说的那件事——它是简拼键的定义，与模糊音设置无关。

零声母音节（`a`、`ai`、`an`、`e`、`en`、`er`、`o`、`ou`）的首字母就是它自己的第一个字母。

## 索引

`BinaryLexicon::load` 已经把全部词条读进内存交给 `DevLexicon`，二进制文件只是加载加速。因此**简拼索引在内存里建，不改 `.lex` 格式**：旧词库直接可用，用户不需要重新编译词库，也不存在格式版本兼容问题。

结构与现有 `pinyin_keys_` 对称：

```text
simple_keys_   按简拼键排序的 (键, 条目下标) 数组
```

查询用 `lower_bound` + `starts_with`，与全拼前缀查询同一套机制。简拼键本身也支持前缀匹配，所以 `sr` 能查到 `srf`，逐键输入时候选连续变化。

**构建时机**：随词库加载在后台线程构建，与现有懒加载同一条路径。启用开关关闭时不构建，不付出任何代价。

**成本估算**：89 万条，生成键约 30ms，排序约 180ms，内存约 +12MB。放在后台线程，不进入按键热路径。实施时以实测为准，超出预算就改为首次简拼查询时构建。

## 匹配

### 纯简拼

输入全是辅音字母（`zsjs`、`srf`、`zhly`）时，不可能是合法全拼——全拼音节必须带韵母。归约成简拼键后直接查索引。

例外是 `n`、`m` 这类可以单独成音节的，以及 `zi/ci/si` 之类。这些照常先走全拼，简拼候选补在后面。

### 简拼全拼混合

`sruf` 要匹配 `shu'ru'fa`。做法是先归约再过滤：

1. 把输入切成音节序列，每个音节要么完整（`ru`），要么只有声母（`s`、`f`）；
2. 取每个音节首字母得到简拼键 `srf`，查索引拿到候选集；
3. 用已知的完整音节回过头过滤：候选的第 2 个音节必须是 `ru`。

`shrfa` 同理：切成 `sh` + `r` + `fa`，键仍是 `srf`，过滤条件是第 1 个音节声母为 `sh`、第 3 个音节为 `fa`。

切分有歧义时保留多个解析，与现有 `expand_input_prefix` 的多解析处理一致。

## 与现有路径的关系

简拼是 `Engine::query` 中与「精确查询」「前缀补全」「整覆盖拼接」并列的第四条候选来源，不改动前三条。

现有的「未完成音节」机制允许**最后一个**音节不完整；简拼是把这件事推广到**每个**音节。两者在分词层面同源，但查询层面完全不同——未完成音节靠全拼前缀索引，简拼靠简拼索引。不复用彼此的代码。

## 排序

简拼候选与全拼候选的冲突面很小：合法全拼音节必须带韵母，纯辅音串不可能是全拼。真冲突时全拼优先。

分组上简拼候选低于「精确词条」和「整覆盖拼接」，高于「单字兜底」。同组内按词频。

候选数量上限单独设，避免简拼把第一行占满——简拼歧义大，用户往往要翻页，但第一行必须留给更可信的来源。

## 设置

```ini
[pinyin]
simplified_pinyin=true
```

默认开启。用户明确要这个功能，且冲突面小。关闭时不建索引、不产生简拼候选，回到当前行为。

## 测试

- 简拼键生成：覆盖 `zh/ch/sh` 归约、零声母音节、单音节词；
- 纯简拼查询：`zsjs`→指示精神、`zly`/`zhly`→张靓颖、`zhshjsh`→指示精神；
- 混合查询：`srf`/`sruf`/`shrfa` 全部命中输入法；
- 逐键连续性：`s`→`sr`→`srf` 每一键都有候选且不倒退；
- 不干扰全拼：`nihao`、`xianzai`、`woaini`、`kadun` 的首选不变；
- 开关关闭时行为与当前完全一致；
- 索引构建耗时与按键延迟门禁。
