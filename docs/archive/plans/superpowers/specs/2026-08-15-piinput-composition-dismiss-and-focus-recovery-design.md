# PiInput 组合取消与失焦恢复设计

## 目标

1. 候选上右键保留“固定首位”和“删除该词”。
2. 右键菜单打开后，点击菜单外或按 `Esc`，关闭菜单并取消当前尚未上屏的组合文字。
3. 编辑器主动终止组合、截图覆盖层短暂抢焦点、点击输入框再返回时，不重复恢复原始拼音，不出现两份相同字母。
4. 无真实候选时保留应用内组合文字，但不显示空白候选框。
5. `mktm` 首选“明天”；按 `=` 后进入当前音节的单字选择，避免展示弱拼接词。

## 根因

旧实现失焦时释放所有待完成编辑请求并把镜像标记为断开。Host 的晚到回复仍会更新镜像，却无法写回原来的 TSF 上下文；再次获得焦点后又恢复镜像内容，造成应用已有文字与恢复文字重复。外部 `OnCompositionTerminated` 只释放 COM 指针，没有清除镜像和 Host 状态，也允许旧回复复活组合。

## 设计

- 普通失焦只通知 Host 隐藏候选，不丢弃待完成编辑，不把健康连接伪装成断线。
- 同一文本上下文恢复焦点时，仅在真实传输断开后发送 Resume。
- 外部终止组合时，本地镜像立即清空，并使此前所有在途序列失效；随后按顺序向 Host 发送取消。
- Host 候选窗的菜单取消动作精确携带进程 ID 与会话 ID，清空对应 HostSession，并向该进程的稳定入口 DLL 发送无激活控制消息；入口 DLL 结束真正的 TSF Composition。
- 无候选快照不创建/显示候选窗。

## 验证

- 镜像在外部终止后为空，终止前的在途回复被拒绝。
- 同进程不同会话、不同进程相同会话号不会被误取消。
- `fdsafds` 无候选时没有空白框。
- `mktm` 首选“明天”，`=` 后选中“明”等单字。
- Release 全目标构建与完整 CTest 必须通过后才生成发布包。
