# 常用语与安装器改进设计

两件事：输入法加「常用语」（自定义短语上屏），以及把安装器做成完整向导并带操作指引。

## 一、常用语

### 要达到的效果

| 用户输入 | 弹出候选 | 别名 |
| --- | --- | --- |
| `dzjl` | `北京市海淀区xx街道xx小区` | 手工指定 |
| `sfz` | `622322199005012219` | 手工指定 |
| `158` | `15801616544` | 不指定，靠内容前几位 |

即「可以设置快捷按键，也可以不设置；不设置就默认输入前几个弹出」。

### 复用已有的快捷表结构

`CustomShortcutSettings` 已经有 `aliases` / `position` / `icon` / `name` / `target` 五个字段，别名匹配 `shortcut_alias_matches` 和按位置插入 `splice_symbol_shortcuts` 都现成。常用语与它同构，**唯一的差别是动作**：一个上屏文本，一个启动程序。

**但不复用同一张表。** `target` 的语义是「交给 Windows 打开的文件、URL 或可执行文件」，往里填一句地址会被当成路径去启动；反过来，一条本想启动程序的行如果被当成文本，就会把命令行原样打进文档。两种动作共用一个字段，错一次的代价都不小，所以新开一张 `[phrases]` 表，字段各自含义明确，谁也不可能被误当成另一个。

### 数据模型

```ini
phrases.count = 3
phrases.1.aliases = dzjl
phrases.1.position = 2
phrases.1.label = 家庭地址
phrases.1.text = 北京市海淀区xx街道xx小区
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `aliases` | 否 | 逗号分隔的拉丁别名。留空则按下文自动推导 |
| `position` | 否 | 候选位置，2–9，默认 **2** |
| `label` | 否 | 候选框里显示的名字；留空显示内容本身 |
| `text` | **是** | 上屏的内容 |

上限 128 行（快捷表是 64）。启动项不会有几十条，常用语会——地址、证件号、邮箱、常用回复，一个人攒到上百条是正常的。

**位置默认 2 而不是 3**：第 1 位留给词库的首选词，普通打字的手感完全不动；第 2 位只要一次按键就能取到。用户可以改成 3–9。

### 四条触发路径

#### 1. 显式别名（`dzjl`、`sfz`）

与启动快捷方式完全同路：别名同时与「拼音读音」和「原始输入」比对，所以双拼和全拼都能命中。零新增风险。

#### 2. 自动别名——拉丁内容

`aliases` 留空且 `text` 以 ASCII 字母开头时，取内容自身的前几个字母作为别名，长度 2 到 8。`github.com/yakoye` 自动得到 `gi`、`git`、`gith`……字母本来就会起合成串，不需要任何新机制。

#### 3. 自动别名——中文内容

`aliases` 留空且 `text` 以中文开头时，用词库反查（`Engine::lookup_word` 已存在）取前 1–4 个字的读音，拼成声母串：`北京市海淀区……` 得到 `b`、`bj`、`bjs`。只看前 4 个字，开销可忽略。

反查不到读音（生僻字、符号开头）时**不报错**，这一行只是需要手工填别名，设置界面给出提示而不是拒绝保存——用户已经录进去的内容不该因为我们查不到读音就被挡住。

#### 4. 数字内容——补全剩余位，不吃第一个数字

这条是整个设计里唯一需要解释取舍的地方。

**为什么不能照字面做。** 数字键在中文模式下是直接透传的：没有合成串时按 `1`，这个字符立刻落进文档，输入法根本不接管。要让「输入 `158` 弹出候选」按字面成立，就得从第一个数字起开始吃键、把数字做成合成串。代价是两条硬性要求同时破掉——核心检查里的「输入数字 `123`，不得丢失首个数字」，以及「远程桌面地址框等数字输入框应直接透传」。为一个便利功能去动所有人的数字输入，这笔交易不划算。

**实际做法：数字照常落下，补全剩下的部分。**

1. 数字键的处理一个字节都不改，照旧立即透传。
2. Shim 记一个影子缓冲，只存「刚刚连续打出的数字」。遇到任何非数字键、焦点切换、光标移动、Esc 就清空。
3. 当这串数字**长度 ≥ 3** 且是某条数字常用语的严格前缀时，打开候选框作为**建议**（合成串那一行是空的——此刻确实没有在合成任何东西）。
4. 选中它时**只插入没打完的那部分**：已经打了 `158`，插入 `01616544`。

这样做的好处值得逐条说清：

- **零回归**。数字透传路径没动，`123` 还是 `123`，数字输入框还是直接透传。没有录入数字常用语的用户，行为与现在逐字节相同。
- **不需要删除已上屏的文本**，也不需要重写周边文本。只追加后缀，所以在 TSF 支持差的程序（MobaXterm 这类终端）里同样成立——最坏情况只是建议不弹出，而不是把文档改坏。
- **用户视角的结果一样**：打三位、按一下、得到完整号码。手机上的号码补全就是这个形态。

**长度门槛定在 3**：1 位或 2 位会频繁误弹——日期、编号、价格里到处是两位数字。

### 不进入学习

常用语候选必须永不写进用户模型。`dzjl → 北京市海淀区…` 不是一条「拼音—词」事实，学进去会污染反查，而且下次打 `dzjl` 时会出现一个来源不明的重复候选。新增 `CandidateKind::phrase`，在学习路径上显式排除。

### 设置界面

在现有「快捷表」旁边加一张「常用语」表，四列（别名 / 位置 / 显示名 / 内容），增删行、上移下移，与快捷表一致的交互。别名留空时在该行显示自动推导出的触发串（灰字），让用户看得见「不填别名会靠什么触发」，而不是猜。

## 二、安装器

### 现状与目标

现在是三个 `TaskDialogIndirect`：确认页、进度页、完成页。功能齐全，但形态是「系统对话框」而不是「安装程序」，而且装完之后用户不知道怎么用——`Win+Space` 切换、`Shift` 切中英、`=`/`-` 翻页、`fh`/`bq`/`sz` 这些工具入口，全都只写在随包的 markdown 里，没人会去读。

目标是 WGestures 那种形态：一个像样的向导，加一份装完就能看的操作指引。

### 不引入第三方安装框架

NSIS / Inno Setup 会带来一个它们解决不了而我们正好最怕的问题：**多一个未签名的可执行壳**。现在 Defender 已经会把 `PiInputHost.exe` 当 `Trojan:Win32/Wacatac.C!ml` 隔离，智能应用控制强制模式下安装器本来就进不去。再套一层第三方 stub，只会让启发式判定更难过，而不是更容易。

所以继续用自绘 Win32 向导，不加依赖。

### 向导页面

| 页 | 内容 |
| --- | --- |
| 欢迎 | 产品名、版本、一句话说明；**明确标注这是候选版、未签名** |
| 说明与许可 | 许可摘要 + Defender / 智能应用控制会拦什么、怎么处理 |
| 安装位置 | 两个位置分别装什么、为什么需要一次管理员权限、是全新安装还是覆盖升级 |
| 进度 | 进度条 + 当前步骤文字 |
| 完成 | 三个勾选项：打开设置 / 查看操作指引 / 立即激活输入法 |

`--silent` 的行为**一个字节都不改**。脚本和本机安装都在用它，它必须继续「完全没有窗口」。

### 操作指引做成随包 HTML

不做 Win32 指引窗口，做一份随包 HTML，从完成页和托盘菜单都能打开。理由是成本与质量都更划算：排版、图示、滚动、可复制，HTML 全都免费拿到，而自绘窗口每一项都要写；包里已经有 `shared-ui.css` 和 `RegCalc64Tool.html` 这个先例，样式直接复用。

指引内容按「第一次用会卡在哪」排序，而不是按功能清单排：

1. 怎么切到 PiInput（`Win+Space`），怎么确认切到了
2. 中英文怎么切（`Shift`），指示器在哪
3. 选词：数字键、空格、`=`/`-` 翻页
4. 标点：中英文标点、两键规则（`0.8` 与 `0.8。`）
5. 工具入口：`fh` 符号、`bq` 表情、`sz` 设置、`jsq` 计算器、`msp` 画图
6. **常用语怎么加**（本版新功能，放在用户真的会用到的位置）
7. 装不上 / 打不出字怎么办：Defender 隔离、智能应用控制、`piinput-diagnostics.exe`

### 装完之后的那一下

完成页的「立即激活输入法」勾上时直接跑 `piinput-profile.exe --activate`。现在这一步靠用户自己按 `Win+Space` 找，而 profile 刚注册完有时并不在前台生效——这是已经踩过的坑（见 `piinput-restore-needs-reactivate` 的成因）。

---

## 实施顺序

常用语先做，它是用户描述最细、价值最直接的一件；安装器随后。两件都不碰协议版本号——常用语的候选走现有的候选通道，安装器完全在协议之外。
