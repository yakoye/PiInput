# PiInput v0.7.7 验证记录

## 内容

用户要求两件事：系统托盘图标与右键菜单；把设置文件里能改的选项全部做进设置窗口。

## 托盘

托盘图标属于 Host 进程——它是唯一既长期存在、又拥有消息循环的 PiInput 进程。这一点依赖 v0.7.6 修好的消息泵：托盘窗口与候选窗在同一个线程上，如果管道循环在等待按键时不泵消息，右键菜单根本打不开。

菜单项直接显示当前状态（「中文」「小鹤双拼」）而不是动作名，菜单因此同时是状态显示。左键单击切换语言，与其他输入法在托盘图标旁放中／英切换的位置一致。

切换动作**写设置文件**而不是直接改引擎状态：Host 本来就在每个输入边界重新读取 `settings.ini`，走同一条路可以保证托盘与设置窗口的改动行为一致。

「退出」经由新增的 `PipeServer::set_stop_requested_handler`，在两次请求之间检查，不侵入管道循环内部。

## 设置窗口

原来只暴露 4 个选项（输入方案、默认语言、候选字号、候选框高度），其余 26 个只能手工编辑 ini。

窗口重写为**数据表驱动**：30 个选项写成一张 `kRows` 表，逐行声明所属页、控件类型、绑定字段、标签与取值范围；控件创建、载入、存回各自遍历这张表。新增一个选项只需加一行表项和两个 switch 分支，不必再写一段控件创建代码。

布局为五个标签页，每页统一的标签列与控件列，行距固定，页与页起始高度一致。

写入层重写为通用的键值就地更新：`apply_assignments` 只重写自己管的键，其余行——注释、未知键、本版不认识的段——原样保留；缺失的段追加到文件末尾。原来那套「每个段一组 in_/found_/inserted_ 标志」的写法扩到 30 个键会散架。

## 界面文字

括号样式的两个选项由「搜狗」「微信」改为直接显示 `{ }` 与 `「 」`。这两个样式与那些产品没有关系，用符号本身表达更准确。

配置取值名 `sogou` / `wechat` 保持不变——它们是数据格式，改动会让已有的 `settings.ini` 失效。双拼方案名（小鹤、自然码、微软双拼、智能 ABC）是键位方案的通用名称，按用户判断不属于品牌引用，未作改动。

## 既有回归的调整

`tests/windows_source_regression.cmake` 中有一组检查锁定的是旧窗口的实现字面量：`kRowsCombo`、`value <= 6U`、`values.visible_rows`、`BS_GROUPBOX`、分组标题文字、`select_number(state->font_combo, 16U)`。新窗口以数据表和标签页表达同一批功能，这些字面量自然不再存在。

已改为检查等价的新结构：`Field::visible_rows` 及其 `1U, 6U` 范围、`WC_TABCONTROLW` 与 `TCM_INSERTITEMW`、页名，并新增一组检查要求 `Field::simplified_pinyin`、`Field::max_items`、`Field::punctuation_mode`、`Field::english_enabled`、`Field::prefix_scan_limit` 等九个字段必须可达——比旧检查更贴近「每个选项都要能改」这个真正的意图。

预览的圆角高亮（`RoundRect` 与 `RGB(241, 235, 255)`）和滚轮微调（`step_numeric_setting` + `SetWindowSubclass`）是重写时一度丢掉的既有功能，已补回。

## 人工验证要点

见 `v0.7.7安装、使用与测试.md`。最关键的一条是保存不破坏配置：在 `settings.ini` 里手写一行注释，用窗口保存后注释必须还在。
