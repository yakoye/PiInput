# 词库与 SCEL 设计

## 当前 SCEL 解析范围

v0.1.3-dev 支持：

- 基础文件头检查；
- 格式 mask `0x44` 和 `0x45`；
- 词库标题、分类、描述和样例；
- 全局拼音表；
- 同音词组；
- 词条文字；
- 标准拼音；
- 扩展字段首个 16 位权重；
- TSV、JSONL 和 TXT 导出；
- 输入边界检查和错误偏移。

当前实现参考了社区公开的 SCEL 解析结构，并通过用户提供的真实文件进行回归验证。SCEL 没有作为本项目稳定公开格式，后续必须保留容错和未知版本拒绝策略。

## 导入流水线

```text
SCEL
  ↓ 解析
RawEntry(word, pinyin, source_weight)
  ↓ Unicode 与拼音规范化
NormalizedEntry
  ↓ 去重与冲突处理
MergedEntry
  ↓ 质量评分和词库层级
RankedEntry
  ↓ 编译
LiteIME .lex
```

## 拼音规范化

需要统一：

- 小写；
- 音节使用 `'` 分隔；
- `ü`、`v` 和 `u:` 的内部形式；
- `lüe/nüe` 等特殊拼写；
- 多余空格；
- 非法音节；
- 汉字长度与音节数量不一致的异常词条。

## 词库分层

```text
base.lex          通用基础
people.lex        常见人名
place.lex         常见地名
computer.lex      计算机
engineering.lex   工程
electronics.lex   电子
pcie.lex          PCIe/芯片
user.lex/user.db  用户自定义和学习
```

每个词库具有：

- ID；
- 名称；
- 类别；
- 版本；
- 来源；
- 许可证或使用说明；
- 默认启用状态；
- 基础权重；
- 校验和；
- 最低引擎版本。

## `.lex` 初步方向

当前 `.lex` v1 已包含魔数、格式版本、固定记录、词条权重和 UTF-8 字符串池，并在编译时去重。后续正式格式还应包含：

- 固定文件头；
- 魔数；
- 格式版本；
- 字节序；
- 文件总长度；
- 校验和；
- 拼音序列索引；
- 词条记录；
- UTF-8 字符串池；
- 可选二元关系区；
- 元数据区。

当前引擎可以读取 TSV 和 `.lex`，但 TSV 只用于开发和转换。正式静态词库将改为带校验和和索引的内存映射 `.lex`。


## v0.1.3-dev 批量导入

`import-dicts.ps1` 会：

1. 转换相邻 `dicts` 目录中的所有 SCEL；
2. 为每个词库生成独立 `.lex`；
3. 合并所有 TSV；
4. 由编译器去重并生成 `liteime-imported.lex`；
5. 把结果保存到 `%LOCALAPPDATA%\LiteIME\UserData\lexicons`。

## v0.1.4-dev 内置基础词库

专业 SCEL 不能替代通用基础词库。v0.1.4 新增 `data/base_lexicon.tsv`，安装和导入时始终先编译基础词库，再与用户 SCEL 合并。这样即使专业词库不包含“计算机”“输入法”等普通词，基础输入仍有可用候选。

当前基础词库只有数百条，用于打通开发链路和建立回归测试，不代表正式词库规模或准确率。后续必须使用许可证清晰的通用语料扩充，并加入通用/专业/用户分层权重。
