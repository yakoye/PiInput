# PiInput v0.6.1-dev 版本说明

本版只处理逐键输入延迟，特别是标点之后再输入文字的卡顿，不增加新功能，不改变候选内容。

## 修复内容

- 稳定 TSF 入口与 Host 不再为每条管道消息分配并清零 1 MiB 协议上限缓冲区，改为复用一个 16 KiB 起步、按需增长的缓冲区；
- 组合边界（每个词的首字母，也包括每个标点之后的第一个字母）不再复制整份候选快照，也不再每次对 `settings.ini` 做两次文件系统查询；设置文件不存在时不再每键抛出一次异常；
- Host 不再把自己刚编码的回包重新解码一遍来展示候选；
- 句子解码在进入定长 beam 前先用整数比较判断能否入选，不再为必然淘汰的路径复制句子文本；
- 未完成音节的补全阶段把已消费音节前缀提到双重循环之外，并将补全词与句子前缀的终端组合预算限定为 8 条；
- 候选栏每键只重建一次 UTF-16 候选列表，几何未变化时不再重复移动窗口。

## 实测依据

真实 101,472 词二进制词库，本机 Windows x64 Release：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 空载 IPC 往返 P95 | 809 微秒 | 71 微秒 |
| 逐键 Host 往返 P95（`womfmktm`） | 2582 微秒 | 1417 微秒 |
| 词—标点—词链路 P95 | 2484 微秒 | 1446 微秒 |
| 引擎查询 `wom`（90 条候选） | 590 微秒 | 197 微秒 |
| 引擎查询 `womfmkt`（90 条候选） | 1191 微秒 | 341 微秒 |
| 引擎查询 `biruwoycuibuv`（90 条候选） | 约 1880 微秒 | 610 微秒 |

整句 41 次按键：P50 78 微秒，P95 1405 微秒，标点后首字母 P95 121 微秒。

需要说明的是，此前的性能门禁固定按 10 条候选测量，而 Host 实际请求 90 条，两者相差约 10 倍，真实热路径长期没有被覆盖。本版基准工具新增 `--limit` 并默认 90，外部大词库性能门禁自此按生产页大小运行。

## 三个长文本真机打字测试

发布后逐键回放三个真实长文本共 1912 次按键（按真人习惯选字：目标词不在首选时翻行 + 数字键）：逐键 P50 约 0.23 毫秒，P95 约 1.8 毫秒，最慢一次 3.7 毫秒；提交之后第一个按键与普通按键处于同一水平，标点后的额外开销已经消除。

同一次测试测得候选命中现状：首选命中 30.2%，第一行内 40.2%，90 条候选内可达 54.7%。这是排序质量问题，本版未改动排序逻辑，属于既有现状。完整数据见 `docs/三个长文本打字测试_v0.6.1-dev.md`。

## 候选质量

候选内容与顺序保持不变：`rug` 为如果/入股/乳沟，`mktm` 为明天，`womfmktm` 为我们明天，`qvnali` 为去哪里，`hlheruhdlq` 与 `huangheruhailiu` 为黄河入海流，`biruwoycuibuv` 候选中仍包含比如我要是不知道。

## 验证句

```text
我，他们。我们明天，去哪里？明天、后天！打后天。
```

请连续输入，不要故意停顿，重点检查标点之后继续输入文字时是否还有明显停顿。
