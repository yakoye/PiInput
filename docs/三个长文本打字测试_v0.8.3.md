# 三个长文本打字测试（v0.8.3）

v0.8.3 继续执行三组真实文本逐键回放、段落输入、结构化语料和逐键延迟门禁，结果与 v0.8.2 一致，无回归。

本版没有触碰解码、词库或候选排序，改的是「哪些按键该接管」和「输入法能否被加载进某个进程」，因此长文本结果预期不变。执行仍是必需的：本版在按键路径上新增了拒绝理由的记录，需要确认追踪关闭时它没有渗入延迟。

## 本版必须复验的项

- **`piinput-keystroke-latency` 与 `piinput-typing-latency` 未因新增记录退化。** 每次拒绝按键都会多算一次理由并调一次追踪，即使追踪关闭也如此。这是本版唯一进入按键热路径的改动。
- **和弦记录不得影响正常输入。** 询问回调里新增的和弦记录对每个非 Shift 键都会跑一次；长文本回放全程不按 Shift，该记录不应改变任何状态。
- **拒绝理由的分布合理。** 长文本回放中 `key_refused` 应只出现 `not_wanted` 一种（没有合成串时的退格之类）。出现 `sensitive_scope`、`replay_tag`、`ctrl_queue_only` 中的任何一个都说明有粘性故障。

## 真实应用手工测试

必须使用验证记录中的同一 build ID。**每个受测程序都要重启**——输入法组件是 DLL，不重启就还是旧版本。

1. **Chrome 标签重命名**：右键标签 → 重命名，打 `zhongwen`，应正常出候选并上屏。
2. **Chrome 书签编辑**：编辑书签名称，同样确认。
3. **Chrome 地址栏**：作为同进程对照，行为应与 v0.8.2 一致。
4. **yesymbol 搜索框**：打开符号工具，在搜索框打中文，应正常。
5. **终端 Shift 组合键**：MobaXterm 里用 Shift+Insert 粘贴，中英文模式**不得**切换；Shift+Delete、Shift+方向键选中文本同样确认。
6. **Shift 单击仍切换**：单独按一下 Shift 应正常切换中英文——上一条不能把这个也修没了。
7. **密码框仍不转换**：任意网站的密码输入框，中文模式下打字母应直接落下拉丁文，不出候选。这是 `IS_PRIVATE` 拆分后必须回归的一条。
8. **升级不中断已开程序**：装上本版后不重启任何已打开的程序，在其中继续打字应正常。
