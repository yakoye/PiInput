# 搜狗与 PiInput 候选对照（2026-08-15）

测试环境为同一个独立 Notepad++ 窗口，使用物理按键切换并输入，不使用绕过输入法的文本注入。

| 小鹤编码 | 搜狗首批候选 | PiInput v0.5.2 当前首批候选 | 结论 |
|---|---|---|---|
| `mkt` | 明天等 | 明天、命题、名堂、名头、明天上午…… | 首选一致；PiInput 保留未完成音节补全 |
| `rug` | 如果、入股、乳沟、如歌…… | 如果、入股、乳沟、如歌、如故、入关…… | 本版已修复长词抢占 |
| `xnhe` | 小鹤、小何、小盒、小河…… | 小河、小和、笑和、晓和…… | PiInput 当前词库把“小河”排首选 |
| `yuwh` | 欲望、渔网、鱼王…… | 欲望、与王、与网、于王、鱼王…… | 首选一致，后续候选仍需词频清洗 |
| `hlheruhdlq` | 黄河入海流 | 黄河入海流 | 精确诗句均为首选 |

## 交互观察

- 两者均支持空格确认候选；
- PiInput 的 `=` / `↓` 与 `-` / `↑` 用于逐行展开和回退；
- PiInput 默认单行、40 DIP 紧凑候选栏；
- PiInput 单独按 Shift 可进入英文直输，英文离线候选默认关闭、可配置开启；
- PiInput 的 `;;f`、`；；f` 和双反引号加 `f` 在候选栏内打开符号中心。

## 不采用的做法

本轮没有复制搜狗内部基础词库，也没有针对每个错误词手工置顶。排序修复通过统一的未完成音节成本与扫描预算完成，以保证相同规则能覆盖其他长短输入。
# 2026-08-15 补充：空候选与 `=` 分段策略

- 搜狗官方帮助把 `-` / `=` 定义为可配置的上一页/下一页键，并提供“以词定字”能力；其近期更新还明确提到限制非单字候选数量。
- 微信截图显示展开区可以继续展示较多同音词，但这会让低质量专业词和姓名词占据较大面积。
- PiInput 采用折中方案：折叠行只保留真实高置信候选；`=` 先遍历可信词条，可信词候选耗尽后进入当前未解决音节的单字选择。已选前缀继续留在组合区，全部完成后一次上屏。
- 无真实候选（如 `fdsafds`）时不显示空白框；原始字母仍由 TSF Composition 管理，可继续编辑、回退或按 Enter 原样上屏。
- 小鹤 `mktm` 的固定验收为：首选“明天”，按 `=` 后进入“明、名、命……”而不是继续暴露“名填、明舔”等弱组合。
