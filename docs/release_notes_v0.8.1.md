# PiInput v0.8.1 版本说明

本版修的都是只在真实程序里才出现的问题，本机测试全绿。

## 忽略打不出来

`hult` 一个候选都没有。小鹤双拼里那是 hu + lüe，解码本身是对的。

ü 在 ASCII 里有两种写法，而不同来源的词库各选了一种：本项目内部一律用 `u`（音节表收的是 `lue`、`nue`），而导入的第三方词库常用 `v`，把「忽略」存成 `hu'lve`。两边对不上，凡是带 lüe、nüe 的词全都打不出来——忽略、掠过、虐待、疟疾。

现在主查落空时会换另一种写法再试一次。只有这两个韵母受影响：`lv`、`nv` 是独立音节两边写法相同，`jue`、`que`、`xue`、`yue` 本来就只有一种写法。

没有改成加载时统一归一：那要在启动时遍历四千万字节的词库，而冷启动本来就贴着预算线。

## 32 位程序里能用了

MobaXterm 里切到 PiInput 是灰的，等于没装。原因是 **PiInput 此前只出 64 位**：32 位进程只能加载 32 位 DLL，也只看得见 `WOW6432Node` 那个注册表视图，而那里没有 PiInput 的登记。

现在随包多出一份 32 位的输入法组件（约 400 KB），装到 `Program Files (x86)`，并登记进 32 位视图。

**词库不会翻倍。** 输入法组件是个薄客户端，词库和引擎都在后台程序里，32 位程序连的仍是同一个 64 位后台——同一份词库，同一份学习记录。

## 候选框跟着光标走

终端里候选框会跑到别处，甚至跑到另一个显示器。

MobaXterm 其实报了位置，但报的是一个固定的屏幕角落，24 次按键纹丝不动，而它的窗口在另一个显示器上。它实现了接口却返回假值，比不实现更难对付——不实现我们会走兜底，返回假值我们就信了。

现在会检查报来的位置是不是落在它自己的窗口里，不是就改用上一次真实的位置。这条对所有报假位置的程序都生效。

## 候选框里显示正在打的字母

终端里候选是对的，而你打的字母一个都看不见，只能靠候选反推。

显示合成串本是应用的职责，绝大多数应用也做了，终端不做。候选框现在会把字母显示出来——默认只在应用没显示时才画，避免同一串字母出现两次。设置里可以改成总是显示或从不显示。

## 中文模式下按 Shift 打大写

打 `previewIdentity` 会得到 `previewdI`——大写的 `I` 跑到末尾，中途还被切进英文模式。

中文模式下按住 Shift 的字母原本直接放行给应用，让它自己打大写。被放行的按键不会进入输入法的 `OnKeyDown`，「这次 Shift 是当修饰键用的」这件事就没人记下来，松手时被判成单击：切了模式，还顺手把正在打的 `preview` 提交了；同时那个字母绕过输入法自己落到文档里，和刚提交的内容抢先后顺序。

现在字母一律由输入法接管，大写字母提交的是**原始字母加这个大写**：打 `key` 再按 Shift+`D`，上屏 `keyD` 而不是 `可以D`。伸手去按 Shift 说明你在拼一个词，不是在选候选。标点仍然取候选——`nihao` 后打句号该得到「你好。」。

Ctrl 组合不受影响。

## 中/a/A 提示弹在屏幕中央

在 Notepad++ 里位置正确，在 ChatGPT、Codex 里却弹到屏幕中间。

提示窗只查 Win32 的系统光标，而 Chromium 及基于它的程序自己画光标，根本不建系统光标；拿不到位置就退回「居中到前台窗口」。同一个窗口里候选框位置却是对的，因为它另有一级兜底。

现在两者共用同一套定位。摆放也从「光标正上方」改成「左上」——候选框并不总在下方，屏幕底部和 Windows 搜索面板里它会翻到上面来，两个就叠在一起。

## 安装器带界面时装不上

双击安装器会失败，静默安装却成功。带界面时安装工作跑在另一个线程上，而 COM 是按线程初始化的，输入法配置注册因此在那里失败。这个缺陷一直存在，只是此前所有自动化路径都用静默模式，没人走到过。

一键更新现在也改走安装器自己的界面：确认页说明装到哪里，安装过程有进度条，完成页负责打开设置程序和配置目录。脚本里原本重复实现的那一份已删除。

## 卸载后 Host 进程还在跑

卸载器请求 Host 退出后只等 3 秒，且不检查结果。Host 没退出就一直占着控制管道和一个已被改名的可执行文件，下次安装起不来。

现在等待改为 10 秒（足够刷完几十兆的学习记录）并检查结果，仍不退出才精确终止属于本次卸载的那个进程，结果如实上报。

## 另外两项

- **反引号的前缀命令撤除**：`` ``f ``、`` ``u `` 这类不再从键盘触发，反引号回归普通标点。工具栏的符号中心不受影响。
- **设置入口触发码更正**：`shizhi` 改为 `shezhi`，其余别名不变。

## 中文模式英文候选

真正解决的问题是**拼写辅助**：忘了一个词怎么拼，打出记得的前几个字母，让输入法补出来。

```text
belie   →  believe  believed  belief
info    →  information  info  informed
palad   →  palladium
```

打开方式：设置程序的英文页，勾选「中文输入时也给出英文候选」。这一项与「英文模式下启用英文候选」相互独立，英文模式的行为不受任何影响。

### 什么时候会出英文

同一串字母既是拼音又可能是英文词。这里的标准只有一条：**打字过程中不该频繁冒出英文，而真想用英文的时候要能匹配出来。** 按这条标准标定的结果是按输入长度分档：

| 输入长度 | 行为 |
| --- | --- |
| 1–2 个字母 | 完全不给。双拼下两个字母正好是一个音节，而那里住着「我」和「的」，英文赢不了 |
| 3 个字母 | 只认完整的词，且这个词必须收录在常用词表里 |
| 4 个字母 | 可以按前缀补全，但只补向足够常用的词 |
| 5 个字母及以上 | 打开完整词库，拼写辅助的主场 |

三个字母那一档最容易误伤，因为双拼下三个字母必然是词打到一半：`wom` 是「我」加个 m，`car` 是「擦」加个 r。

判据是**这个词在不在常用词表里**，而不是权重高不高。试过权重阈值，任何一条线都会在中间切出空集，把 `dog`、`egg` 这类日常词一起误伤。常用词表本身就是「最常用的词」，判据和问题是同一件事，不需要再挑一个数。实测分得干净：`dog`、`egg`、`cat`、`bus`、`car` 全部收录，而 `tam`、`nim`、`nid`、`wod`、`ken` 一个都不在。

**把词完整打出来永远算数。** 打完 `bucolic` 一定会出，哪怕它排在常用词表的倒数一百名。

**这些限制只在候选行里有中文时才生效。** `girl`、`fish` 在双拼里解码不出任何中文（`gi` 不是合法音节），候选行本来就是空的，没有什么需要保护——那里从第二个字母就开始给英文，而不是空两下再猛地填满。

有中文要让位时一次最多两个英文候选；解码不出中文时把候选行填满。全词命中且不超过四个字母时只给这个词本身，不会连带拖出 `catch`、`cathedral` 这类同前缀的长词。

**打完的词排在自己的变形前面。** 打 `animal` 给的是 `animal` 而不是 `animals`。只认屈折变化（复数、时态、比较级这些）——`believe` 不是 `belie` 的变形而是另一个词，常用得多，那种情况下补全仍然排前面。

顺带清掉了一批混进英文词库的汉语拼音。词频统计的是真实英文文本，而拼音在英文语境里出现得不少，`hao`、`xie`、`dui`、`mei`、`zhong` 因此都成了「英文词」，权重和 `car`、`cat` 挤在一起。它们已在词库生成阶段剔除，而 `can`、`he`、`me`、`man`、`men`、`sun`、`tan`、`nun`、`fang`、`gong` 这些同样是合法音节的真英文词不受影响。

### 快捷命令不受影响

`calc` 打开计算器、`sj` 给出时间这类快捷码是手工配置的，它们的候选编号不会因为混入英文而改变。英文候选一律排在快捷命令之后：

```text
calc  →  1 中文候选   2 计算器   3 calculate   4 calculation
```

固定候选和删除候选作用于词库，因此对英文候选直接拒绝，不会误伤同位置的中文词。

### 词库

英文词库扩充到约 25 万词，分三层：

| 层 | 规模 | 内容 |
| --- | --- | --- |
| 高频层 | 28,670 | 原有词表与常用词表合并去重，日常高频词永远排在最前 |
| 中频层 | 22,529 | 按真实词频收录，`palladium`、`paladin`、`obsidian` 都在这层 |
| 低频层 | 199,999 | 覆盖用，只保证打得出来 |

高频层由两份来源合并：项目原有的词频表（24,188 词），加上一份人工整理的常用词表补入的 4,482 个词。补入的都是原表真缺的日常词——`tablespoon`、`grandchild`、`lawmaker` 这类。合并结果就是最终的那一份高频词数据，不再是一张原表加一张待合并清单。

分层是必需的而不是优化：只有词形没有词频时，`palad` 会被 `palladia`、`palladic` 这类同前缀的生僻词按词长挡在三个候选之外，而这两个词在词频统计里根本不存在——正说明没人用它们。

词库数据来自 dwyl/english-words（Unlicense，公有领域）与 wordfreq（数据 CC BY-SA 4.0，须署名 SUBTLEX 作者）。完整许可证、来源与取用方式随包安装在 `bin/licenses/EnglishWordlist/`，另见 `LICENSE_NOTICE.md`。

### 学习

选中的英文词会被记住，与英文模式共用同一份学习数据——在哪个模式打过这个词，并不影响下次是否还想用它。词库再大也覆盖不到领域专名，打过一次即可补全，这是长尾唯一的出口。

## 中文模式下按 Shift 打大写

打 `previewIdentity` 会得到 `previewdI`——大写的 `I` 跑到了末尾，中途还被切进英文模式。

原因是中文模式下按住 Shift 的字母被直接放行给应用，让它自己打大写。这个做法省事，但代价有两处：被放行的按键根本不会进入输入法的 `OnKeyDown`，于是「这次 Shift 是当修饰键用的」这件事没人记下来，松手时被当成单击，切了模式还顺手把 `preview` 提交了；同时那个字母绕过输入法自己落到文档里，和刚提交的内容抢先后顺序。

现在字母一律由输入法接管，大写字母走「先提交正在打的内容，再原样追加这个字符」的路径，顺序由 Host 保证。

**提交的是字母本身，不是候选。** 打 `key` 再按 Shift+`D`，上屏的是 `keyD` 而不是 `可以D`——伸手去按 Shift 说明你在拼一个词，不是在选候选。标点仍然取候选：`nihao` 后打句号该得到「你好。」。

Ctrl 组合不受影响：字母遇到 Ctrl 一律让路，两种按键状态读法任一读到即让路。

## 来自 v0.7.16 的修复

- **升级后重启不再丢失程序文件。** 旧版升级是「先卸载再安装同一批路径」，卸载时被占用的文件删不掉，就把整棵安装树排进了系统的重启待删队列；安装器随后把新文件写回同样的路径，装完当场可用，下一次重启却被系统按队列删光，只剩注册表。现在删不掉的文件先改名到一次性路径再排队，稳定路径永不进队列。
- **Windows 搜索里能看到候选了。** 此前候选窗其实一直在画，只是被搜索面板盖住——它绘制在普通置顶窗口无法逾越的层级上。候选窗现在避开面板摆放，且只对 Windows 搜索生效，其余程序位置逐像素不变。
- **安装器有了界面**：确认页说明装到哪里、为何需要一次管理员权限，安装过程有进度条，完成页把「打开设置」改成可勾选而非强制弹窗。
- **一键更新改为原地覆盖升级**，UAC 提示从两次减到最多一次，Shim 未变时一次都不需要。
