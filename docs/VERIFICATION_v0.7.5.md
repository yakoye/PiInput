# PiInput v0.7.5 验证记录

## 需求来源

用户提出全拼超级简拼，参考搜狗与 Google 输入法的公开说明：声母简拼（`zhly`）、首字母简拼（`zly`）、简拼全拼混合（`srf`/`sruf`/`shrfa`）。

## 关键约束

现有词库按完整拼音串排序，靠 `lower_bound` + `starts_with` 做前缀扫描。简拼不是前缀关系——`zsjs` 与 `zhi'shi'jing'shen` 只有首字母相同——所以现有索引找不到任何简拼。硬扫首字母相同的几万条词条逐个验证，每次按键都做，性能上不可接受。

因此必须有独立的简拼索引。

## 实现方式

- **简拼键**：取每个音节的首字母。`zh/ch/sh` 天然归约成 `z/c/s`，所以只需要一张索引，声母简拼在查询前做同样归约即可命中。
- **索引位置**：`BinaryLexicon::load` 已经把全部词条读进内存交给 `DevLexicon`，二进制文件只是加载加速。索引因此建在内存里，**不改 `.lex` 格式**——旧词库直接可用，用户不需要重新编译词库。
- **构建时机**：第一次简拼查询时构建，与既有的 `ReverseWordIndex` 同一套惰性模式。关闭简拼的用户不付任何代价。
- **混合输入**：`simplified_pinyin_readings` 把输入切成音节序列，每个音节要么完整要么只有声母，取首字母得到简拼键，再用拼写出来的音节回过头过滤。`sruf` 的键是 `srf`，过滤条件是第 2 个音节必须是 `ru`。
- **精确音节数**：只匹配音节数等于声母数的词。`srf` 不会带出「输入法软件」。

## 过程中修掉的四个问题

1. **`wang` 的单字被埋**：`wang` 能读成 w+a+n+g 四个声母，简拼把四字词顶到了「王」前面。改为只在输入完全无法读作普通拼音时才启用简拼。
2. **未捕获异常导致进程 `__fastfail`**：`PinyinSegmenter::normalize` 对非拼音字符抛 `invalid_argument`，而简拼的调用点在 `Engine::query` 的 try 块之外，异常逃逸触发 terminate，`piinput-host-session` 与 `piinput-incremental-decoder` 以 `0xc0000409` 崩溃。简拼段现在自带 try/catch——热路径按契约不得抛异常，而简拼只是一个额外的候选来源。
3. **搜索空间指数级**：解析在每个位置分叉，长输入下调用次数爆炸。加了输入长度上限 32、音节数上限 8，并在每层循环里检查已收集的解析数。
4. **排序被外层规则盖过**：`Engine::query` 的排序按消耗音节数降序，会让 `sruf` 的「收入分配」（4 音节）压过「输入法」（3 音节），也让 `zhly` 的「综合利用」（z+h+l+y）压过「张靓颖」（zh+l+y）。改为用 parse rank 区分精确匹配与前缀匹配、区分不同解读，在那条比较之前定胜负。

## 自动验证

- Windows x64 Release 全目标构建：通过；
- 完整 CTest：59/59 通过，0 失败；
- 新增 `tests/data/simplified_pinyin_candidates.tsv`，10 条用例覆盖三种写法与混合输入，写测试时全部为红；

## 人工验证要点

见 `v0.7.5安装、使用与测试.md`。核心是四条：三种写法同出「输入法」、`zly` 与 `zhly` 候选相同、`wang` 等正常全拼不受影响、双拼不受影响。

## 已知落差

简拼排序只有词频，没有语言模型。`zsjs` 的「指示精神」排第 4、`zly` 的「张靓颖」排第 5，词都在但不如搜狗靠前。用户学习会随使用把常用词顶上去。
