# PiInput v0.7.4 版本说明

本版修卸载和安装，不改输入行为。v0.7.3 的候选改动原样保留。

## 卸载：不管什么版本都能卸干净

卸载一直失败，报「PiInput active-version directory is missing」。

原因是卸载器读 `current.json` 里的版本号，再去 `bin\<版本号>` 找程序目录——**而当前布局所有程序都直接放在 `bin` 下，那个子目录从来就不存在**。于是每一次卸载都在这里中止。

同一条链上还有三处同样性质的问题：卸载器找 `bin\bin\piinput-profile.exe`、找 `bin\Shim\PiInputTSF.dll`，两条路径都是旧布局的；文件缺一个就报「installation is incomplete」直接退出。

更根本的是设计：整个卸载是一条「全或无」的链，任何一步失败就完全不动手。结果是用户越想卸载越卸不掉——而失败的原因往往正是「东西已经不在了」。

本版把它改成：

- **先反注册，再删文件**。这条顺序保留，不能让系统里留下指向已删文件的输入法；
- **每一步失败都记录并继续**，不再中止；
- **程序在所有历史布局里找**：`bin\`、`bin\<版本>\bin\`、`bin\Shim\`、`Runtime\bin\`、`Runtime\Shim\`、`Dev\`；
- **结束时如实报告**。全清干净就说清干净了，有残留就逐条列出来，而不是把整个卸载叫做失败。

## 卸载：清理范围补全

以前卸载后会留下这些：

- `current.json`——安装状态标记，不是用户数据。留着它，下一次卸载又会去解析一个不存在的版本目录，正是上面那个 bug 的触发条件；
- `Runtime\`、`Dev\`——更早版本的运行时目录，历经几次布局调整从没被清理过；
- COM 类注册 `HKCU\Software\Classes\CLSID\{13EB305F-...}`。DLL 已经被删时没人再去调用 `DllUnregisterServer`，这个键会永远留在注册表里；
- `HKCU\Software\PiInput`。

这些现在都在清理范围内。保留用户数据的卸载仍然只保留 `UserData\`：词库、设置和学习记录。

## 安装：完成后打开设置目录

设置是手工编辑 `settings.ini`，以前只在对话框里显示一行路径，用户得自己去 `%LOCALAPPDATA%` 里翻。

现在安装完成的对话框同时列出安装目录和用户设置目录，点「确定」后自动打开设置目录。`--silent` 安装不弹窗，也不开目录。

## 升级说明

新的卸载器可以直接卸载旧版本的安装，不需要先重装。用本包里的 `PiInput-Uninstall.exe` 即可。
