# 开发约束

1. 文件名使用英文，文档正文使用中文；代码注释在必要位置提供中英文说明。
2. 方案映射只能存在一个事实来源，派生编码通过脚本生成。
3. 测试用例必须包含稳定 ID，后续版本不得无故复用或改变旧 ID 含义。
4. 目标文本、输入序列、操作动作、候选结果和期望指标必须分字段保存。
5. 平台相关键值不得直接写入通用状态机；通用动作在平台适配层解析。
6. 不把 Viterbi、HMM、N-gram 或神经模型写成强制实现。
7. 不把某款商业输入法特有功能定义为基础标准。
8. 测试包发布时必须包含项目定位、架构、开发任务、约束、版本说明、后续计划和新会话续接说明。
9. 所有 JSON 必须能够被标准解析器加载，所有文本使用 UTF-8。
10. 任何生成脚本失败都应返回非零退出码，并显示具体文件和用例 ID。
11. 候选评估必须使用引擎原始顺序，不得在适配器中重排。
12. 样例数据必须明确标记，不能冒充真实准确率或性能结果。
13. 纠错用例必须保留正确原码、派生错码、变异类型、位置和来源种子。
14. 模糊音必须同时验证开启和关闭状态。
15. 密码框、隐私模式和敏感控件不得参与用户词频学习。
