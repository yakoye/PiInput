# 项目定位与架构

## 1. 目标

建立一套能够长期支持 PiInput 开发的中文输入法测试体系，覆盖规则正确性、词库、长句切分、候选质量、容错、状态机、字符编码、用户学习、平台兼容性和性能稳定性。

## 2. 测试层级

```text
输入方案规则
    ↓
字词与专业词库
    ↓
切分、候选和上下文消歧
    ↓
容错、模糊音与异常输入
    ↓
输入状态机
    ↓
Unicode 与字符提交
    ↓
用户学习、隐私和数据恢复
    ↓
操作系统、键盘和应用兼容性
    ↓
性能与长期稳定性
```

## 3. 数据与执行分离

- `schemes/`：描述输入方案规则；
- `corpus/`：描述输入内容、目标文本和派生种子；
- `tests/`：描述具体操作、期望和指标；
- `reports/`：描述引擎实际输出；
- `tools/`：生成派生数据、计算指标并校验一致性；
- `generated/`：面向人工执行或审阅的最终材料。

## 4. 黑盒与白盒测试

黑盒测试关注“输入序列到候选和上屏结果”，不要求引擎必须采用 HMM、Viterbi 或某一种语言模型。白盒测试可在具体实现确定后检查词图、路径分数、词频、缓存和状态转换。

## 5. v0.2.0 数据流

```text
语料与纠错种子
    ↓ 生成脚本
结构化测试用例
    ↓ PiInput 测试适配器
候选列表、上屏文本、延迟
    ↓ 评估脚本
Top-1 / Top-5 / 目标排名 / CER / 延迟报告
```
